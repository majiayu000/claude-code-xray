CLI COMPUTER USE · MACOS CONTROL PATH

两道系统权限都通过，CLI 才能看和动

项目先启用内置的 computer-use，macOS 再分别放行屏幕录制和辅助功能。Claude 每次会话还要申请具体应用。三处都通过以后，它才会接收缩小后的屏幕截图，并向获准应用发出点击、输入或滚动动作。按 Esc 或 Ctrl+C 能立即截断当前动作。

01 / ACTORS

四个角色，各守一段

这条链从项目开关开始，经过操作系统和应用批准，最后落到屏幕与输入设备。把角色分开以后，权限不足发生在哪里就很清楚。

A1

用户

启用服务器，授予 macOS 权限，允许或拒绝应用，并随时按 Esc 或 Ctrl+C 接回控制权。

A2

Claude Code 会话

加载默认关闭的内置 MCP，申请应用，取得全机锁，把屏幕结果交给当前对话。

A3

macOS

Screen Recording 决定能否看见，Accessibility 决定能否点击、输入和滚动。

A4

获准应用

实际接收动作。浏览器和交易平台只读，终端与 IDE 只允许点击，其余应用才可能得到完整控制。

02 / ONE GUI TURN

一次桌面动作怎样走

同一任务里，Claude 会先找 MCP、Bash 或 Claude in Chrome 这类更精确的入口。只有 GUI 没有合适接口时，屏幕控制才接手。

01

O项目启用

用户在交互会话运行 /mcp，把默认关闭的 computer-use 打开。该选择按项目保存。

02

O首次请求系统权限

第一次需要桌面能力时，CLI 给出 macOS 设置入口。两项都授予后，用户在提示中选择 Try again。屏幕录制授权有时要重启 Claude Code。

03

O批准具体应用

终端列出 Claude 想控制的应用、额外权限和会隐藏的其他应用数量。用户可仅在本次会话允许，也可以拒绝。

04

O取得全机锁

第一次电脑动作取得锁。第二个 Claude 会话此时不能控制电脑，要等持有者退出。

05

O观察并发动作

未批准的可见应用被隐藏，终端留在屏幕上但不进入截图。截图缩小后送给模型，获准应用接收点击、输入或滚动。

06

O结束一轮

一轮完成后，Claude 自动恢复被隐藏的应用。会话仍持有全机锁，直到退出。

07

I权限被收回

后续动作必须重新满足系统和应用权限。公开契约没有说明动作已经发出时撤权会不会让它完成，因此这里保留未知。

03 / SCREEN & INPUT FLOW

屏幕往回走，动作往前走

官方公开了四个相邻环节。把它们连成逐调用数据路径含有研究推断，底层消息格式和坐标算法没有公开。

REQUEST当前会话

保留用户任务，决定何时调用内置 MCP，并接住观察结果。

LOCKcomputer-use

检查系统与应用许可，取得全机锁，安排截图和输入动作。

OS GATEmacOS

屏幕录制开放可见内容，辅助功能开放点击、输入与滚动。

TARGET获准应用

显示状态并接收允许级别内的动作。应用类别限制动作上限。

返回方向 每张截图先缩小，再送给模型。官方示例把 3456×2234 缩到约 1372×887并保持宽高比。终端窗口不在截图里，用户仍能看见会话并随时停止。

04 / GATES & STOPS

权限逐层放行，停止分两步

这项能力直接操作真实桌面，没有 Bash 沙箱。官方用项目开关、系统权限、应用批准、应用分级和全机锁缩小暴露面。

ELIGIBILITY

入口条件

macOS、Pro 或 Max、claude.ai 认证和交互会话缺一不可。Team、Enterprise、第三方模型提供商与 -p 都不在 CLI 预览范围。

OS PERMISSIONS

系统双授权

只给 Screen Recording 时能否观察而不能动作，官方按权限用途支持这一理解。实际组合失败信息没有在本轮验证。

APP APPROVAL

每会话应用门

一次允许只活到本次会话结束。Finder 和系统设置会显示文件或系统设置风险。2.1.243 起，桌面、Dock 和 Finder 动作都要批准 Finder。

CONTROL TIER

动作上限

浏览器与交易平台只读，终端和 IDE 只允许点击。应用通过批准也不能越过所属类别的控制上限。

DENY

拒绝当前申请

Deny 会挡住本次应用控制。CLI 目前没有 Desktop 那种可配置的拒绝应用列表。

SESSION EXIT

释放机器

任务完成不会释放锁。持有会话退出后，其他会话才能取得电脑控制；异常退出时官方会检测死亡进程并释放。

ESC

按键先停动作，会话退出再释放锁

macOS 通知会提示全局 Esc。用户也能在终端按 Ctrl+C。两种方式都会立刻终止当前动作、恢复被隐藏的应用并交还控制权。当前会话仍保留全机锁。

05 / SAFE OBSERVATION

本轮没有假装控制过桌面

真实实验会启动符合套餐条件的交互会话，还要改项目启用项并触发系统授权。任务禁止新开付费会话，也要求不影响正在使用的桌面，因此本页停在官方契约与只读观察。

  • L当前隔离 PATH 找不到 claude，`--version` 与 `--help` 无法从这个入口复核。
  • O官方 Computer use、MCP、Desktop 与 changelog 互相核对了权限、锁、中断和版本差异。
  • R没有截图、点击、输入、打开应用、读取私人配置或检查现有会话锁。

06 / IMPLEMENTATION & VERSIONS

公开到项目开关和全机锁为止

官方说明默认关闭的内置服务器通过项目项 enabledMcpServers 启用，也说明截图缩小、应用隐藏和全机锁。动作协议、采样节奏与锁文件路径没有公开。

2.1.85

changelog 修复多显示器下 switch_display 返回不可用，说明早期版本的多屏路径有明确差异。

2.1.243

桌面、Dock 与 Finder 窗口开始像其他应用一样要求用户在访问框中批准 Finder。

2.1.247

本页固定基线。包含此前两项变化，页面状态仍因缺少真实运行证据保持 documented。

为什么服务器已启用仍不能动

项目开关只让内置 MCP 连接。macOS 双授权和本次会话的应用批准仍要分别通过，应用类别还会限制动作级别。

为什么第二个会话报占用

锁在第一次电脑动作时取得，在会话退出时释放。任务结束和按 Esc 都不会提前释放。

为什么屏幕小字看不清

截图会自动缩小，且没有目标尺寸设置。官方建议放大应用里的文字或控件，不必降低显示器分辨率。

浏览器页面为什么不在本页展开

官方优先让网页任务走 Claude in Chrome。扩展连接、站点许可和标签页动作由 UI-06 Claude in Chrome 解释，本页只保留工具选择边界。

07 / OPEN QUESTIONS

公开材料没有走到这里

  • 屏幕采样在什么事件后发生，连续动作之间何时重拍，官方没有说明。
  • 动作消息格式、坐标转换、辅助功能元素选择和多显示器坐标系没有公开。
  • 动作发出以后，用户马上撤销系统权限或应用许可，当前动作是否完成，公开契约没有原子性保证。
  • Esc 或 Ctrl+C 到原生输入停止之间的最坏延迟没有公开。
  • 异常退出的锁检测周期、锁文件路径和每会话应用批准的内存结构没有公开。
