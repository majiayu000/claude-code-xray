01

先认清三样东西

自动记忆、索引和主题文件各做一件事。把它们混成一个大文件，会误读启动加载范围。

自动记忆

Claude 自己写的跨会话笔记。官方限定为用户、反馈、项目和引用四类，按仓库划分。

MEMORY.md

目录索引。每次新会话自动装入的只有它的前 200 行或 25KB，哪条先到就停。

主题文件

每条记忆的详细内容。启动时不自动装入，Claude 在需要时用普通文件工具读取。

modified

Claude 再写带 frontmatter 的文件时记录的 ISO 时间。它帮助判断新旧，不负责自动判定真假。

L本机静态与帮助证据
R隔离真实运行。本页没有

02

一次记忆怎样走到下次会话

这条时序从用户的一次纠正开始，到后续会话拿到索引前缀结束。

  1. 信息进入对话 O

    用户给出偏好、纠正、项目决定或外部资料位置。也可以直接要求 Claude 记住某件事。

  2. Claude 判断有没有复用价值 O

    它会跳过代码或 Git 能推出的内容，也跳过 CLAUDE.md 已经写明的内容。没有足够价值时，这一轮到此为止。

  3. 会话中写主题与索引 O

    Claude 把内容写进本仓库对应的记忆目录，用 MEMORY.md 记录它放在哪里。界面可能显示保存了几条记忆。

  4. 客户端在写后量索引 O

    接近上限就提醒 Claude 缩短。越界写入仍落盘，随后返回错误，要求改写索引。

  5. 新会话装入索引前缀 O

    启动只带入 MEMORY.md 的前 200 行或 25KB。越过上限的内容留在文件里，却不会出现在这次启动上下文。

  6. 需要细节时再读主题文件 O

    Claude 根据索引定位主题文件。记忆只作为上下文影响判断，不构成强制执行规则。

默认作用域 O

  • 每个 Git 仓库一份目录
  • 同仓库 worktree 与子目录共享
  • 离开 Git 仓库后按项目根归组

启动读入量 O

200 行与 25KB 同时计数，先碰到哪一个就在哪里截断。这个上限只管 MEMORY.md。

04

开关、失效与停止位置

用户能控制读写和文件，自动记忆本身没有替用户兜底的强制力。

位置发生什么用户怎样处理证据
没有复用价值Claude 不保存，每个会话都可能没有新记忆。需要明确持久化时，可以直接要求“记住”。O
自动记忆关闭不再创建或加载自动记忆文件。用 /memory 切换并保存到用户设置，项目设置也可单独写 false，环境变量还能关掉它。O
索引接近上限客户端提醒压缩条目、移动细节、合并或删掉陈旧项。打开目录，检查一行一条的索引是否仍准确。O
索引已经越界写入成功，客户端返回错误。下次启动会漏掉越界部分。缩短索引，再把细节移进主题文件。O
内容已经失效modified 只显示最后改写时间，没有自动过期承诺。用 /memory 打开 Markdown，直接改或删。O
需要硬性阻断记忆只是上下文，模型不保证严格遵循。用 PreToolUse hook 无条件阻断相应动作。O
关闭后仍有旧文件开关停止读写，保留期清扫又排除记忆文件。旧内容会留在磁盘。确认不再需要后手动删掉相关 Markdown。重新开启前先审阅。I

访问方式 O

使用本地 CLI 仍要先完成认证。个人可以用 claude.ai 的 Pro 或 Max 账号，团队可以用 Team 或 Enterprise 账号。组织也可以接入 Anthropic Console、Amazon Bedrock、Google Cloud 的 Agent Platform 或 Microsoft Foundry。官方把本地运行的 CLI 能力列为所有提供商可用，没有为自动记忆另列套餐门槛。

费用归属 O

费用跟当前认证走。Pro 与 Max 的使用包含在订阅中，Team 与 Enterprise 会消耗成员的席位额度。Console 和云提供商按 token 向对应组织或云账户计费。新会话会再次调用模型，可能继续消耗额度或产生 token 费用。

权限边界　自定义记忆目录必须是绝对路径或以 ~/ 开头。项目或本地设置提出的重定向受工作区信任规则约束。官方没有公开每次自动写入是否弹出普通文件权限提示。
05

本轮停在只读证据

没有 R，就不把官方文档画成已经亲手跑通的路径。

状态 documented

没有启动新 Claude 会话，没有打开私人记忆目录，也没有修改任何设置。

真实写入、跨会话加载和失效修订仍待隔离实验。

本机看到了什么 L

claude --version 返回 2.1.248。当前二进制已经偏离指定的 2.1.247 基线，因此本机帮助只能证明当前安装带有相关入口。

静态帮助写明 --bare 跳过自动记忆；二进制含公开契约名 autoMemoryEnabled、autoMemoryDirectory、禁用变量与 MEMORY.md。这些字符串不能证明一条真实记忆曾经写入或加载。

未做 R 的原因很直接。新会话可能产生付费调用，也可能碰到已有私人状态，超出这轮安全边界。

07

官方没有说透的地方

这些缺口会改变诊断方式，页面把它们留在明处。

Claude 怎样判断“将来有用”

四种类型和跳过原则已经公开，内部评分、阈值与去重算法没有公开。

并发写入怎样合并

同仓库的 worktree 共享目录。两个会话同时改索引时采用什么锁、谁先落盘、冲突怎样恢复，官方没有给出契约。

失效是否会被自动识别

modified 只留下日期线索。自动 TTL、可信度分数、事实复核和回滚机制都没有公开说明。

普通文件权限提示会不会出现

文档说 Claude 在会话中读写记忆文件，也说主题页通过普通文件工具读取。自动写入与通用权限层之间的精确调用关系仍缺少 R。

关闭后再开启会不会复查旧条目

开关的读写效果与文件保留都能从文档确认。重新开启时是否先做额外陈旧检查，官方没有说明。
