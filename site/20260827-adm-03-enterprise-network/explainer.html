企业代理、证书与网络请求链

请求先过门，再等回答

Claude Code 在启动时装入代理、CA 和客户端证书设置。一次请求随后选择代理，完成服务器证书校验与可选的 mTLS 身份证明。握手前失败时还没有模型回答；响应流已经开始后再断开，Claude Code 会按进度重试、保留已有输出或停止。

四个名词够用了

我把官方网络页、错误参考与本机 2.1.247 的静态入口对了一遍。这里的 corporate proxy 负责转交 HTTP 流量，LLM Gateway 会改 API 目的地并可能承担认证与路由。两者能一起用，角色不同。

O官方契约
说明公开支持什么
L本机证据
说明目标二进制带有什么
R真实实验
说明这次确实跑过什么
I研究推断
说明证据之间怎样接起来

代理

请求先连到企业代理，再由它转发。HTTPS 常用 CONNECT 隧道。

CA

签发或信任证书的机构。Claude Code 默认合并内置 Mozilla CA 与系统信任库。

TLS 检查

企业代理终止一段 TLS，再向上游建立另一段。客户端需要信任企业根 CA。

mTLS

服务端出示证书以后，客户端也出示证书并证明持有对应私钥。后半句是 TLS 语义解释。O + I

一次请求的时间顺序

环境变量在进程启动时进入 Claude Code。之后每个出站请求都沿着已解析的路径走。文件轮换有单独的重读时机，后改 shell 环境不会自动进入正在运行的会话。O

01 / 启动

读网络设置

代理 URL 会在这里检查格式。少了协议头，程序直接停在启动错误。

02 / 选路

决定直连或代理

按小写 HTTPS、大写 HTTPS、小写 HTTP、大写 HTTP 的顺序取第一个值，再看 NO_PROXY。

03 / 信任

校验服务端证书

默认信任内置 Mozilla CA 与系统库。企业根 CA 也可从额外 PEM 文件加入。

04 / 身份

按需做 mTLS

Claude Code 读取客户端证书与私钥。服务端要求时，客户端在握手中证明身份。

05 / 结果

收响应或错误

连接成功后才进入 HTTP 与响应流。连接重置、证书拒绝或替代页面会落到不同错误。

数据和文件流到哪里

代理地址和证书路径先进入进程。CA 文件决定信任谁，客户端证书与私钥完成 mTLS。官方契约只公开文件读取与重读时机，没有公开私钥在内存里的完整生命周期。

本机进程边界

环境变量代理地址、绕过清单、CA 来源、客户端材料路径
CA 文件追加企业根证书，用来校验代理或服务端给出的证书链
客户端证书向要求 mTLS 的服务端声明客户端身份
客户端私钥本机证明持有对应密钥。私钥内容不应作为请求正文发送，这一解释标作 I

代理能看到多少取决于 TLS 终止位置。 普通 HTTPS CONNECT 代理只承载加密隧道。TLS 检查代理会解密再加密，因此客户端看到的是它签发的证书。O

设置来源也有权限门。 本地终端在启动前设置即可。由 Desktop 应用管理连接时，网络变量只从 managed settings 与用户 settings 进入。云会话会忽略设置文件中的客户端证书与 CA 变量。O

主机清单随能力变化。 模型 API、登录、OAuth、连接器、插件下载、文档查询和可选遥测不共用一个域名。防火墙只放行模型端点，登录或扩展仍可能失败。O

失败落在哪一关

2.1.247 会区分配置格式、连接、TLS 校验与 HTTP 返回。重试不是一个统一开关，证书校验失败立即停，瞬时网络故障才按各自预算重试。

启动即停

  • 代理 URL 解析失败
  • 错误会点名应修的变量
  • 请求尚未发出

连接级故障

  • DNS、拒绝连接、代理隧道失败
  • 连接重置或 TLS 握手超时
  • 符合条件时重试，mTLS 材料也会重读

明确停止

  • 证书校验失败从 2.1.199 起不重试
  • 代理替换成 HTML 或空正文会报畸形响应
  • HTTP 拒绝不会触发连接错误式 mTLS 重读

这轮核到了哪一步

我没有启动 Claude 会话，也没有借用现有登录态。企业代理、测试 CA 和 mTLS 服务都不在安全实验条件里，因此不能把静态入口写成一次已经跑通的请求。

Dev Container 与进程包装为什么没有展开

Dev Container 改变进程运行环境，process wrapper 改变 Claude Code 怎样被企业启动器包住。它们会影响变量怎样到达进程，却各自拥有另一条部署或启动状态机。本页在这里停住，回总索引寻找相邻机制。

Corporate proxy 与 LLM Gateway 怎样分工

Corporate proxy 接管 HTTP 或 HTTPS 传输。LLM Gateway 改变 API 基址，还可能集中处理认证、路由与限额。两种配置可以同时存在，后者的完整状态机留给 ADM-05。

仍然不知道的部分

这些缺口会影响安全审计或跨代理复现，所以保留在页面上。它们没有被首屏改写成确定事实。

原生运行时合并 bundled 与 system CA 时怎样去重、怎样处理同名根证书，官方没有公开。

02

03

04

不同企业代理对长时间响应流、CONNECT 重置与证书轮换的实际表现仍缺 R。

一手来源与复现入口

复现时应在隔离容器里用测试代理、测试 CA 和测试 mTLS 服务。先制造证书拒绝，再加入 CA；随后轮换客户端证书，分别制造 TLS 握手失败与握手后的 HTTP 403。只有前者应触发连接错误式重读。
