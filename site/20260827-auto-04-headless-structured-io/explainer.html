Headless · structured I/O · process boundary

一条命令进来，一条可判定结果出去

非交互调用把 Claude Code 变成脚本里的一个进程。外部程序送入提示或事件，Claude Code 完成一次 agent 工作流，把文本、JSON 或逐行事件写到标准输出，最后交回退出状态。进程启动前，调用者还要选定加载边界、凭据来源和付费方式。

01 / TERMS

先分清输入、运行与输出

stdin

文本输入可以来自管道，也可以与命令行提示一起交给本次调用。官方给管道输入设了 10MB 上限。O

print mode

启用 print mode 后，终端不再等人持续对话。进程运行、打印并退出。普通调用会加载与交互会话相同的项目和用户上下文，也会建立可续接的会话。O L

output framing

文本适合人读，单个 JSON 适合一次性脚本，逐行事件适合实时消费者。Schema 约束的是最终业务结果。O

bare mode

脚本与 CI 推荐加 --bare，跳过自动发现的上下文和扩展。所需设置、MCP 与 agent 要由调用者显式传入。O R

02 / SEQUENCE

一次调用按进程时序走

T+00

外部程序启动

选择输入封装、输出封装、权限模式和会话参数。无效参数会在模型运行前失败。O R

T+01

读取输入

文本模式消费 stdin。流式输入允许进程持续接收消息，但官方 CLI 页面没有公开完整的原始行 schema。O

T+02

建立会话

新调用生成 session ID，resume 则装入既有上下文。非交互续接会重新采用新 print run 的权限起点。O

T+03

执行 agent loop

模型可以读文件或调用工具。工具能否运行，由 permission mode、allow 与 deny 共同决定。O

T+04

写出并退出

结果进入 stdout，启动前诊断进入 stderr。成功退出 0，失败为非零，SIGTERM 固定为 143。O R

03 / FLOW

输入格式与输出格式各管一边

INPUTtext 或 stream-json

输入封装决定 stdin 怎样被消费。

→
SESSION新建、继续或精确恢复

会话负责保留上下文，权限在非交互续接时另按规则选择。

→
OUTPUTtext、json 或 stream-json

输出封装决定 stdout 的机器可读程度。

Schema 位于输出末端。它让最终业务对象进入 structured_output，外层仍保留 session、用量和成本等运行元数据。O

文本输入适合一次送完的任务。调用者可以把提示写在命令行，也可以从管道送进 stdin，两者还能合在同一次调用里。管道内容超过 10MB 时，进程会报错并返回非零状态。stdin 已经断开而命令行仍有提示时，警告写到 stderr，提示本身继续执行。O

流式输入解决的是另一件事。进程保持开启，调用者继续送入消息，输出端则逐行吐出事件。普通事件流给出完整消息；若还要看令牌级增量，需要同时启用 verbose 和 partial messages。输入流的原始逐行 schema 没有在 CLI 文档里完整公开，这一段只能写到官方已经承诺的格式边界。O

claude -p "提取函数名" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}'
业务终态 result逐行事件可以先报告 init、assistant、tool result 与 API retry。可选尾随事件让物理末行存在例外，消费者应一直读到 EOF。O + I
04 / LIMITS

先关启动面，再配工具权限

DISCOVERY工作目录与用户配置

项目设置、CLAUDE.md、hooks、插件和 MCP 都可能成为启动输入。

→
PLAIN -P自动发现并加载

普通非交互调用沿用交互会话的上下文加载面。

→
BEFORE TURNhook 可运行，MCP 可连接

随后 agent 的工具调用才进入 allow、deny 与 permission mode。

普通 -p 在陌生目录中不会显示 workspace trust 对话框，也不会逐个询问 MCP 服务器。脚本不能把没有交互提示当作没有加载项目内容。O

普通启动面

不加 --bare 时，项目与用户范围的 hooks、skills、自定义命令、subagents、插件、MCP、auto memory 和 CLAUDE.md 都会自动发现。项目 hook 可以运行，项目 MCP 可以连接。O

Bare 启动面

--bare 跳过这些自动发现项，适合需要跨机器复现的脚本和 CI。它仍提供 Bash、文件读取和编辑工具，所需上下文通过 flags 显式加入，工具权限仍要另配。O

凭据门

普通 -p 可以沿用 Pro、Max、Team 或 Enterprise 的订阅登录，也可以使用 Console API 凭据和 Bedrock、Google Cloud Agent Platform、Foundry 等提供商凭据。--bare 不读订阅 OAuth 或系统钥匙串，Anthropic API 需环境变量中的 key 或经 --settings 传入的 apiKeyHelper，云提供商仍读各自凭据。O

费用门

一次真实模型调用会消耗所用订阅的额度，或进入 Anthropic API、云提供商的账单。JSON 里的 total_cost_usd 和分模型成本都由客户端估算，可能与实际账单不同。O

权限门

Print mode 的官方起点是 Manual。脚本应显式列出允许的工具，或选择合适的权限模式。dontAsk 会拒绝没有预批准的动作，适合锁紧的 CI。O

输入门

管道文本最多 10MB。stdin 断开且无法读取时，警告进入 stderr，命令行提示仍可继续。O

主动停止

预算上限和 turn 上限可以让任务自行停下。达到 turn 上限按错误结束。后台 Bash 与后台 agent 还有各自的退出等待规则。O

进程信号

SIGTERM 返回 143，当前 turn 不记录 result，并终止仍在运行的 Bash 进程树。持久化会话以后可以续接未完成的 turn。O

这里有两个结果要分别保存。退出码回答进程有没有正常结束，stdout 里的 result 回答 agent 做出了什么结果。有输出不等于成功，运行中的失败也可能作为结果写到 stdout。参数解析失败则更早发生，诊断留在 stderr。脚本要先看退出码，再解析与所选输出格式相符的内容。O R

续接也不会替调用者保存权限决定。JSON 结果里的 session ID 能交给下一次 --resume，上下文由此接上；新的 print run 仍从它自己的权限设置开始。若调用时关闭会话持久化，这个 ID 不能再用来恢复。O

05 / EXPERIMENT

本轮只碰启动前校验

本机保留了 2.1.247 归档二进制。版本输出和指定 SHA-256 完全吻合。它的帮助文本列出两种输入、三种输出、Schema、权限、resume 与禁用持久化等选项。L

实验显式使用 bare mode，让项目与用户范围的 hooks、插件、MCP 和 CLAUDE.md 留在启动边界之外；同时移除进程环境里的 Anthropic 认证变量，阻止模型请求。无效输出格式、无效 JSON Schema、非数字 turn 上限都在发起模型请求前退出 1。第三项也说明 2.1.247 的解析器认识帮助里没有显示的 turn 上限。R

claude-2.1.247 --bare -p --output-format invalid-format "x"
# exit 1

claude-2.1.247 --bare -p --json-schema 'not-json' "x"
# exit 1

claude-2.1.247 --bare -p --max-turns not-a-number "x"
# exit 1

这组 R 没有生成真实响应，也没有验证权限拒绝、续接、SIGTERM 或事件顺序。核心协议仍靠官方契约，所以页面状态保持 documented。

06 / IMPLEMENTATION

会话、流和退出码要分开判断

调用者要判断的事首选信号容易踩的边界
进程有没有正常完成退出码参数错误写到 stderr，运行中失败可作为结果写到 stdout。
agent 工作流得到了什么JSON result 或流中 result不要把 stdout 有内容等同于成功。
结构化业务对象是否可用structured_outputformat 关键字只作注解，客户端不校验它。
本次用了哪种访问与计费路径实际凭据来源与提供商账单Bare 不读订阅 OAuth；JSON 成本字段只是客户端估算。
启动前加载了什么--bare 与显式配置普通 -p 没有 trust 提示，也可能运行项目 hook、连接项目 MCP。
下一次怎样接着问session_id普通 picker 和交互式 continue 会跳过 print 会话，精确 resume 最稳妥。
流是否彻底结束EOF主文档称 result 是最后一行，SDK 文档允许少量尾随事件。

--bare 在 2.1.81 已进入官方 changelog，早于本页的 2.1.247 基线。本轮 R 只证明 2.1.247 接受这个参数，没有采样自动加载和认证运行路径；这些细节采用当前官方契约，身份保持 O。研究时默认启动器已经升到 2.1.248，本页只把它记作版本漂移。能力字段比单纯比较版本号更适合长期消费者。O L R

07 / UNKNOWNS

还有六块不能写死

01

官方 CLI 页面没有发布 stream-json stdin 每行的完整 schema、控制消息全集和输入错误恢复规则。

02

2.1.247 的真实 JSON 外层字段与失败 subtype 本轮没有采样。

03

result 后是否出现可选事件，官方两处文字需要消费者用 EOF 保守处理。

04

Manual 遇到每种需审批工具时，2.1.247 的无 TTY 输出形态没有实测。

05

SIGINT 与 SIGTERM 的完整退出码对照，官方没有在同一张进程状态表里列出。

06

2.1.247 的 bare 参数已经过解析实验，自动发现与凭据分支没有做真实启动采样，细节仍依赖官方契约。

怎样补完真实协议实验

获准后，用禁用全部工具的固定短答分别采样三种输出，再用不含私人内容的临时会话验证 resume。最后在受控进程里发送 SIGTERM，只保留匿名化字段名、事件类型和退出码。
