桌面值班表 · 持久计划

电脑醒着，计划才会出发

Desktop 把任务保存成独立计划。到点以后，应用检查计划并新建一次会话，结果留在侧栏和运行历史里。电脑睡着时它不会把电脑唤醒，恢复后七天内只补最近错过的一次。

使用门槛

先登录 Anthropic 账户，并确认 Pro、Max、Team 或 Enterprise 付费订阅仍然有效。Cloud routine 也只向这四类套餐开放。

本地计划能碰当前文件和未提交改动。需要关机后继续跑，就选 Cloud routine，让远端环境克隆仓库再开会话。

01 / ANSWER

保存的是值班计划，每次运行仍是新会话

O创建时

用户在 Routines 里新建本地任务，填写名称、说明、指令和时间，再选工作文件夹、模型、权限模式和是否隔离 worktree。文件夹未经信任时，保存前会先出现信任提示。

到期时

Desktop 每分钟看一次计划。应用开着、电脑醒着，才会新建一次 Scheduled 会话。

O运行后

系统通知提醒用户，侧栏出现新会话。用户可以读结果、看改动，也可以处理停住的权限请求。

O持久性到哪里

计划跨应用重启保留。电脑睡眠期间的旧班次不会逐次重放，醒来时只补七天内最近的一次，更早的全部丢弃。

02 / TERMS

三个名词够用

计划

一组保存下来的指令、时间和运行选择。提示正文可在任务目录里的 SKILL.md 修改，时间、文件夹、模型和启用状态另由 Desktop 管理。

运行

计划每次触发都会开一个新会话。历史里的一个条目对应一次启动、一次跳过或一次停住。

运行位置

Local 读取电脑上的文件。Cloud routine 克隆所选 GitHub 仓库，在指定环境里跑，不依赖这台电脑保持开机。

03 / SEQUENCE

一次本地任务怎样走完

保存写下提示和计划，指定文件夹与权限。
等待状态为 Active，Desktop 按分钟检查。
到期固定的小延迟分散同时启动的请求。
开会话创建独立 Scheduled 会话。
执行读写文件，必要时等待批准。
回报通知、侧栏会话和历史留下结果。

O到点时若上一次还在跑，调度器也可能因其他计划正在运行而跳过这次。官方页面公开了这些原因，没有给出并发名额的具体数字。

04 / FLOW

文件夹留在本机，仓库交给云端

ROUTINES
NEW
LOCAL / CLOUD

同一个入口分出两条因果链。选择取决于任务要接触哪份状态，以及电脑能否一直醒着。

Local

  • 绑定一个受信任的本地文件夹
  • 默认看见该目录当时的状态，含未提交改动
  • 可让每次运行进入独立 Git worktree
  • 沿用配置文件和本任务的权限选择

Cloud routine

  • 保存一个或多个 GitHub 仓库
  • 每次从默认分支新克隆
  • 环境提供网络、变量和安装脚本
  • 连接器随任务配置，运行中不弹权限确认

I可以把选择规则压成一句话。任务必须读取本地未提交状态，就留在 Local。任务必须在合盖后继续，就交给 Cloud routine，并接受新克隆、云环境和账户限额这一组条件。

05 / LIMITS

它会跳过，也会停住

位置条件可见结果怎样继续
进入前尚未登录，或没有有效的 Pro、Max、Team、Enterprise 付费订阅无法使用 Desktop Code；Cloud routine 也不开放登录 Anthropic 账户并确认订阅有效
保存前没选文件夹，或文件夹尚未信任不能直接保存，先要求选择或信任确认目标文件夹
到期时应用关闭或电脑睡眠这次不启动七天内醒来时只补最近一次
调度时上一次仍在运行，或调度器因其他计划正在运行而跳过历史记为 skipped，并显示原因等下一班，或手动 Run now
执行时Manual 模式遇到未获准工具会话留在侧栏并等待用户批准，或调整本任务的允许项
暂停后任务状态为 Paused计划不再按期启动改回 Active
删除时用户确认删除任务删除，既有会话归档可另外勾选删除磁盘上的任务文件
06 / EVIDENCE

本页有 O 和 L，没有 R

O 官方契约产品公开承诺与边界
L 本机证据版本、帮助与静态字符串
R 真实实验本页未创建任务
I 研究推断从相邻证据收窄出的判断

O登录和套餐是使用入口。Desktop Code 要求登录 Anthropic 账户，并持有有效的 Pro、Max、Team 或 Enterprise 付费订阅。Cloud routine 当前也只向这四类套餐开放。

我把 Desktop 本地计划、会话内调度和 Cloud routine 三份官方页逐段对过，再核本机保留的基线程序。本机 Claude Code 2.1.247 二进制返回同一版本号，SHA-256 与研究基线一致。公开帮助列出云会话、worktree 和权限模式，静态字符串能找到 CronCreate、CronList、CronDelete 与 scheduled-tasks。这些 L 证据只说明基线程序带有相邻调度词面，不能证明 Desktop 的保存、唤醒或补跑路径真的执行过。

创建本地计划会写用户配置并可能触发付费会话，创建 Cloud routine 还会写远端账户。研究边界不允许这两种动作，因此状态保持 documented。

07 / IMPLEMENTATION

提示文件只装提示

O磁盘提示

任务名会转成小写 kebab-case，并成为任务目录名。目录中的 SKILL.md 用 YAML frontmatter 保存名称与说明，正文保存提示。改完以后从下一次运行生效。

O调度元数据

时间、文件夹、模型和启用状态明确不在这份 SKILL.md 里。官方要求从 Edit 表单或会话里让 Claude 修改，公开文档没有给出另一份文件的名称和格式。

O本地文件流

不启用 worktree 时，运行直接面对工作目录当时的内容。启用以后，每次运行有自己的 Git worktree，隔离方式与并行会话一致。

O结果记录

通知负责叫人来看，Scheduled 会话承载过程和改动，历史再记录运行或跳过。对 Cloud routine 来说，绿色状态只证明会话没有基础设施错误，任务是否做成还得打开会话确认。

O版本线也要分开。官方要求 Claude Desktop 至少达到 1.1.5368 才有本地 scheduled tasks。Claude Code 2.1.247 是这套 XRY 的 CLI 基线，它不能替代 Desktop 应用版本。

08 / UNKNOWNS

公开契约留下的空白

完整计划究竟存在哪份文件里

官方只公开提示文件，并明确排除了时间、文件夹、模型和启用状态。本轮遵守隐私限制，没有读取用户的 scheduled-tasks 目录。

本地计划最多能同时跑几个

历史会显示因其他计划正在运行而跳过，文档没有公布并发上限，也没有说明多个同分钟任务的排序规则。

本地历史保留多久

详情页可以 Show more 加载旧条目。官方没有写明本地历史的保留期、清理条件或最大条数。

夏令时和跨时区移动怎样处理

界面用本地时间排班，公开页没有说明本地计划在夏令时切换或电脑时区改变后的精确行为。

一次本地运行怎样计入用量

Cloud routine 的账户限额有单独说明，本地 scheduled task 页面没有给出同等精度的用量与并发口径。

09 / SOURCES

一手来源与复现

  • Desktop 入门官方页，证明登录要求和 Pro、Max、Team、Enterprise 付费订阅门槛。
  • Desktop scheduled tasks 官方页，证明保存字段、按分钟检查、补跑、权限、历史和提示文件。
  • 会话内调度官方页，证明 /loop 的会话边界、恢复条件和七天到期。
  • Cloud routines 官方页，证明支持套餐、仓库克隆、云环境、连接器、无交互权限和结果会话。
  • Desktop 官方参考，证明 Desktop 与 CLI 的版本和界面边界。

安全复现先核对 2.1.247 --version 与二进制哈希，再读取同版本 --help。随后在可付费的隔离测试账号里新建一分钟一次的本地任务，记录保存前后的状态，并观察准点运行和睡眠错过。另做一次权限停住，再确认暂停有效。不要读取私人会话或把真实工作目录写进日志。
