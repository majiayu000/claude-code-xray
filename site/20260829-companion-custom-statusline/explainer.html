Claude Code 2.1.247 · 固定基线 2026-08-27

一份快照，换回一段底栏文字

刷新到来时，Claude Code 启动配置好的本机命令，把会话快照作为 JSON 写进标准输入，再捕获脚本的标准输出。脚本成功打印，底栏就更新。非零退出或没有输出会留下空白；脚本被下一次刷新取消时，新的调用接手。

本页状态为 documented。官方契约和本机 help 已核对，本轮没有启动真实 Claude 会话。

01 / TERMS

四个角色就够了

本页只追踪命令边界。底栏怎样在 fullscreen 或 classic 里绘制，交给 UI-02。

Claude Code

组装当前快照，触发刷新，管理子进程，再把输出交给界面。O

statusLine command

用户配置的 shell command。它从 stdin 读 JSON，做格式化，也可以自行运行 git。O

stdin snapshot

一次调用只收到当时可见的数据。字段可能缺席，首个 API 响应前也可能为 null。O

footer row

stdout 的去处。多行、ANSI 颜色与 OSC 8 链接都属于公开输出面。它在部分交互期间会暂时隐藏。O

02 / SEQUENCE

一次刷新走完六步

防抖发生在启动命令之前。取消发生在旧命令还没结束而新刷新已经到来时。

用户先配置命令

可以让 /statusline 按自然语言生成脚本，也可以手动写设置。前一种做法发生在已认证的 Claude Code 会话里，不能套用子进程刷新零 token 的结论。项目命令还要先通过 workspace trust。O

某个刷新条件出现

会话启动或恢复会触发，助手消息和压缩完成也会触发。权限、Vim 模式或 command 变化继续触发；已收到的 rate-limit reset 时间到点也会触发。refreshInterval 还能在空闲期加一条定时刷新。O

普通变更等待 300 毫秒

短时间内连续出现的变化会合并。command 本身变更时会跳过这段等待，立刻运行新命令。O

Claude Code 启动子进程

JSON 快照进入 stdin，终端宽高通过 COLUMNS 与 LINES 环境变量传递。stdout 被捕获，脚本并没有直接连到终端。O

脚本读取并打印

它可以只格式化已有字段，也可以运行 git 查询。官方建议缓存较慢的 git 操作，免得每次刷新都重新扫描。O

完成、失败或取消

stdout 成为新的状态行。非零退出或无输出会留下空白。新的刷新到来时，仍在运行的旧命令会被取消。O

数据只走一趟

图中状态名是研究者把官方时序压成的一条线。输入字段和停止行为来自官方契约。

JSON STDIN

→
CAPTURED STDOUT

stdout 完成后替换底栏。非零退出或无输出会让底栏变空。

I 可以把一次调用理解为 wait → pending → running → displayed。blocked、blank 与 cancelled 是旁路终点。官方没有公开内部枚举，这些名字只帮助阅读。

数据组Claude Code 给什么脚本要留意什么
会话与位置session_id、session_name、prompt_id、cwd、transcript_path这些值能定位真实会话。不要把整份输入写进日志。I
模型与上下文model、context_window、effort、thinking上下文取自最近一次 API 响应。首个响应前应准备 null 兜底。O
成本与时间total_cost_usd、总时长、API 等待时长和改动行数美元值是客户端估算，可能不同于实际账单。O
套餐与速率窗口rate_limits.five_hour、rate_limits.seven_day只向 Claude.ai Pro 或 Max 用户提供，并且要等首次 API 响应。每个窗口都可能缺席。O
git 与协作仓库身份、worktree、已发现的 PR 或 MR普通分支和 dirty 计数常由脚本自行运行 git 取得。O
04 / LIMITS

本地刷新只占其中一层

statusline 子进程在本机刷新，不消耗 API token。这项承诺不覆盖自然语言配置和外围 Claude 会话。

O

认证和配置

Claude Code 的交互会话需要按部署方式认证。/statusline 会理解自然语言、生成脚本并改设置。手动写脚本和设置可以省掉这次生成动作。

O

订阅和 API 费用

本地子进程每次刷新都不花 API token。外围会话仍按接入方式计算用量。Pro 与 Max 计入订阅额度，Console 和云服务按各自的 API 账单处理。

O

套餐限定字段

2.1.247 的五小时与七天窗口只面向 Claude.ai Pro 或 Max，并且首次 API 响应后才可能出现。gateway 的 spend_limit 要到 2.1.251 才支持。

O

Workspace trust

目录尚未被信任时，命令会跳过，状态行保持空白。debug 会记录跳过原因。

O

Managed gate

disableAllHooks 与 allowManagedHooksOnly 会按设置来源决定自定义 statusLine 能否运行。

O

失败和空输出

非零退出或没有 stdout 都产生空白。stderr 不会自动变成底栏文字，可用 debug 看首个调用的退出码和 stderr。

O

慢脚本和取消

脚本没结束，状态行就不会更新。新刷新到来时旧进程被取消，新的快照随后接手。

O

临时隐藏

自动补全、帮助菜单和权限提示出现时，状态行会暂时隐藏。窄终端里的通知也可能截短它。

I

脚本自己的权限

官方只说明命令在本机 shell 中运行，没有承诺为脚本的读写和网络再弹 Claude 工具权限提示。脚本应按本机程序对待。

refreshInterval 不是超时。 它只增加刷新时机。官方没有公开 statusLine 的固定截止时间，也没有配置 timeout 字段。没有新刷新时，一个卡住的命令何时被强制结束仍然未知。
05 / EXPERIMENT

本轮停在静态核对

子进程刷新可以零 token，启动外围交互会话仍会接触认证和会话状态，也可能占用订阅额度或产生 API 费用。本轮没有得到这类授权。

固定二进制的 version 返回 2.1.247，help 能正常读取。当前 PATH 没有 claude 入口，安装文件的静态读取又被操作系统拒绝，所以本页没有重做二进制摘要，也没有用 strings 推断内部实现。

这些结果只证明固定版本入口存在。它们证明不了 stdin 的真实字段集合、300 毫秒防抖或进程取消已经在这台机器上发生。

R mock JSON 能测试一段脚本，却不能测试 Claude Code 的调度与渲染。本页没有把 mock 冒充真实产品实验。

06 / IMPLEMENTATION

给脚本留好退路

字段缺席、git 变慢和异常退出都很常见。最小脚本先读完 stdin，再用短输出收住。

#!/bin/sh
input=$(cat)

model=$(printf '%s' "$input" | jq -r '.model.display_name // "?"')
used=$(printf '%s' "$input" | jq -r '.context_window.used_percentage // 0')

# Keep optional git work bounded and cache its result.
# Do not dump the full JSON. It contains session and path identifiers.
printf '%s · context %s%%\n' "$model" "$used"

I 若脚本还要调用网络或较慢的 git 命令，给那一步设置自己的短截止时间，并缓存结果。Claude Code 的公开配置没有 statusline timeout 可以替脚本兜底。

07 / UNKNOWNS

还有五处不能写死

公开 schema 讲清了接口，没有把每个平台的进程清理细节一并公开。

固定超时

没有新刷新时，2.1.247 会不会在某个未公开的时限强制结束卡住的脚本。

后代进程

macOS、Linux、Git Bash 与 PowerShell 上的取消是否会递归清理脚本创建的全部后代。

stdout 上限

捕获字节数、尾随换行与异常 ANSI 序列的精确处理规则没有公开。

环境继承

除了明确给出的 COLUMNS 与 LINES，子进程还会继承或过滤哪些环境变量。

实际速率窗口

满足套餐和首次 API 响应条件以后，当前账号究竟会收到哪些 rate-limit 窗口，仍需隔离真实会话核对。

渲染边界

输出怎样与通知、fullscreen 和辅助技术共同排版，由相邻 UI-02 页面继续解释。
