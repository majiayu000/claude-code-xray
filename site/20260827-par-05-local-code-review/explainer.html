18 / LOCAL REVIEW DOSSIER

先圈定改动，再判断问题。

用户启动本地 Code Review 后，Claude Code 按公开契约确定默认 diff 或显式 target，并在独立审阅上下文中寻找能够落到文件位置、说明影响且值得修复的问题。无可靠发现也是有效终点。O

01

先认四样东西

本页只使用公开 Code Review 契约，不公开安装物中的内部审阅模板。

默认范围当前分支领先 upstream 的提交，加上未提交改动。O
显式 target文件、PR、分支或 ref range 可以替代默认范围。O
finding值得报告的问题必须具体、可定位并说明影响；空结果仍然有效。O
effortlow 与 medium 偏向高置信问题，high 与 max 扩大覆盖。O
02

公开契约里的 review 流程

  1. 选择范围使用默认 diff，或由用户提供文件、PR、分支与 ref range。O
  2. 分出审阅上下文默认在后台 subagent 中运行，避免占用主对话上下文。O
  3. 检查变化Claude 读取所需代码与项目规则，寻找具体且可操作的问题。内部搜索顺序不是公开承诺。O
  4. 返回结果终端返回文字，支持的宿主可以接收结构化 findings；没有发现时可以返回空结果。O

05

公开证据边界

本页公开版只保留官方 Code Review、Commands 与 Permissions 契约。

没有启动真实模型 review，因此页面状态仍是 documented。私有研究环境中的安装物核对只用于发现需要向官方文档求证的问题，不在公开版披露内部模板或分支。

06

版本与产品边界

本地 review 与自动 PR Review 不同

本地 review 围绕当前会话的 diff 或 target 工作；自动 PR Review 有自己的资格、触发与计费。O

effort 改变覆盖强度

官方只承诺低档偏向高置信，高档扩大覆盖；不承诺固定候选数量或内部搜索顺序。O

写入需要显式动作

普通 review 只报告。--fix 会改工作区，--comment 会尝试写 PR 评论，仍受 Git 与权限规则约束。O

07

仍然不知道

空范围的最终文案

官方定义了空结果边界，没有固定所有宿主显示的同一句话。

权限阻断后的具体续跑

拒绝会回到模型；是否改用别的只读方法取决于当次上下文。

大型 diff 的固定阈值

公开文档没有给所有环境通用的文件数、行数或字节上限。

安全复现办法

在无私人内容的临时仓库固定 2.1.247，先保存 Git 算出的两份预期 diff，再分别运行默认 review、显式路径 review、空 diff review，并用临时 ask 或 deny 规则阻断一次 diff 读取。只记录匿名化文件位置、工具类型、批准状态和最终 findings。不要保存 prompt、思考或完整工具输出。这些步骤会启动 Claude 并触发模型调用，需另行授权。
