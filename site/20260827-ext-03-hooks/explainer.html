EXT-03 · documented

Claude Code 先发出事件，再等 hook 交回决定。

会话开始、用户送出提示、工具准备执行、工具结束和本轮收尾，都会落到各自的生命周期点。交互会话先检查 workspace trust，随后才会放行 settings hooks。事件命中配置后，handler 收到 JSON。同步 handler 跑完以后，Claude Code 合并结果，随后继续、询问、拒绝，或者把补充信息交给下一次模型请求。

O这条链来自 Anthropic Hooks 参考与权限文档。I页面把它压成一次裁决链，方便看清先后。当前机器已升级到 2.1.248，本页仍以指定的 Claude Code 2.1.247 为版本基线，因此状态保持 documented。

01 / TERMS

先分清三个东西

配置里有三层。事件决定何时检查，matcher 决定这一次算不算，handler 才是实际运行的命令、端点、MCP 工具或模型判断。

事件

PreToolUse 在工具执行前出现，PostToolUse 在成功后出现，Stop 在主 Agent 准备结束回复时出现。事件位置决定了 hook 还能改变什么。

匹配

工具事件通常按工具名匹配。没有 matcher、空字符串或星号会命中每次事件。工具 handler 还可用 if 按权限规则语法继续缩小范围。

处理器

官方参考列出 command、HTTP、MCP tool、prompt 和 agent 五类。同步处理器默认会挡住后续流程，直到完成、超时或报错。

O

Anthropic 官方文档、官方 changelog 或官方仓库。用来说明公开契约。

L

本机只读命令与静态帮助。用来说明当前安装实际带了什么。

R

隔离条件下实际触发一次 hook。此页没有这一层证据。

I

研究者为了解释调用链作出的归纳。它不会替代运行证据。

02 / SEQUENCE

一次工具调用经过七站

下面画的是 settings hook 已获准运行，并且 matcher 命中的路径。没有通过入口检查或没有匹配项时，Claude Code 都不会启动 handler。

T-01

会话入口先处理信任

交互会话会暂停所有 settings hooks，连用户级配置也一样，直到用户接受当前目录或其父目录的 workspace trust。-p 与 SDK 不显示这道对话框，并把目录视作已信任，因此陌生仓库里的项目 hook 也可能运行。O

T+00

模型提出工具调用

用户先提交提示，模型随后可能提出 Bash、Edit 或 MCP 工具调用。UserPromptSubmit 位于模型处理提示之前，能阻止提示进入上下文，也能附加上下文。O

T+01

PreToolUse 发出

Claude Code 把通用字段、工具名、工具输入和工具调用 ID 组成 JSON。command handler 从标准输入读取，HTTP handler 收到相同结构的 POST body。O

T+02

匹配项一起运行

同一事件的所有匹配 handler 并行运行。一个 handler 先给出 deny，也不会取消已经启动的同级 handler。相同 settings handler 会去重，插件或 skill 的副本仍分开。O

T+03

结果合并

PreToolUse 的结构化结果按 deny、defer、ask、allow 的严格程度合并。多个 handler 给出的 additionalContext 会一起交给 Claude，返回 defer 的 handler 除外，它的这项内容会被忽略。O

T+04

权限规则继续复核

allow 可以略过普通交互提示，却不能越过 deny 或 ask 规则。受管理的 deny 仍然优先，要求真实用户交互的某些 MCP 工具也仍会询问。O

T+05

执行或停止

通过后工具才运行。成功会触发 PostToolUse，运行后失败会触发 PostToolUseFailure。准备结束本轮时才到 Stop，API 错误则改走不能裁决的 StopFailure。O

03 / FLOW

输入是一包事件数据，输出是一次局部裁决

通用字段让 handler 知道哪段会话、哪个目录和哪种权限模式触发了它。事件字段再补上工具输入、提示文本、错误结果或结束原因。

进入 handler 的 JSON

官方契约给每个事件一套 schema。转录路径可能落后于内存里的当前轮次，Stop handler 若要读刚生成的最终文本，应使用 last_assistant_message，不要假定 transcript 已经写完。

session_id当前会话标识
cwd触发时的工作目录
permission_mode当前权限模式
hook_event_name事件名称
tool_name工具事件才有
tool_input工具事件的参数

O这些字段可能包含敏感内容。官方安全建议要求校验输入、给 shell 变量加引号、拦截路径穿越，并避开密钥文件。

三种常规去向和一项非交互延后

PreToolUse 的结构化输出放在 hookSpecificOutput 中，并带上正确的事件名。它还能用 updatedInput 替换完整工具输入，用 additionalContext 给 Claude 补充事实。

DENY取消调用
DEFER仅 -p 单调用
ASK交给用户
ALLOW继续复核
defer 有单独的 surface 边界。 它只在非交互 claude -p 中生效，并且这一轮只能有一个工具调用。交互会话会警告并忽略它，一轮并行调用也会警告并走正常权限流程。defer 同时会忽略 updatedInput、permissionDecisionReason 和该 handler 的 additionalContext。
权限门仍在。 hook 的 allow 只解决 hook 这一关。匹配的 deny 与 ask 规则还会生效。一个同步 hook 的 deny 也不能撤销同批其他 handler 已经产生的外部副作用。
04 / LIMITS

失败时，多数路径选择继续

hook 常被拿来做安全门，最容易出错的地方恰好也在这里。超时、普通非零退出和异步运行通常不会替你阻断动作。

超时会撤掉这次决定

同步 command、HTTP 或 MCP tool handler 到时会被取消，输出被丢弃。PreToolUse 随后进入正常权限流程。官方明确提醒，不要把卡住的 hook 当成安全门。O

退出码 1 通常只报错

大多数事件里，只有退出码 2 能靠退出码本身阻断。退出码 1 会显示非阻断错误并继续。WorktreeCreate 是任何非零都失败的例外。O

退出码 2 也要看事件

PreToolUse 会取消工具，UserPromptSubmit 会拒绝提示，Stop 会让 Claude 继续工作。PermissionRequest 不接受退出码 2 的否决，必须返回它专用的 JSON decision。O

异步 handler 没有裁决权

async 只适用于 command handler。它启动后 Claude Code 立刻继续，decision、permissionDecision 与 continue 都不生效，结果要到后续轮次才可能送回。O

后置 hook 改不了已经发生的事

PostToolUse 可以替换 Claude 接下来看到的工具输出，也能加上下文。文件写入、命令和网络请求已经完成，替换展示结果不会撤销这些副作用。O

Stop 有循环保险

Stop handler 连续阻止结束时会再次触发。输入里的 stop_hook_active 可帮助脚本避免死循环，Claude Code 在连续八次阻止后会强制结束本轮。O

command hook 拿到当前用户权限

它能访问、修改或删除当前系统用户有权处理的文件。Claude Code 的工具权限门不会给这个子进程再套一层限制，配置前需要逐条审查脚本。O

05 / OBSERVE

这次没有触发真实 hook

本轮遵守只读边界，没有改 settings，也没有启动新的付费 Claude 会话。L 证据只能说明当前程序和 help 已经变到哪里，不能证明 2.1.247 的运行链。

R = 0

缺少一次隔离运行，所以页面状态是 documented。

L1

claude --version 返回 2.1.248。它说明本机已越过页面基线。

L2

claude --help 仍列出 hooks 调试过滤、stream JSON 中包含 hook 事件、临时 settings，以及跳过 hooks 的 bare 与 safe mode。

L3

当前可执行文件的 SHA 与任务给定的 2.1.247 SHA 不同。它只能证明安装发生了变化。

O4

官方 2.1.247 changelog 修复了超大 hook 错误输出挤爆会话的问题。2.1.248 又改变了无效 hook JSON 与无效权限回答的报错表现。

06 / BUILD

配置决定作用域，也决定谁能带走它

用户、项目、本地、受管理策略、插件、skill 和 subagent 都能声明 hook。settings 各层会累加，外层的 disableAllHooks 不能关掉受管理 hook。

最小结构

下面只展示协议形状。它没有在本轮写进任何 settings，也没有执行。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "./check-command.sh",
            "timeout": 5
          }
        ]
      }
    ]
  }
}

默认等待时间

当前官方参考给 command、HTTP 和 MCP tool 六百秒，prompt 三十秒，agent 六十秒。UserPromptSubmit 会把前三类默认值降到三十秒。页面没有在 2.1.247 上逐项计时，这些数字仍属于 O 层契约。

command handler 带 args 时直接启动可执行文件，不经过 shell。省略 args 才会进入 shell form。官方建议路径占位符使用 exec form，减少引号和重新解释带来的风险。

Hooks 不绑定某一种提供商

官方可用性表把 hooks 列为所有模型提供商都能使用的本地能力。Claude Code 会话仍要有可用认证，来源可以是 Claude.ai 订阅、Anthropic Console、Bedrock、Google Cloud、Microsoft Foundry 或企业网关。O

模型型 handler 会增加模型用量

prompt hook 每次触发会向 Claude 模型发送一次判断请求。agent hook 会启动最多五十轮的子代理。它们产生的模型请求会计入当前认证渠道对应的订阅或 API、云提供商用量，频繁触发时应把这部分计入成本。O

07 / UNKNOWNS

目前还缺四块

这些缺口会影响版本复现或运行判断，不能靠当前文档补成 2.1.247 的现场事实。

2.1.247 的真实运行次序没有 R 证据

当前机器只有 2.1.248。本轮也不能启动付费会话，因此没有拿一个隔离项目触发 SessionStart、PreToolUse、PostToolUse 和 Stop。

2026 年 8 月 27 日的官方 Hooks 页面快照没有保留在本目录

在线 llms.txt 入口数仍为 202，SHA 已与指定基线不同。当前参考页可能包含第二天发布的修订，尤其是无效 JSON 的报错表现。

同批 handler 的完成先后没有稳定承诺

官方只承诺匹配项并行运行，等它们完成后合并结果。handler 各自何时结束不应当被脚本当成排序机制。

终端、IDE、Desktop 与 Web 的现场差异没有逐端实验

官方参考说这些表面都会发出相同 hook 事件。云端读取哪些本地配置另有范围限制，本页没有逐个产品表面做 R 层核对。

安全复现办法

  1. 准备一个无凭据、可丢弃的临时目录，确认安装版本恰好是 2.1.247。
  2. 只通过命令行 --settings 传入临时 JSON。handler 把事件名和时间写入临时目录，绝不记录提示正文、工具参数、转录路径与会话标识。
  3. 分别让 PreToolUse 返回 allow、ask、deny，并加入一个短超时 handler。另在单工具 claude -p 中测试 defer，再核对交互会话与并行工具调用会警告并忽略它。
  4. 用 --debug hooks 和 --include-hook-events 只核对匿名化事件顺序。实验完删除临时目录，不写用户、项目或受管理 settings。
