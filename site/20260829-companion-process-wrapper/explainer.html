组织 launcher 怎样启动 Claude 进程

管理员配置 launcher 后，Claude Code 会把后台服务、Agent View host 和会话交给它启动。launcher 满足 argv 与 exec 契约时，目标进程接管。路径无效或脚本提前退出时，相关进程会停在启动阶段，原因显示在 Agent View 或后台服务错误里。O

四个角色就够

我对照了 corporate launcher、Agent View、错误参考和本机 2.1.247 帮助。这里的 wrapper 管 Claude Code 自身的进程创建。Bash、hooks 与 stdio MCP 走另一项 shell prefix 契约。O + L

说明证据怎样接上

launcher

组织维护的可执行入口。它可以进入 sandbox、加网络控制或注入凭据。

self-spawn

Claude Code 从自己的二进制路径再启动后台服务、host、会话或 relaunch。

supervisor

每用户后台服务。它承载 Agent View 会话，并维护一个预热 worker。

exec

launcher 用目标进程替换自己，让 supervisor 能追踪正确的进程身份与退出状态。

Agent View 派发后台会话时，supervisor 把工作目录、设置与凭据交给预热 worker，随后再补一个 standby。每个后台会话仍有自己的 Claude Code 进程。会话第一次创建、崩溃后重启或更新后重新拉起，都各自经过 launcher。O

一次启动怎样走

这条链从配置被新进程读到开始，到目标进程接管或错误返回为止。已运行的服务不会靠保存设置立即换壳，需要重启。O

01

管理员下发

环境变量放进 user 或 managed settings，也可用顶层 processWrapper。

02

新进程读取

环境变量优先。项目与 local 配置不能给整机进程插 launcher。

03

解析参数

值成为 argv 前缀。它不经过 shell 展开，非法操作符直接报配置错。

04

调用入口

launcher 收到目标二进制与原始参数。继承环境要原样保留。

05

目标接管

脚本约三秒内走到 exec。嵌套 self-spawn 仍会再次经过它。

06

成功或失败

成功后 supervisor 继续追踪；失败时受影响进程不启动，调用面收到原因。

哪些进程过闸

判断标准很具体。进程若由 Claude Code 自身二进制直接派生，就进入 process wrapper。由用户 shell、操作系统、浏览器或 tmux 启动的第一层进程留在外面。O

WRAPPEDAgent View terminal host、session 与 warm standby
WRAPPEDcrash 或 update 后的 respawn 与 self-relaunch

OUTSIDE用户直接运行的第一层 claude 与深链第一进程
OUTSIDEChrome native host 与 worktree 配合 tmux 的 relaunch

网络从下一页继续

launcher 可以先放入企业网络变量或凭据。目标进程接管以后，请求怎样经过代理、CA 与 mTLS，交给 ADM-03 企业网络主页面。

用户在终端直接运行的第一层 claude 由 shell 启动，不在 corporate launcher 覆盖内。组织若也要包住这一层，需要把单独入口放在 PATH 前部。Claude Code 自己派生进程时使用二进制绝对路径，随后转入 process wrapper，两段入口不会自动叠成同一个包装。O

工具进程要分开看。shell prefix 承接 Bash、hooks 与 stdio MCP 命令，收到的是一段 shell 字符串。process wrapper 收到目标二进制与原始 argv。组织可以同时配置两项控制，但脚本必须分别满足各自契约，不能拿一份脚本直接替换。O

失败停在哪里

组织强制入口若不可用，Claude Code 选择拒绝受影响的启动。Windows 是明示例外，它忽略这项配置并无 wrapper 运行。O

解析前就停

  • 路径未指向绝对路径下的可执行普通文件
  • shell 操作符或 argv 格式非法
  • 消息以变量名开头并点明原因

launcher 启动后停

  • 脚本 fork 后退出，没有 exec
  • Agent View 行进入 failed
  • 提示必须 exec，并附脚本先前输出

恢复路径

  • 修正 launcher 与环境传递
  • 停止旧 supervisor
  • 下一次派发重启，再查 Self-exec

权限门 managed settings 可以压住 user 与 shell 的同名环境值，仓库配置不能接管整台机器的 self-spawn。Windows 上这道门没有执行能力，debug log 只会给警告。

会话先要可用凭据

Agent View 不另建一套认证。supervisor 与后台会话复用交互会话已保存的凭据。派发若报 Could not resolve authentication method，说明 supervisor 没拿到可用凭据。先在交互会话运行 /login，或按组织方案配置 API key，再停止旧 supervisor 后重试。O

费用跟着认证入口走

wrapper 只改启动路径，不提供账号或额度。后台会话与交互会话共用同一用量入口。Pro、Max、Team 与 Enterprise 计入订阅用量，Claude Console 消耗预付 API credits，Amazon Bedrock、Google Cloud 的 Agent Platform 与 Microsoft Foundry 由对应云账户结算。并行派发会更快消耗额度。O

错误沿着发起启动的界面返回。launcher 文件无效，进程创建前就报告配置错误；脚本已经运行却没有 exec，Agent View 会把对应行标成 failed，并附上 wrapper 先前写出的内容。后台服务若在可连接前退出，2.1.246 起会直接带回首行原因，2.1.247 继承这项行为。O

这轮核到哪里

我没有启动新的 Claude 会话，也没有列出本机现有会话。触发这项机制要启动 supervisor 或 Agent View 进程。真实派发还需要可用凭据，并会消耗对应订阅、Console 或云提供商额度，所以本轮停在官方契约与无会话帮助。

DOCUMENTED

L 已核 目标二进制实际返回 2.1.247。它的帮助公开了 agents、background 与 daemon 的生命周期入口。

R 缺席 没有测试 launcher 的调用计数、argv 摘要、进程树或退出状态。帮助只能证明入口存在，不能证明 wrapper 在本机执行过。

哈希边界 任务给定二进制 SHA-256 固定基线。本轮普通文件读取受 macOS 权限拒绝，没有把该值写成本轮重算结果。

实现与版本边界

process wrapper 控制 argv 与进程身份，Agent View 管会话状态与恢复。两条机制在 supervisor 的进程创建处相接，本页只沿前一条追到失败回传。O + L + I

为什么 shell export 不适合长期部署

后台服务按需启动，也可能活得比当前 shell 久。官方要求把环境变量放进 user 或 managed settings，让 detached supervisor 继承。已运行的进程只在启动时读取这项值。

为什么要求 exec

supervisor 需要追踪自己启动的 Claude Code 进程。launcher 若 fork 出子进程后自己退出，supervisor 留下一个无法按契约追踪的孤儿，Agent View 会把这次启动判为失败。

怎样判断配置真的生效

新会话中的 /status 会显示 resolved launch command 与不匹配警告。shell 里的 claude daemon status 能给同类信息，也能在变量已经取消后检查仍在运行的旧服务。

还缺哪几块

这些问题会影响企业验收或错误分流。本页没有把它们偷偷补成首屏事实。

UNKNOWN 01

2.1.247 在本机为每类 self-spawn 组装的完整 argv 顺序没有 R。

UNKNOWN 02

launcher 接近三秒边界才 exec 时，各类进程的定时误差与重试差异没有公开。

UNKNOWN 03

launcher 输出多行文本后目标进程成功，各个前端怎样保留或隐藏这些文本没有实测。

UNKNOWN 04

远程 managed settings 下发与旧 supervisor 自动退休同时发生时，精确竞争窗口没有 R。

安全复现

  1. 用隔离配置固定 2.1.247，写一个只记匿名计数与退出状态的 launcher，末尾执行 exec "$@"。
  2. 从 user 或 managed settings 设置变量，停掉测试 supervisor，再打开空 Agent View。不要派发 prompt。
  3. 依次换成不可执行路径和不 exec 的脚本，核对配置拒绝与 Agent View failed 行。
  4. 恢复脚本，用 /status 或 claude daemon status 检查 Self-exec，随后移除测试配置。
