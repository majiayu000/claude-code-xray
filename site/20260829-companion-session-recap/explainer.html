COMPANION XRY / RETURN HANDOFF

回来先看一行，再决定要不要接手

后台会话把回归信息分成几层。状态先告诉你它还在做、等你回答、已经完成或已经失败，行摘要补上进度、需求或产出，peek 给准确问题与结果。用户随后附着，Claude 再贴一条离开期间的短 recap。O

RUNNING看当前动作与最新进度
NEEDS看准确问题或权限请求
DONE看结果，不必先翻完整记录
FAILED先认红色状态，再查原因

recap 没有公开的固定字段。它是一条短回归提示，不能替代状态、peek 或完整 transcript。OI

01 / TERMS

四个东西别混在一起

STATE

会话状态

Working、Needs input、Idle、Completed、Failed 与 Stopped。它先回答会话现在处在哪一格。

ROW SUMMARY

行摘要

agent view 里的一句话，写会话正在做什么、需要什么或产出了什么。

PEEK

展开查看

按 Space 打开。等待时给准确问题，完成时给结果，运行时给完整状态句。

ATTACH RECAP

附着回顾

用户按 Enter 或右箭头附着以后出现的短 recap，概括离开期间发生的事。

02 / SEQUENCE

离开以后，回归从扫一眼开始

本页独有的转换是，用户从未附着转成重新附着，并在切入完整会话时收到一条回归 recap。后台会话怎样启动、运行与停止，仍归 PAR-07 和 PAR-02。I

04 / LIMITS

状态可靠，短句有边界

Working

Claude 正在运行工具或生成回复。行摘要写当前动作。

Needs input

它等用户给答案、权限决定或只有用户能补的输入。peek 给准确问题。

Idle

会话无事可做，等下一条 prompt。

Completed

任务成功结束。peek 直接给结果。

Failed

任务因错误结束。红色状态有明确契约，recap 是否逐字带出原因没有保证。

Stopped

用户停止、进程被外部结束，或后台服务关闭期间结束。

信任与登录要先就绪

  • 未信任的工作目录会先出现 workspace trust 对话框，拒绝后 agent view 不打开。
  • 后台 worker 要能取得已存的登录凭据或 API key。没有凭据时，dispatch 会报认证方式无法解析。
  • 权限请求本身会把会话放进 Needs input，用户要在 peek 或附着后的正常 prompt 里作决定。
  • recap 只报告近况，不会代替用户批准工具。

O

2.1.247 的并发打开有风险

  • 2.1.247 还没有第二写入者拒绝。若同一 conversation 已在另一终端恢复，再从 stopped 行打开，可能启动第二个进程写同一 conversation。
  • 拒绝并发打开的保护从 2.1.248 才加入，不能倒算成固定基线的行为。
  • 会话没有已存 transcript 时，attach 会拒绝，并提供重新开始的路径。
  • 终端 host 死亡或 supervisor 无响应，也可能先以 Failed 或错误提示出现。

O

每条后台会话独立消耗额度

  • 后台会话与交互会话一样消耗订阅用量。并行开的每一条 session 都单独占用配额。
  • 官方给出的量级提醒是，十条并行 session 消耗配额的速度大约是一条的十倍。行摘要的模型请求也经正常 provider 计费。

O

本轮只做到安全静态复核

2.1.247

固定路径上的本机程序返回这个版本。没有启动新会话，也没有附着任何现有会话。L

06 / IMPLEMENTATION

公开实现边界落在四处

01 / SESSION STATE

状态单独保存

官方说明后台会话状态会落盘，并能跨自动更新与 supervisor 重启保留。本轮没有读取这些本机文件。O

02 / RECENT OUTPUT

运行中轻量刷新

行文字最多每 15 秒从最近输出更新一次，这一段不发模型请求。长回合中还会隔几分钟重写。O

03 / MODEL SUMMARY

轮末重写一行

Haiku 级模型经会话正常 provider 写新摘要，并按相同数据条款处理和计费。缺少 Haiku 配置时用主模型。O

04 / ATTACH

回到完整会话

Enter 或右箭头把 agent view 换成完整交互会话，并贴出离开期间的短 recap。recap prompt 与字段优先级没有公开。O

版本与本页有关的变化
2.1.186修复后台 session recap 重复，并让 agent 自己的 end-of-turn summary 显示为 recap 行。
2.1.198Needs input、完成或失败开始通过既有通知通道提醒用户。
2.1.205行摘要改为 session 自己的一行报告，peek 开始给完整状态句与准确问题。
2.1.207peek 从终端边缘截断的那句话开始，等待时长另列一行。
2.1.225未信任目录在打开 agent view 前加入 workspace trust 门。
2.1.247Linux 与 WSL 的终端 host 死亡能更快转成带原因的失败，并提供重启入口。
2.1.248基线之后才加入同一 conversation 的第二写入者拒绝。2.1.247 不能采用这项保护。
07 / UNKNOWNS

短 recap 还有几处黑箱

固定字段有没有

官方只承诺一条短 recap，概括用户离开期间发生的事。没有 schema 保证它同时写出目标、进度、待输入、结果和错误原因。

运行中附着取什么输入

行摘要会从最近输出刷新，轮末摘要另由模型生成。用户在一轮尚未结束时附着，recap 选哪一份材料，官方没有说明。

失败原因能否完整出现

Failed 的红色状态有稳定含义，peek 对完成结果和准确问题有明确契约。失败 recap 是否带原始错误与恢复动作，没有同等保证。

recap 自己怎样计费

行摘要的 provider、模型回退与计费已经公开。attach recap 是否另发请求、怎样算用量，公开文档没有单列。

怎样补上真实运行证据

得到账号与费用批准，并确认隔离环境已有登录凭据或 API key 后，在临时仓库用 2.1.247 启动四条无副作用后台 session。每条 session 都会独立消耗额度。让它们分别停在运行、等待输入、成功与可控失败，逐条记录状态、行摘要与 peek，再附着并只保存匿名化 recap。普通终端失焦后的自动 recap 不放进同一组实验。
