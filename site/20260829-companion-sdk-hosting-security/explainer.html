Agent SDK hosting matrix

SDK 会话状态应该存在哪里

每个 SDK session 都落到一个 claude 子进程。小规模单机可以直接跑，生产环境通常把它放进隔离容器。要跨重启恢复，就把 transcript 接到持久存储，并另存工作目录。多租户再加入口认证、按 session 路由和受控出站。

HOSTING RACK 04STATE ROUTE
subprocess　单 session 运行单元BASE
container　文件、进程与资源边界WRAP
Kubernetes　租户路由与编排FLEET
sandbox host　托管隔离与弹性LEASE

四层可以叠加

先把层级拆开

subprocess 是 SDK 的固定运行模型。container、Kubernetes 与 sandbox host 是它外面的承载和编排层，可以叠在一起使用。 O/I

01 / PROCESS

SDK 宿主与子进程

应用接收请求，调用 SDK。每个 session 对应一个 CLI 子进程，子进程持有 shell、cwd 和本地 transcript。 O

02 / BOUNDARY

容器

把应用和子进程放进 namespace 边界，限制文件、进程、网络和资源。隔离强度取决于具体配置。 O

03 / ORCHESTRATOR

Kubernetes

gateway 先验租户，再把 session 路由到 pod。Redis 保存路由，warm pool 缩短冷启动，网络策略收紧出站。 O

04 / PROVIDER

Sandbox host

供应商负责创建与回收隔离执行环境。你的应用仍要确认持久卷、身份验证、网络控制和租户保证。 O/I

一次请求

路由、恢复、运行、回收

时序只描述官方公开组件。托管供应商内部怎样调度，仍是未知项。

01

入口验身份

gateway 认证调用方，并把外部 session 与租户绑定。Agent 容器不负责验证用户 token。 O

02

选择执行单元

长驻模式固定路由到已有进程。临时或混合模式创建容器、pod 或托管 sandbox。 O

03

装回状态

恢复会话时从 SessionStore 取 transcript。CLAUDE.md 与工作目录产物由挂载卷或同步流程另行恢复。 O

04

启动 query

SDK 通过 stdio 驱动 CLI 子进程。子进程读取 cwd，在本地写 transcript，并向模型端点发 HTTPS。 O

05

受控出站

egress proxy 放行指定域名，记录请求，并可在隔离边界外补入模型或工具凭据。 O

06

保存或销毁

长驻进程继续等待。混合模式镜像 transcript 后缩容。临时模式完成任务就销毁本地状态。 O

失败与停止

三处最容易断

查询没有顶层自动超时。部署方要用 maxTurns 限制循环，还要给容器、pod 与外部存储安排自己的停止条件。 O

状态已安全保存

  • SessionStore 收到 transcript batch
  • 产物已经同步或保留在卷中
  • 执行单元可以回收

继续运行但耐久性受损

  • 镜像写失败会发出 mirror_error
  • 失败 batch 会被丢弃
  • 查询仍会继续

进程或路由中断

  • CLI 缺失或架构不匹配会启动失败
  • pod 消失后要从共享状态恢复
  • 没有 SessionStore 的缩容会丢 transcript

L / NO BINARY

只读检查结果

当前独立 shell 的 PATH 与三个常见安装入口都没有找到 claude。任务给定的 2.1.247 与二进制哈希未能在本轮独立复核。

为什么没有 R

本轮没有启动会产生 API 用量的 Agent SDK 查询，也没有创建 Docker、Kubernetes 或云 sandbox 资源。

检查过程避开了私人 transcript、token、真实 cwd 和工具内容。页面只记录 O、L 与 I，状态保持 documented。

落地顺序

把共享状态逐件拆开

单独设置 cwd 仍不够。配置、自动记忆、transcript、工具进程与宿主缓存都可能形成共享面。

持久化清单

transcript用 SessionStore 跨宿主镜像并恢复。
CLAUDE.md 与记忆挂载专用卷、对象同步，或在多租户服务中显式关闭自动记忆。
工作产物给每个租户单独 cwd，按业务决定应用、审查或丢弃。

边界清单

入站gateway 认证并校验租户拥有 session。
出站默认拒绝，只让代理访问模型端点和获准工具。
密钥由边界外代理注入，减少 Agent 环境中的长期秘密。

账户、认证与费用边界

官方 Quickstart 的常规路径要求 Anthropic 账户和 Claude Console API key。SDK 从运行 Agent 的进程环境读取 ANTHROPIC_API_KEY，也支持文档列出的云端提供商认证。一次 query() 可能包含多次模型交互，模型调用会产生计费用量。结果里的费用字段只是客户端估算，正式账单应以 Claude Console 或 Usage and Cost API 为准。未经 Anthropic 事先批准，第三方产品不得向自己的用户提供 claude.ai 登录或 rate limit，应使用官方 API key 认证方式。 O

与 SDK-02 主页面的交接

宿主先把 session 放进合适的执行边界。边界内部，工具是否可见、候选调用能否获批、Hook 怎样拦截，继续由 SDK-02 工具治理主页面 解释。本页不重复那条权限状态机。

审批等待中的故障恢复

pod 在工具审批等待时消失，待决决定怎样持久化和重放，官方部署页面没有给出完整状态机。

托管 sandbox 的真实边界

冷启动、持久卷一致性、内核隔离、私网连接与域名白名单都依赖供应商。接入前要逐项看合同并做故障注入。

镜像写失败后的下一次恢复

mirror_error 会让查询继续，失败 batch 会被丢弃。下一次 resume 缺多少上下文，取决于失败发生的位置。

宿主应用的共享状态

即使 cwd 与配置目录已经分开，MCP server、自定义工具进程和应用缓存仍可能共享。它们需要宿主自己的租户审计。
