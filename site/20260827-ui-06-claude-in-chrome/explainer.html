Claude in Chrome · connection trace

页面接通以后，Claude 才能看和动

一次 Chrome 任务有一条很短的主线。会话先连上扩展，扩展把可见标签页交给浏览器工具。读取结果回到会话，点击、输入和导航经过当时版本采用的提示路径后落到页面。拒绝、掉线或禁用 Chrome 都会截断这条浏览器连接。

01 / FOUR ACTORS

先认清四个角色

页面动作没有凭空发生。Claude Code 负责会话与工具调用，扩展站在浏览器里，native messaging host 负责让两边找到彼此，可见标签页承接实际读写。

A1

用户

启用连接、选浏览器、给出任务，随后批准、拒绝或手动接管登录与 CAPTCHA。

A2

Claude Code 会话

加载 claude-in-chrome 浏览器工具，把页面结果带回当前对话，并把下一步动作送出去。

A3

扩展与主机

扩展拥有页面读取和浏览器控制能力。首次连接还会安装 native messaging host 配置，让 CLI 找到扩展。

A4

标签页与站点

任务在可见窗口里执行，并沿用浏览器已有登录态。站点许可和组织策略决定它能走到哪里。

02 / ONE BROWSER TASK

一次动作按这个顺序走

唯一状态转换会话从没有页面能力，变成可读取和可操作；权限拒绝、连接掉线或会话禁用 Chrome 后，浏览器工具停止承接动作。

O会话请求 Chrome

用户用 --chrome 启动，或在现有会话运行 /chrome。第一次启用会出现一次性说明，并安装浏览器读取的 native messaging host 配置。

O扩展与浏览器就绪

/chrome 显示 Enabled 和 Installed 才算工作。连接多个浏览器时，用户要选一个；Claude Code 会继续用这次选择，不会因为另一浏览器后来接入就自行切换。

O打开任务标签页

Claude Code 在可见窗口打开新标签，并把自己开的标签收进会话标签组。页面沿用该浏览器的登录状态，用户能实时看到动作。

O读取页面状态

浏览器工具可取页面文字与结构，也能读控制台、网络请求和截图。它还会沿用浏览器已有的登录状态，因此连接前要先确认当前标签页适合交给任务使用。

O提示路径决定下一步

现行文档把 Plan Mode 的纯读取列为免提示，把点击、输入、导航、标签管理和录制列为要审批。2.1.247 有一项版本例外。关闭遥测的会话当时使用 Chrome 扩展自己的提示，不能把每次浏览器动作都写成先经过 Claude Code 权限检查。2.1.251 才统一到 Claude Code 权限检查。

O页面改变或任务暂停

获准后，扩展把点击、输入或导航落到页面。碰到登录页与 CAPTCHA，Claude 会停下，请用户手动完成。拒绝则阻止当前动作。

I停止以后不再发动作

用户可拒绝当前动作或撤销站点许可。另开会话时，--no-chrome 可让该会话不加载集成。连接休眠要用 /chrome 重连。官方没有说明撤权与已发动作之间的竞态，逐调用停止点仍是未知项。

03 / DATA PATH

页面内容怎样进出会话

官方文档公开了工具入口、native messaging host、扩展和页面能力。下面的四段关系有官方事实支撑，把它们画成逐调用传输链仍含研究者推断。

Claude Code 会话保留用户任务，决定何时请求浏览器工具，并接住页面返回结果。
→
浏览器工具claude-in-chrome 提供读取、点击、输入、导航、标签和截图等调用。
→
主机与扩展native messaging host 让 CLI 找到扩展，扩展使用浏览器权限触达标签页。
→
可见标签页DOM、文字、控制台、网络和截图可被读取，获准动作会改动页面。

返回方向 页面文字、结构、截图和调试信息回到当前对话。上传文件走相反方向，Claude Code 先读文件，再把内容交给浏览器。Read 规则、10 MB 总量和多硬链接检查都可能把上传拦住。

04 / GATES & STOPS

动作提示有版本差异，站点门一直在

通用 Claude Code 审批由 SAFE-01 解释。本页只交代 Chrome 动作怎样进入提示，以及扩展能不能进入当前站点。2.1.247 的关闭遥测会话走扩展提示。到 2.1.251，浏览器动作才全部经过 Claude Code 权限检查。

账号与认证门

用户要有 Pro、Max、Team 或 Enterprise 这类直接 Anthropic 计划，并通过 /login 登录。API key、setup-token 长期令牌和第三方模型提供商不支持这项集成。

现行工具动作门

现行文档允许 Plan Mode 的纯读取直接运行。点击、输入、导航和标签管理会改变浏览器状态，需要用户批准。带改状态参数的读取调用也会进入审批。

2.1.247 的例外

目标版本关闭遥测以后，浏览器动作使用 Chrome 扩展自己的提示。页面无法据此断言这些动作先经过 Claude Code 权限检查。2.1.251 才取消这条分支。

扩展站点门

站点许可来自 Chrome 扩展。扩展设置决定 Claude 能在哪些站点浏览、点击和输入。动作提示出现时，用户也可以把当前站点的全部动作放行到本次会话结束。

人工接管点

登录页面、CAPTCHA 和 JavaScript 模态框会让自动动作停下。用户完成登录、解开验证或关掉对话框以后，才能让 Claude 继续。

连接故障点

扩展的 service worker 长时间闲置后可能休眠，浏览器连接随之中断。此时页面动作不会继续，要回到 /chrome 选择重连。

STOP 01

拒绝这一步

选择拒绝会阻止当前站点动作。Claude 可以换安全做法或跳过任务，许可不会因此自动扩大。

STOP 02

收回这个站点

Chrome 扩展设置控制 Claude 可以浏览、点击和输入的站点。收回许可后，后续访问会再次停在这道站点门前。

STOP 03

禁用新会话的连接

以 --no-chrome 启动时，该会话不加载集成。官方没有给出已连接会话中立即卸载浏览器工具的单独命令。扩展 service worker 休眠属于意外掉线，恢复要回到 /chrome 选择重连。

06 / IMPLEMENTATION & VERSIONS

公开到主机配置为止

官方能确认首次连接会写 native messaging host 配置，浏览器工具挂在 claude-in-chrome 入口下。消息 schema、认证材料和重连算法没有公开，页面不会把推断写成协议。

2.1.198

官方 changelog 记录 Claude in Chrome 一般可用。

2.1.211

修复 CLI 与远程会话上传文件，也修复 Chrome 未运行时的启动挂起。

2.1.216

修复 OAuth scope 不足造成的 Chrome 重连循环。

2.1.247 → 2.1.251

本页基线仍有关闭遥测时改走扩展提示的分支。2.1.251 起，浏览器动作一律经过 Claude Code 权限检查。

连接没有建立时先查什么

确认扩展已安装并启用，浏览器正在运行，/chrome 显示 Installed。首次安装主机配置后，Chrome 可能要重启才能读取。组织 IP allowlist 也可能挡住官方桥接域名。

连接建立后为什么突然没反应

JavaScript 模态框会阻塞浏览器事件，扩展 service worker 长时间闲置也会休眠。前者要手动关掉对话框，后者用 /chrome 重连。

会话结束后标签页会怎样

/clear 通常关闭会话标签组。切换会话或退出时，只装着空白新标签的组才会被关闭，用户还在看的页面可能保留。页面保留不代表浏览器工具仍在工作。

07 / OPEN QUESTIONS

官方没有讲到的地方

  • native messaging host 与扩展之间的消息 schema、认证材料寿命和重连退避算法没有公开。
  • Claude 怎样在 DOM、纯文本和截图之间选择，以及截图频率怎样变化，官方没有说明。
  • 用户撤销许可、禁用扩展或关闭浏览器时，已经发出的页面动作会不会完成，公开契约没有原子性保证。
  • 公开 Claude Code 文档没有列出哪些站点会触发动作提示，也没有说明站点判断规则。
  • 浏览器工具常驻会增加上下文占用，官方没有给出可跨任务复用的数字。
