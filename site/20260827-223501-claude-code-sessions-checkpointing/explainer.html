会话身份、恢复、分叉与导出

一段对话，可以续写，也可以分流

我把官方会话页、命令参考和本机 2.1.247 帮助对了一遍。Claude Code 先保存一条带身份的对话记录。你回来时可以继续写这条记录，也可以复制到一个新身份再走另一条路。

一分钟答案

恢复会沿用旧会话身份。会话分支复制历史并切到新身份。/fork 带 prompt 才会让后台副本立即工作，不带 prompt 就等待输入，关闭 Agent View 时还会走旧式 subagent。导出只留下可读文本副本。磁盘里的代码仍按当前状态工作，文件回退交给 checkpoint。

01 / TERMS

先认清四张纸

命令很像，改动的对象并不一样。这里的 branch 指会话分支，不等于 Git branch。

↺

恢复

找回一条旧对话，继续使用它的 session identity。官方只恢复列明的状态。

⑂

会话 branch

复制当前历史，生成新 identity，当前进程随后写入新副本。

⑂⋯

会话 fork

复制当前历史到后台会话。带 prompt 时副本立即工作，不带时等待输入。原会话留在眼前。

□

导出

把当前对话渲染为纯文本，写入文件或剪贴板。identity 不随之改变。

02 / SEQUENCE

一次恢复怎样发生

这一段只写官方可见顺序。没有 R 的地方不补内部戏码。

01　用户选记录

从目录、名称、ID 或 PR 关联开始

--continue 取当前目录最近的合格交互会话。--resume 可打开选择器，也可接名称或 ID。--from-pr 先按 PR 过滤。

O + L　官方 sessions 与本机 help
02　定位 transcript

先查近处，再查本机其他项目

按 ID 查找时，2.1.247 先看当前项目和 worktree，再找其他项目里的唯一匹配。重复复制出的同 ID 不会被随便挑一个。

O　跨项目查找从 2.1.223 起可用
03　恢复列明状态

对话回来，运行条件重新核对

完整历史和工具结果会恢复。模型、agent、权限模式、goal 与 scheduled task 各有例外。部分启动 flag 需要重传。

O　plan 与 bypassPermissions 不会自动恢复
04　长会话选择

Pro 或 Max 可能先出现 summary 对话框

会话闲置约一小时以上且超过 100,000 tokens 时，恢复后会在第一条新消息前让用户选择 summary 或完整历史。无论选哪项，下一次请求都要先处理一次完整历史。summary 还会发起一次摘要请求，换来以后每次请求携带更少内容。

O　此选择只向 Pro 与 Max 提供
05　继续写入

同一身份收到后续消息

恢复路径继续使用旧 session identity。两个终端同时恢复同一身份，消息会交错进入同一 transcript。

O　官方明确给出并发风险
06　退出或再分流

记录持续保存，下一次还能选择

用户可以退出后再恢复，也可以在此时 branch、fork 或 export。每个动作留下的东西不同。

O　session 在工作时持续保存

身份延续不等于进程快照

恢复会把对话历史和工具结果带回来，随后沿用原 session identity。新进程仍会重新读取标准 settings。模型、agent、权限模式和启动参数依照各自规则处理，有些状态会回退，有些 flag 需要再次传入。

导出文件也不是可恢复会话

导出得到的是供人阅读的纯文本。Claude Code 后续恢复时查找本地 transcript，导出的文本没有获得新的 session identity，也不会接替原记录继续写。指定文件名会写出文件，不指定时才进入复制或保存菜单。

04 / LIMITS

恢复会停在哪些地方

session 能找回来，不保证当时的每项运行条件还在。

会直接失败或降级的情况

  • ID 没有匹配记录时，CLI 报找不到 conversation。
  • 另一个项目存在重复 ID 时，跨项目定位不会任意选一个。
  • 原 agent 定义找不到时，会提示后改用默认工具和 system prompt。
  • 选择器载入失败时，启动入口退出；会话内入口保留当前对话。

恢复时重新过的门

  • plan 与 bypassPermissions 不会自动恢复。
  • CLI 新进程里的 branch 不继承 “Allow for this session” 授权。
  • MCP、plugin、额外目录和部分 settings flag 需要重传。
  • 标准 settings 文件会在进程启动时重新读取。
同一 session 开在两个终端会怎样
官方说明两边消息会交错写入同一 transcript。要保留两条可分辨的路线，应先 branch 或使用 fork-session 生成新 identity。
checkpoint 放在哪里理解
checkpoint 会随会话保存，恢复后仍可调用 rewind。它追踪哪些文件、怎样撤回代码、哪些工具改动漏掉，都属于 CTX-08。这里不另画一套回退状态机。

继续对话需要可用账户

Claude Code 要求账户或受支持的云服务凭据。个人可用 Claude.ai 账户，团队还可用 Team、Enterprise、Console、Bedrock、Vertex AI 或 Foundry。恢复先定位本地记录，发送后续消息仍按当前登录方式和用量限制运行。

长会话的 summary 有套餐和 token 代价

Pro 与 Max 才会看到恢复 summary 的选择，而且只在会话闲置约一小时以上、历史超过 100,000 tokens 时出现。下一次请求无论怎样选都要处理一次完整历史。保留全文会让后续每次请求的用量随历史大小增长，summary 会多做一次摘要请求，随后每次携带的内容较少，也可能漏掉原历史中的细节。Pro 与 Max 的用量含在订阅额度内，Console API 用户按 token 计费，云服务按各自账单处理。

06 / DISK

磁盘上留下什么

这里采用官方公开路径和格式边界，没有进入本机的会话目录。

默认 transcript

~/.claude/projects/<project>/<session-id>.jsonl

每行是消息、工具使用或元数据对象。格式属于内部实现，升级后可能变化。脚本应优先用官方导出或结构化接口。

持久化开关

非交互 -p 可用 --no-session-persistence 关闭该次落盘。官方另提供环境变量关闭所有模式的 transcript 写入。关闭后，该记录无法恢复。

项目目录参与会话筛选，也参与 transcript 的默认归档。按 ID 恢复时，程序先查当前项目和它的 worktree。跨项目搜索只接受唯一匹配，这条限制用来避免同一记录的复制件把目标弄混。两个终端若主动打开同一个身份，官方没有替它们分流，消息仍会交错写入同一份记录。

2.1.247 需要记住的版本差异
2.1.223 才加入按 ID 的唯一跨项目查找。2.1.212 起，Agent View 开启时的 /fork 生成独立后台会话，旧的 forked-subagent 入口移到 /subtask。后台副本收到 worktree 隔离指令的说明要求 2.1.221 或更高版本。
