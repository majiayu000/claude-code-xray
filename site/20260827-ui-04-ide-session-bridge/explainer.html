选区进会话，改动回到 Diff

01 / TERMS

三个角色就够了

编辑器

掌握当前选区、活动文件和原生 diff 视图。它还可以提供诊断，但诊断怎样产生属于 EXT-06。

Claude 会话

接住这次提示、既有历史和编辑器上下文。恢复、分叉与落盘由 CTX-02 解释。

本地 IDE 桥

扩展运行名为 ide 的本地 MCP 服务。CLI 用内部 RPC 读选区、开 diff；这些 RPC 不会冒充普通模型工具。

这三个角色没有合成一个程序。编辑器仍决定你眼前有什么。哪段文字被选中、哪个文件处于活动状态、该打开哪种原生视图，都由宿主 IDE 提供。Claude Code 则记录这轮工作进行到了哪里。提示、历史、文件编辑与权限判断都留在当前会话。中间的桥只负责交换这两侧需要的状态。因此，隐藏选区改变的是下一次送入会话的上下文，不会抹掉既有历史；拒绝一张 diff 改变的是这次文件应用，也不等于删除整段会话。

02 / SEQUENCE

一次改动怎样穿过编辑器

用户选中代码并发送提示

VS Code 自动让当前提示看见高亮文本，也允许隐藏选区；插入引用时还会带上文件路径与行号。JetBrains 在连接存在时，把选区和活动文件路径加入每次提示。两者都以发送当时的编辑器状态为入口，不表示整个工作区会自动塞进会话。

O

扩展把编辑器状态交给当前会话

本地 ide 服务负责桥接。它运行在临时端口，并用本次 IDE 启动生成的令牌鉴权。会话仍有自己的历史与上下文，多开会话不会把历史合成一份；同一个选区被送往哪个会话，取决于当时连接和操作的那一个会话。

O

Claude 读取上下文并提出文件变化

模型请求、工具权限和文件编辑仍由 Claude Code 引擎处理。IDE 扩展负责把编辑器信息接进来，却不替模型决定该改什么，也不绕过文件工具的权限边界。这里关于两侧职责的连接是根据官方公开接口作出的概括，所以保留 I。

O + I

改动回到 IDE diff

VS Code Manual 模式先展示原稿与建议稿的并排差异，并等待接受、拒绝或补充指令；用户还可以先修改建议稿。JetBrains 可把 diff viewer 选为 IDE 或 terminal，但官方没有承诺它和 VS Code 使用同一组按钮。

O

权限门给出停止位置

Manual 停在 diff，Plan 更早停在改文件之前。Edit automatically 和可用时的 Auto 会减少确认，但仍可能受权限规则或其他安全控制约束。出现批准卡时，接受才让这次变化继续，拒绝则终止这次应用；它们都不是会话级删除。

O

O　选区和打开 diff 的内部 RPC 会从模型工具列表中过滤。模型在 JetBrains 中可见的 IDE 工具是只读诊断接口。锁文件的公开结构只用于本地鉴权，本轮没有读取它。

这条双向线承载两种不同的消息。向右走时，选区和活动文件给会话补充“我此刻正在看的内容”。向左走时，桥请求 IDE 把这次文件变化放进熟悉的审阅界面。官方资料能证明这些用途和本地传输方式，却没有公开 2.1.247 的完整字段、逐条消息顺序或失败重试协议；页面因此不把示意图写成抓包结果。

04 / LIMITS

五个地方会暂停或失去桥接

账户与计费

首次使用需要完成登录。直接使用 Anthropic 服务时，要有付费 Claude 订阅或 Claude Console 账户。VS Code 也能按官方指引接入 Amazon Bedrock、Google Cloud 的 Agent Platform 等第三方提供商，认证与计费随后服从对应提供商。装好扩展本身不等于已经取得产品准入。

选区门

VS Code 可以隐藏当前选区；隐藏后，下一次提示不再自动携带那段高亮内容。JetBrains 的匹配 Read deny 会挡住选中文本和活动文件提示。两种控制发生位置不同，结果都是让桥少送一部分编辑器上下文。

编辑批准门

Manual 等用户处理 diff，Plan 等用户批准计划。自动编辑模式缩短了这段停顿，也扩大了配置文件风险。是否出现停顿取决于当前模式与适用规则，不能仅凭看见 IDE diff 就推断文件尚未落盘。

连接失败

插件没安装、没启用或 IDE 没被发现时，原生 diff 与选区桥不会出现。CLI 仍可退回终端工作，但此时提示不会自动获得 IDE 选区，变化也不保证回到原生 viewer；这是界面能力降级，不等于会话失效。

宿主错位

JetBrains Remote Development 要把插件装在远端 host。WSL2 的 NAT 或防火墙也可能挡住 IDE 检测。此类故障发生在桥的发现与连接阶段，所以先检查插件所在宿主和网络边界，比追查模型回答更接近故障点。

05 / LOCAL CHECK

这轮核了二进制，没有跑会话

只读命令

直接调用保留的 2.1.247 二进制，检查版本、SHA-256 与 --help。随后只在标准扩展位置定点查找 IDE 插件。

关键结果

版本与给定二进制哈希一致。帮助里的 --ide 要求恰好发现一个有效 IDE；本机标准位置没有找到两类插件。

这只能算 L。它证明目标版本公开了 IDE 连接开关，也证明检查过的标准位置没有插件；它不能证明选区曾被传输、diff 曾被打开，更不能证明接受或拒绝后的磁盘结果。真实链路需要插件与一次 Claude 会话，本轮没有启动它，也没有产生费用。页面因此保持 documented，示意中的运行时顺序以 O 为主，不能升级成 R。

06 / IMPLEMENTATION

公共链相同，宿主方式不同

对照点VS CodeJetBrains
会话宿主图形面板自带一份 CLI。终端里另跑 claude 仍需独立安装。插件不自带 CLI，在 IDE 终端运行已安装的 claude。
选区入口高亮文本自动进入提示，可切换可见性，也可插入带行号引用。连接时每次提示附带选区和活动文件路径，Read deny 可阻断。
DiffManual 明确提供并排 diff、接受、拒绝和补充指令。diffTool 决定在 IDE viewer 或 terminal 展示。官方没有承诺统一按钮细节。
会话接续图形面板与 CLI 共用历史，可从列表或 --resume 接续。本身就是 CLI 终端会话；外部终端用 /ide 接桥。

版本边界　VS Code 从 2.1.246 起会恢复会话结束时的 Plan 模式，但显式初始模式和 process wrapper 会覆盖。目标版本 2.1.247 满足门槛。当前在线文档没有提供按 CLI 版本冻结的 IDE 插件快照。

这份对照只用来找出相同链路落在哪个宿主里。VS Code 把会话入口做进图形面板，并随扩展附带 CLI；JetBrains 从 IDE 终端里的外部 CLI 起步。入口不同以后，选区仍进入当前会话，建议变化仍交给 diff，权限仍决定是否等待。平台表只在宿主、入口和 viewer 上分叉，两列描述的仍是同一套桥接机制。

展开复现步骤
  1. 在一次性仓库固定 2.1.247，记录版本、二进制哈希和插件版本。
  2. 以 Manual 模式启动全新会话，选中无敏感信息的两行文本，确认 UI 显示选区。
  3. 先隐藏选区或加入 deny，再发下一次提示，检查选区是否消失。
  4. 请求改一个字面量，记录 diff 的打开位置与批准提示，再比较接受或拒绝后的文件哈希。
  5. 断开 IDE 桥后重复一次，确认终端回退。只保存匿名结果，不保存 prompt、session ID 或令牌。
