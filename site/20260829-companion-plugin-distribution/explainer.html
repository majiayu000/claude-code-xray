MARKETPLACE SHIPPING DESK

一份目录先能被找到，推荐和依赖才有落点。

发布方交付的是一份可寻址、可校验、可更新的目录。目录告诉 Claude Code 去哪里取插件，插件声明再给出版本和依赖。推荐还要经过组织许可或官方目录检查，任何一种提示都不会替用户安装。

OL官方契约已经讲清，当前研究 shell 没有可调用的 Claude Code 入口，也没有远端发布权限。本页保持 documented，不把文档示例写成真实运行。

FOUR DECLARATIONS

四份声明，各管一件事

M

目录文件

marketplace.json 给出目录名字、维护者、插件条目和每个插件的 source。

P

插件 manifest

plugin.json 给出插件身份、组件、显式版本和依赖。默认 strict 模式下，它是组件定义的权威来源。

R

Relevance

目录条目里的本机匹配线索。管理员放行该 marketplace 后，线索才会让建议出现。

H

CLI hint

外部 CLI 输出的一行标记。协议只接纳 Anthropic 控制目录中的插件。

O官方契约

Anthropic 文档公开的 schema、流程、限制和版本门。

L本机证据

本轮 shell 的命令可见性与获准读取的相邻页面。

R真实实验

本页没有 R。未发布、未登录、未启动 Claude 会话。

I研究推断

只连接公开步骤，内部审核和事务实现仍留作未知。

ONE PRODUCER TRIP

发布方走过六个站点

O这条时间线停在可分发与可建议。用户怎样添加目录、安装、启停和卸载，交给相邻主页面。

01 PACKAGE

整理插件

组件放在插件根目录，manifest 写身份、版本与依赖。

02 CATALOG

登记条目

目录根写 marketplace 文件，每个条目给名字和可取的 source。

03 CONSTRAIN

固定版本

显式版本适合发布节奏，省略版本可让 git commit 成为更新身份。

04 RECOMMEND

声明线索

组织目录可写 relevance。自有 CLI 只有在官方目录列名后才能发 hint。

05 VALIDATE

校验与测试

先校验目录和 manifest，再逐项试组件。目录校验不会替你打开所有组件文件。

06 DISTRIBUTE

托管或提交

自建目录分享 git 或 URL 来源。Community 走提交审核，官方目录另行策展。

ACCOUNT AND PLAN GATES

四种发布入口，账号和套餐各不相同

SELF-HOSTED

自建托管

O官方步骤是托管目录仓库并分享地址，没有设置 Anthropic 账号或 Team、Enterprise 套餐门。

登录与权限
发布方要有托管服务的写权限。私有来源还依赖 git 凭据，具体账号由托管方决定。
费用
I发布步骤没有模型调用。仓库、网络和托管费用由所选服务决定，Anthropic 文档没有替第三方定价。
ORG SETTINGS

组织内分发

OOrganization settings > Plugins 是 Team 或 Enterprise 套餐的分发入口。

仓库与权限
Marketplace 仓库必须是 private 或 internal。组织同步通过 Claude GitHub App 或组织的 GitHub Enterprise App 读取仓库。
费用
入口受 Team 或 Enterprise 套餐约束。I官方没有给插件同步另列一次模型调用费。
COMMUNITY / CLAUDE.AI

组织表单提交

Oclaude.ai 的 Community 表单要求 Team 或 Enterprise 组织，还要有目录管理权限。Owner 默认具备该权限。

登录与权限
需要登录合格组织并进入目录提交表单。提交后仍要经过 validator 与安全筛查。
费用
套餐本身有费用边界。I官方提交说明没有公布按次提交费，也没有要求为审核启动付费模型会话。
COMMUNITY / CONSOLE

个人作者提交

O不在 Team 或 Enterprise 组织里的个人作者可以改用 Console 表单，仍需 Console 账号并接受同一审核链。

登录与权限
需要登录 Console。公开说明没有再列 claude.ai 的目录管理角色。
费用
I公开提交说明没有写 API 余额、付费调用或提交费要求。本页把费用条件记为未确认，不写成免费。

I“没有单列模型调用费”和“免费”含义不同。这里只记录官方发布步骤与明示门槛，账号订阅、第三方托管和未来审核收费仍按各自条款确认。

FOUR STOP GATES

四道门，任何一道都能停

IDENTITY GATE

名字与 source

O同名目录会替换先前来源。保留名和冒名名称在每次加载时重查，第三方不能借官方名字通过。

POLICY GATE

组织许可

ORelevance 的声明本身不够。管理员还要许可 marketplace，并让登记来源与许可来源对得上。

SOLVER GATE

依赖与标签

O跨目录默认拒绝。版本范围找不到满足条件的标签时，独立 git 依赖会让安装停住。

HUMAN GATE

用户确认

ORelevance 只显示建议。Hint 也给一次询问，30 秒没有答复就按拒绝处理。两者都不自动安装。

目录校验通过以后还差什么

Marketplace 目录校验不会打开每个插件的 skill、agent、command 或 hook 文件。发布方还要逐项测试组件。Community 审核另有自动安全筛查，公开文档没有给出完整规则。

为什么自建 marketplace 的 hint 不工作

CLI hint 协议明确要求目标位于 Anthropic 控制的 marketplace。自建目录可以用 relevance 做组织内建议，也可以靠文档和安装命令分发，hint 标记会被静默丢弃。

推荐会泄露命中的路径和命令吗

官方契约说 relevance 在用户机器本地匹配，不增加网络流量，也不把命中的信号或值报告给 Anthropic 或目录运营方。本页没有抓包 R。
