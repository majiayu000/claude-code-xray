Dev Container 的环境构建与隔离生命周期

代码留下，容器可换

编辑器把宿主机仓库挂进容器，Claude Code 与工具在容器里运行。重建会换掉容器 home；仓库修改回到宿主机，显式配置卷继续保留。网络规则和凭据能进容器，也会扩大容器内进程可触达的范围。O + I

先认清四层

我把 Anthropic 的 Dev Container 文档和官方仓库里的三个参考文件逐项对过。这里说的隔离主要围住命令、工具链与临时文件；bind mount 和配置卷是有意穿过边界的通道。

镜像

Dockerfile 或基础 image 给出系统、工具与 Claude Code 安装层。官方 Feature 也能在构建时注入 CLI。O

workspace

宿主机仓库 bind mount 到容器。Claude 改的是容器路径，结果落回本地仓库。O

容器 home

没有额外挂载时，它随重建被替换，登录和用户状态也要重新处理。O

命名卷

把配置目录从临时层移出。项目化卷名能减少不同仓库共用状态。O

一次生命周期

下面七步把官方配置接成时间顺序。编辑器和 Docker 的细节会因工具而变，顺序中的通用连接标作 I，官方参考配置直接规定的动作标作 O。

01 / 定义

仓库提供配置

.devcontainer 选 image 或 Dockerfile，声明 Feature、挂载、用户与启动命令。O

02 / 构建

生成镜像层

安装系统工具和 Claude Code。Feature 默认取最新 CLI；固定版本要改走 Dockerfile。O

03 / 创建

接上两种持久层

仓库 bind mount 成 workspace，命名卷接到 Claude 配置目录。O + I

04 / 启动

先过启动门

参考配置用非 root 用户，并等待防火墙启动脚本结束。脚本失败会挡在进入工作前。O + I

05 / 认证

凭据进入容器

浏览器登录、短期 token、环境变量或 workload identity 选一条适用路径。认证方式也决定功能范围和费用归属。O

06 / 工作

命令留在容器

Claude 与工具看见同一套依赖。它改 workspace，宿主机仓库同步出现修改。O

07 / 销毁

重建或删除容器

重建替换临时 home。删除时会不会连项目化命名卷一起清掉，要看编辑器与运行时。O + I

哪些东西穿过边界

Dev Container 的价值来自边界可写。文件、身份与网络都有明确入口。入口越多，容器能做的事越多，销毁临时层以后留下的东西也越多。

宿主机或外部控制面

仓库目录以 bind mount 进入 workspace，写入可回到宿主机
命名卷承接配置、认证和会话状态，寿命独立于临时 home
环境与秘密经 containerEnv、Codespaces secret 或 workload identity 注入
⇄

容器内 Claude Code

文件视图和容器工具链共用 workspace 路径与依赖
配置目录按 CLAUDE_CONFIG_DIR 落到持久卷或临时 home
出站连接受容器网络规则限制，代理与证书请求链留给 ADM-03
停止后再启动官方只明确 Codespaces 会保留 home。其他工具待实测。O + I
重建容器临时 home 丢失。bind-mounted 仓库与显式卷在边界外。O + I
删除容器和卷Anthropic 没给跨编辑器统一规则。配置卷是否由编辑器代删仍未知。I

四个停止位置

构建、启动、认证和退出各有自己的失败点。容器提供隔离，却不会替使用者判断挂载和凭据是否过宽。

构建没有完成

  • 基础 image 或包下载失败
  • Feature 无法安装 Node.js 与 npm
  • Claude Code 安装入口未出现
O + I

启动脚本拦住进入

  • 参考防火墙缺少 capability
  • 域名解析或 GitHub 元数据失败
  • 允许与拒绝验收不符合预期
O + I

认证没有完成

  • 浏览器 callback 没有转发进容器
  • 云凭据没有注入
  • 配置卷路径和 remoteUser home 不匹配
O + I

删容器以后仍要核卷

  • 配置放在项目化命名卷
  • Anthropic 没承诺编辑器代删该卷
  • 敏感状态应按所用运行时显式核对
I
认证方式决定谁为用量付费

claude.ai 账号登录需要 Pro、Max、Team 或 Enterprise。Pro 与 Max 的 Claude Code 用量包含在订阅中，Team 与 Enterprise 从成员席位额度扣取。Console 路径按 token 计入 Anthropic API 组织，Bedrock、Google Cloud 与 Microsoft Foundry 路径按 token 计入对应云账户。容器只承接凭据，不会把一种计费关系变成另一种。O

跳过权限提示仍有什么风险

Claude 仍能改 bind-mounted workspace，也能访问参考防火墙明确放行的路径。脚本允许任意目标的 UDP/53 与 TCP/22、loopback、从默认路由推算出的宿主机 /24 网段，以及 allowed-domains 集合。容器内可读的 Claude 凭据同样可能被恶意仓库利用。官方建议只对可信仓库使用，并避免挂载宿主机 SSH 和云凭据文件。O

网络请求为何在这里停住

本页只说明 allowlist、环境变量和网络 capability 在容器生命周期中的位置。代理选择、CA、mTLS 与连接重试见 ADM-03 企业代理、证书与网络请求链。

本轮没有运行容器

当前 PATH 找不到 claude、docker 与 devcontainer。本轮无法读 CLI 帮助，也没有拉镜像、建卷、登录或启动付费会话。

实现与版本边界

官方把参考容器定位为工作示例，维护基础镜像不在承诺内。项目可以只用 Feature，也可以复制三份参考文件后按自己的工具链调整。

部件官方参考做法版本或寿命边界证据
运行边界编辑器连入 Docker 容器，终端、语言服务、构建工具与 Claude Code 在容器里运行。宿主机仓库以 workspace 形式挂入，文件修改落回本地仓库。O
Dev Container Feature在 devcontainer.json 中加入官方 Claude Code Feature。1.0 固定 Feature 安装脚本，不固定 Claude Code。默认安装最新 CLI。O
workspace官方参考配置把本地仓库 bind mount 到 /workspace，并把它设为工作目录。远程用户为非 root 的 node。O
Dockerfile官方参考镜像以 Node 20 为基础，通过 npm 安装 Claude Code。CLAUDE_CODE_VERSION 默认值为 latest。复现 2.1.247 需要固定包版本。O
Claude 配置把 ~/.claude 放进命名卷，并让 CLAUDE_CONFIG_DIR 指向同一路径。临时 home 在重建时丢失，项目化卷名可减少仓库之间共用状态。O
认证入口浏览器认证从容器内的 claude 启动；回调不能转发时，可把 code 粘回终端。云凭据可经 containerEnv、Codespaces secret 或 workload identity 进入。O
凭据边界官方警告不要把宿主机 SSH 或云凭据文件直接挂入容器。配置卷里的 Claude 凭据仍可被容器内进程读取，应优先用仓库范围或短期 token。O
启动门官方参考配置通过 postStartCommand 运行防火墙脚本并等待结束。脚本需要 NET_ADMIN 与 NET_RAW，Claude Code 本身不需要。O
参考防火墙脚本放行任意目标 UDP/53、任意目标 TCP/22、loopback、推算出的宿主机 /24 网段，以及 allowed-domains 集合。默认策略随后设为 DROP，已建立连接继续放行；脚本最后检查一个应失败和一个应成功的请求。O
权限范围非 root 用户与跳过权限提示都不会切断 bind-mounted workspace。Claude 仍能修改仓库，并访问防火墙允许的目标。O
销毁边界重建会替换临时 home，命名卷用于在重建后保留 Claude 状态。停止、关闭或删除时怎样清理项目化卷，Anthropic 没给跨编辑器统一规则。O + I

固定研究基线怎样落进镜像

本页基线是 Claude Code 2.1.247。官方 Feature 的版本标签不会固定这个版本。需要可复现镜像时，在自己的 Dockerfile 指定 @anthropic-ai/claude-code@2.1.247，同时关闭自动更新。此路径只有官方文档契约，本轮没有构建。O

这些问题会改变销毁后的残留或网络保证。官方没有给出统一答案，本轮也没有 R，因而留在首屏结论之外。
