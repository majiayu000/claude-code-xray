01 / TERMS

先认清四个角色

Agent View 管的是完整 Claude Code conversation。它不把子 Agent 或 team teammate 各画成一行。 O

用户

派发任务，查看状态，回答问题，附着、脱离、停止或删除。

Agent View

一块本地控制面。它显示 roster，也接收派发和回复。

supervisor

独立于终端的用户级进程。它托管 worker，负责重连与闲置回收。

background session

一条完整、独立、可恢复的 Claude Code 对话。附着时仍属于后台会话。

02 / SEQUENCE

一条会话怎样走完

这条时序从用户派发开始，到停止后仍能找回 conversation 为止。跨会话消息没有插进来。

  1. 派发

    用户在 Agent View 输入普通任务，或从 shell 用后台参数启动。每条普通 prompt 创建一条新 session。PR 引用和后台 shell job 另有处理。太短的输入会被拒绝。 O

  2. 接管

    supervisor 把预热 worker 分给这条 session，应用目录、设置与凭据，再准备下一个 worker。 O

  3. 载入项目

    session 按运行目录读取项目设置。provider 与部分环境跟随派发来源，gateway 还要满足额外条件。 O

  4. 进入 roster

    行状态随工作变化。需要回答、批准、sandbox 放行或 MCP 输入时，session 进入 Needs input。 O

  5. 回复或附着

    Space 打开 peek 并可直接回复。Enter 或右方向键进入完整对话，空输入时按左方向键脱离。 O

  6. 完成或出错

    结束后行进入 Completed、Failed 或 Stopped。完成且无人附着约一小时，worker 可能退出，磁盘状态还在。 O

  7. 停止与保留

    停止结束进程，conversation 仍可附着或恢复。删除的结果取决于入口和 worktree 里的内容，有些情况会同时保留 roster 行与 worktree。 O

Working工具或回复正在运行
Needs input等待用户独有的输入
Idle无任务，等下一条 prompt
Completed任务成功结束
Failed任务以错误结束
Stopped用户或外部事件停止
I这排状态方便阅读，不能当成每条会话都必经的线性流程。会话可以直接完成、失败或停止，也能在回复后回到 Working。

03 / FLOW

终端可以离开，磁盘状态还能接续

Agent View 可以退出，shell 也可以关闭。会话继续工作的条件来自 supervisor 与 worker；进程闲置退出以后，conversation 和状态仍留在配置目录。 O

派发来源

  • 当前目录或所选项目
  • 设置与派发默认值
  • 存储凭据与 provider 选择
  • 用户 prompt
→

supervisor

  • 分配预热 worker
  • 维护 roster
  • 重连与重启
  • 回收闲置进程
→

会话留下的东西

  • daemon/roster.json
  • jobs/<id>/state.json
  • conversation transcript
  • 任务结果与可选 worktree
I把官方的退出继续运行、磁盘状态和重连契约放在一起看，roster 更像控制面，worker 可以替换，保存的 conversation 与 state 才让工作接得上。

04 / LIMITS

会话会在哪些门口停住

Needs input 往往意味着用户必须出现。权限模式能随入口带过去，新的系统授权和高风险免责声明仍要由人处理。

PERMISSION

批准与提问

工具批准、sandbox 放行、MCP 输入和 Claude 的问题都会让行等你。peek 可以回答，标准权限面板需要附着。

TRUST

工作区信任

目录尚未信任时，Agent View 先显示 trust 对话框。拒绝后直接退出，不会打开列表。

BYPASS

高风险模式

后台参数不能跳过首次免责声明。没有接受记录时，Claude Code 要求一次交互确认。

MACOS

系统级授权

后台 host 是独立进程。受保护目录与本地网络可能要为 Claude Code 单独授权。

SHUTDOWN

睡眠与关机

睡眠后可以重连。关机和重启会停止运行。2.1.247 会把长时间离线后发现的非等待 session 显示成新的 Failed。

QUOTA

额度

每条后台 session 独立使用订阅额度。十条并行任务大约以单条十倍的速度消耗额度。

AUTH

登录与 API key

派发前要先通过账号登录保存凭据，或配置 API key。supervisor 拿不到凭据时，派发会失败，错误名写作 Could not resolve authentication method。

O2.1.247 还没有同一 conversation 的并发打开保护。另一终端已经恢复它时，Agent View 仍可能启动第二个写入进程。2.1.248 才会拒绝第二次打开。

05 / LOCAL CHECK

R 0

派发会产生真实用量，附着或停止又可能碰到用户正在使用的 session。本轮停在只读帮助与归档二进制核对。页面因此是 documented。

06 / IMPLEMENTATION

继承有边界，重启也有边界

官方把来源说得很细。目录决定项目设置，派发入口决定权限模式，shell 决定 provider 选择，gateway 还要满足环境和目录条件。

目录、设置与凭据怎样到 worker

worker 按自己的运行目录读取设置。supervisor 使用与交互 session 相同的存储凭据，并把派发 shell 的 provider 选择与 PATH 应用到 worker。凭据可以由 /login 保存，也可以来自配置的 API key。若 API key 放在环境变量里，必须从带有该变量的 shell 重新启动 Agent View 或后台派发入口。gateway 端点不会从启动 supervisor 的 shell 无条件扩散到所有 session。 O

权限模式怎样决定

从现有 session 移入后台会保留当前模式。由该 session 打开的 Agent View 再派发，会沿用来源模式。从 shell 直接打开 Agent View 时，新 session 按目录内的新会话规则启动，显式派发默认值优先。 O

进程退出以后怎样接回来

完成且无人附着约一小时后，supervisor 可以回收 worker。再次回复或附着时，它从保存的 conversation 和 state 启动新进程。运行中、等待输入、被 pin 或仍有活跃后台工作的 session 不按这条闲置规则回收。 O

停止、删除与 respawn 的差别

stop 结束 session 并保留 conversation。respawn 重启并接续保存的 conversation，找不到保存内容时才重跑原 prompt。Agent View 的二次删除快捷键 Ctrl+X 通常移出 roster 行，也会删掉 Claude 创建的 worktree 及其中未提交改动。shell 删除命令 claude rm 遇到未提交改动时会同时保留 roster 行和 worktree。两种入口遇到无法确认已另行保存的 commits、占用或锁，也都会保留两者。conversation transcript 始终留在本机。 O

O2.1.247 加入 Linux 与 WSL 的终端宿主死亡检测和附着超时恢复。2.1.248 才增加关机超过 48 小时后显示 Stopped 并要求确认恢复的分支，本页没有把它写回 2.1.247。

07 / UNKNOWNS

还没有证据回答的事

  • 01这个账号与管理策略在 2.1.247 上会不会实际打开 Agent View，本轮没有 R。
  • 02roster.json 与 state.json 的完整字段、原子写入和损坏恢复没有公开 schema，本轮也没有读取私人配置目录。
  • 03派发到首行出现、状态刷新、通知到达和闲置回收的本机实际时延没有测量。
  • 04当前安装方式下，macOS 会把受保护目录与本地网络授权显示给哪个系统主体，没有触发验证。
  • 05高并发、额度耗尽、provider 暂时失败或预热 worker 崩溃后的调度与退避算法，官方没有完整公开。
