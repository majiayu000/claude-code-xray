01 · 四个词

schema

中间消息

04 · 门、失败和停止

host 要检查字段，不能只看绿灯

配置与运行

  • schema 无效2.1.205 以后在启动阶段失败，并指出 schema 问题。
  • 工具没有权限agent 可能无法取得 schema 要求的数据，权限决策仍按原有规则处理。
  • 连接或进程故障这类失败可能没有 result，host 只能处理抛出的异常。

终局检查

  • 验收成功消息类型是 result，subtype 是 success，structured_output 也确实存在。
  • 没有有效输出留下subtype 是 error_max_structured_output_retries。常见原因是 schema mismatch 反复未修好；model fallback 撤回已完成输出且没有成功重试，也会使用同一 subtype。errors 可帮助区分两者。
  • 字段缺席官方允许出现 success 但没有 structured_output。host 也要把它当作失败。
单次查询还有一次异常交接

官方示例说明，错误 result 会先被迭代器产出，单次 query 随后抛出异常。host 应先记录 result 的 subtype 和 errors 摘要，再由外层异常处理完成清理。

运行前先确定谁的凭据、谁的账单

官方 Quickstart 要求 Anthropic 账户，并以 Claude Console 的 API key 作为直接接入方式。Agent SDK 也支持 Amazon Bedrock、Google Cloud Agent Platform 和 Microsoft Foundry，此时要配置对应云平台的凭据。Claude Code 若已保存订阅 OAuth 登录，会在没有更高优先级凭据时采用它。

把 Agent SDK 做进第三方产品时，Anthropic 要求开发者使用 Console API key 或受支持的云平台凭据。未经批准，第三方不能向用户提供 claude.ai 登录，也不能代用户转接 Free、Pro 或 Max 凭据。平台托管未修改的 Claude Code 时，终端用户仍可走 Anthropic 自己的登录流程，并使用自己的凭据。

凭据所有者承担相应的用量。API key 归 Claude Console 账户，云平台凭据归对应提供商账户。result 里的 total_cost_usd 只是客户端估算，正式账单要看 Claude Console Usage 页面或 Usage and Cost API，不能拿这个估算字段向终端用户计费。

06 · 实现切口与版本

验证过的 JSON 仍要进入宿主类型系统

SDK 交付 JSON

TypeScript 参考把 structured_output 留作宽类型，Python ResultMessage 把它声明为 Any。schema 验证保证运行时形状，编译器不会凭空知道具体业务类型。

host 建立 typed object

官方示例再次调用 Zod safeParse 或 Pydantic model_validate。成功后的对象才带应用代码能追踪的字段类型。

消息分支先于字段读取

先确认 result，再确认 success，最后确认 structured_output 存在。任何一步没过，都不要把正文文本强转成业务对象。

INPUToutputFormat / output_format
SCHEMAjson_schema · draft-07
PASSresult + success + structured_output
TYPEZod safeParse / Pydantic model_validate
FAILerror_max_structured_output_retries

收件代码要保留两道检查

第一道检查发生在消息循环里。host 可以把 stream_event 和 assistant 消息交给界面更新进度，但这两类消息没有承诺业务对象已经过 schema 验证。读到 result 以后，host 先查看 subtype。错误 subtype 应进入失败分支，并保留经过删减的 errors 摘要供诊断。连接在 result 之前中断时，外层异常分支负责收尾，因为此时没有终局字段可查。

第二道检查发生在应用边界。success 只说明 agent loop 正常结束，host 还要确认 structured_output 存在，再交给 Zod 或 Pydantic。语言级解析成功以后，路由、持久化和后续函数才接触具体类型。若这一步失败，问题已经落到 host 的类型定义、转换选项或版本漂移上，不能退回去采用 assistant 正文。这个处理顺序让界面仍能实时显示过程，也让依赖固定字段的业务代码只接收终局对象。I

对外报告 schema mismatch 时，host 还要保留错误来源。error_max_structured_output_retries 说明最终没有可接收的对象，但同一 subtype 也可能来自 model fallback 撤回输出后未能完成重试。errors 摘要能帮助运维区分这两种情况，subtype 本身只能确定收件失败。O

版本边界

固定基线是 Claude Code 2.1.247。官方把无效 schema 的启动失败分界写在 2.1.205，因此基线应当具备这项行为。这个“应当”来自官方版本说明与版本号比较，当前环境没有 R。研究日读取的官方文档也可能含有 8 月 27 日以后的补充说明。
