01 / TERMS

四种东西别混在一起

上下文窗口

模型这一轮能看见的总量。会话历史、读过的文件、命令输出、项目指令和系统指令都会占位置。O

工具输出清理

接近上限时先处理较旧的工具结果。官方公开了先后顺序，没有公开选择算法和清理粒度。O/I

压缩

把原消息历史换成一份结构化摘要。它保留继续工作的线索，也可能漏掉早期细节。O

提示缓存

服务端按请求开头做精确匹配。命中后可少处理重复前缀；它不等于缩短上下文本身。O

O官方契约

Anthropic 官方文档、帮助与仓库。

L本机证据

版本、帮助、公开 schema 与安装文件。

R真实实验

本轮没有启动付费会话，因此没有 R。

I研究者推断

只负责串起证据，不能冒充运行事实。

02 / SEQUENCE

一轮轮增长，直到过线

会话先有固定占用

系统提示、项目根指令、自动记忆、工具名称和 skill 描述会在用户输入前后进入上下文。不同内容的加载时机并不完全相同。O

每轮继续追加

用户消息、Claude 回复、文件读取和工具结果进入会话历史。下一次请求会再次带上完整上下文。O

旧前缀通常命中缓存

正常追加不会改动请求开头，服务端可读已有前缀，只处理新尾部。缓存过期或前缀变动时会重新处理。O

接近上限先清工具输出

Claude Code 优先清理较旧的工具结果。空间仍不够，自动压缩才总结对话。O

摘要替换旧历史

程序另发一次总结请求。压缩后的下一轮沿用稳定层，并在较短摘要上建立新的会话缓存。O

装不下就停止

单个输入反复填满窗口时，自动压缩尝试数次后不再循环。界面会给出上下文过长或压缩失败等错误。O

03 / FLOW

缓存省重算，压缩省空间

A / CLIENT

Claude Code

把系统提示、项目上下文、会话历史与新消息排成一次请求。

B / PREFIX

稳定内容在前

系统层和项目层先放，变化更频繁的对话层跟在后面。

C / CACHE

服务端精确匹配

从开头逐字匹配。中间一处变化会让后续部分重新计算。

D / COMPACT

新摘要另起前缀

旧会话层被替换，后续请求只为较短摘要重建缓存。

压缩会打断旧会话层的缓存连续性。生成摘要的那次请求在缓存仍热时可以沿用旧前缀；完成压缩后，下一轮面对的是新的短历史。系统提示仍可复用，项目上下文从磁盘重载后能否命中，取决于它是否变化。O
04 / LIMITS

三个停止位置

模型窗口已超

对话和附件超过模型上下文窗口，请求会以 Prompt is too long 一类错误停止。用户可压缩、清空或退回几条消息。O

摘要也无处落脚

窗口已经太满时，压缩请求自己也可能放不下摘要。官方建议退回数条消息后再压缩，仍不够就清空。O

原始请求超过 32MB

这是 token 窗口之外的请求体限制。消息本身过大时，压缩可能也救不了。O

权限与费用

压缩会发模型请求，依赖当前认证、提供商和模型可用性。官方没有为它描述工具审批步骤。底层认证或模型错误仍会让自动压缩失败。O/I

05 / EXPERIMENT

这次只做只读核对

没有启动 Claude 会话，也没有消耗模型额度。页面状态因此保持 documented。

L 本机 claude --version 返回 2.1.247；可执行文件哈希与指定基线一致。

L 本机帮助列出 --autocompact，接受 auto 或 100k 到 1M token。

L 定向静态匹配只确认自动压缩、压缩禁用和缓存 TTL 的公开配置名存在，没有读取任何私人配置值。

O 官方索引仍有 202 个入口，SHA-256 与指定基线一致。

R 缺失。触发真实压缩需要调用模型，超出本轮免费只读实验范围。

06 / IMPLEMENTATION

用户能控制哪些地方

/context查看当前窗口由系统提示、工具、记忆文件和消息等内容占了多少。O
/compact [focus]手动把历史换成摘要，并告诉 Claude 重点保留什么。新会话没有足够消息时不会压缩。O
/clear从空上下文继续。原会话仍保存，可由会话机制恢复。O
--autocompact本机 2.1.247 帮助接受 auto 或 100k 到 1M token。它证明入口存在，不证明某次配置已生效。L
压缩以后哪些内容会回来

项目根 CLAUDE.md、非路径限定规则、自动记忆和计划会重新注入。Claude Code 还会重读最近修改的文件，最多五个。已调用的 skill 正文也会重注入，但每个最多 5,000 token，合计最多 25,000 token。路径规则和子目录 CLAUDE.md 会随匹配文件再次读取。O

缓存能热多久

命中会刷新闲置计时。Claude 订阅且仍在套餐用量内时，主会话默认请求一小时 TTL；API key、usage credits 或云提供商路径通常为五分钟。2.1.242 起才有两项公开 TTL 设置。O

与其他页怎样分工

CTX-02 负责会话身份、恢复和分叉，CTX-04 负责自动记忆，CTX-03 负责 CLAUDE.md 与 Rules 加载，CORE-02 负责单次工具结果整形。本页只追踪窗口从增长到清理、压缩、改写缓存前缀和失败的链条。

07 / UNKNOWNS

官方没有给出全部细节

实际触发点

不同模型、提供商与配置下的百分比和预留 token 数，本轮没有 R。

旧输出怎样挑

选择算法、清理粒度和必须保留的工具结果没有公开。

尝试几次才停

官方只写自动压缩尝试数次后停止，没有给出精确次数与退避办法。

摘要会漏多少

长会话里哪些细节最容易消失，focus 指令能改善多少，需要受控真实实验。

安全复现办法

先核对版本、帮助和官方索引哈希。若另行批准模型用量，可在空白临时目录启动全新会话，只使用可删除的合成文本，先看上下文占用，再手动压缩并比较前后分类。大输入实验应设置预算和更低的安全窗口，第一次出现压缩或错误就停。
