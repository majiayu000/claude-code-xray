CORE-01 documented Claude Code 2.1.247
Agent loop signal map

一句任务，怎样变成一轮行动

模型负责选择下一步，Claude Code 的 harness 负责把选择变成可控的动作。模型若请求工具，harness 先过权限门，再执行工具，把结果送回模型。模型拿到新信息后继续选择。它给出自然回复时，Stop hook 仍可把原因送回去，要求继续；其余出口还包括截断、拒绝、用户中断和运行错误。

工具执行层在本页只露出接口。命令怎样起进程、输出怎样裁剪、失败怎样细分，都留给 CORE-02。当前页没有安全的真实模型实验，因此状态是 documented。

01 / ROLES

先认清三个角色

O

用户给目标，也握着中断权

用户提交任务，可以在权限提示中批准或拒绝，也能按 Esc 终止当前轮次。排队消息与即时中断属于 UI-01，本页只记录它们怎样进入或切断循环。

O

模型看上下文并选择

模型读到当前对话、已加载的指令、文件内容和工具结果。它可以回复文字，也可以发出结构化工具请求。官方文档中的“Claude 决定”指这一层。

OL

harness 管理现实世界

Claude Code 准备上下文和可用工具，检查权限，执行本地或远端动作，再把结果放回下一次模型请求。2.1.247 的帮助允许收窄工具集并选择权限模式。

02 / SEQUENCE

一轮按什么顺序走

公开契约拼出的最短时序O 为主，私有序列化保持未知
STEP 01 · O用户提交任务目标和当前会话上下文成为这一轮的输入。
STEP 02 · Oharness 准备上下文工具定义、指令和前序结果占用同一个上下文窗口。
STEP 03 · O模型给出响应响应可以含文字，也可以含一个或多个工具调用块。
STEP 04 · O检查停止原因工具调用表示要把控制权交给执行方，尚未形成最终回复。
STEP 05 · O权限门裁决deny、ask、allow 与 PreToolUse hook 决定调用能否开始。
STEP 06 · O工具运行并产出结果成功与错误都能形成结果，调用 ID 把结果接回原请求。
STEP 07 · O结果送回模型模型用新信息再选一步，循环回到响应阶段。
继续通道　tool_use 加对应的 tool_result，随后再次请求模型。
停止通道　自然回复还要经过 Stop hook；截断、拒绝、用户中断和 API 错误各走自己的分支。

“收集、行动、验证”会互相穿插。一次修复可能读文件、改代码、跑测试，再根据失败结果重新读取。页面里的七格是通信顺序，不能读成模型固定采用七步思考法。

03 / FLOW

信息在哪两边来回

O

模型这一边

  • 收到系统指令、会话内容和 harness 暴露的工具说明
  • 输出文字或带 ID、名称和参数的工具调用
  • 收到结果后继续原任务，失败结果也能参与下一步判断
⇄
O

harness 这一边

  • 登记可用工具并套用权限、hook 和执行环境
  • 把结构化调用交给对应工具
  • 整形结果并按调用 ID 回填，随后检查新的停止原因

Claude Code 官方说明会把消息、工具调用和结果写入本地明文 JSONL，以便恢复和分叉。本轮没有读取这些文件。它们的持久化细节属于 CTX-02，工具结果怎样裁剪属于 CORE-02。

O

循环开始前要先通过认证

个人用户可以用 Claude.ai 的 Pro 或 Max 账号登录。团队还可以使用 Team、Enterprise、Claude Console、云提供商或组织自建 gateway。设置了 ANTHROPIC_API_KEY 时，Claude Code 会跳过浏览器登录并要求确认这把 key。

O

采用哪种认证，也决定用量记在哪里

Pro 和 Max 的常规用量计入订阅额度，超出后可另开 usage credits。Team 与 Enterprise 使用成员席位额度。Claude Console 和云提供商按 token 向组织计费。一次循环可能多次请求模型，工具结果回流和上下文都会继续占用 token。

05 / LOCAL

本轮只做静态核对

VERSION · L2.1.247来自本机只读版本输出
BINARY · L哈希与基线一致指定安装文件共 233,073,008 bytes
RUNTIME · R没有运行样本未启动交互或 print 会话

实际执行过的安全命令

claude --version、claude --help 与指定安装文件的 SHA-256 核对。帮助里能看到工具集、权限模式、安全模式、最小模式和流式输入输出开关。

这些命令没有证明运行路径

帮助输出不能证明某次工具调用怎样排队，也不能证明权限弹窗、截断和错误重试的真实表现。本轮没有读取私人会话记录，旧页引用过的会话结构观察已经撤下。

怎样复现同一组只读核对

运行版本和帮助命令，再对指定 2.1.247 安装文件执行 SHA-256。随后逐页核对核心循环、工具调用、停止原因、权限和 hooks。不要启动模型会话，也不要读取本地会话 JSONL。

06 / VERSION

2.1.247 改了哪条循环边界

OL

错误输出不会再轻易挤死会话

官方 changelog 记载，这一版修复了 hook 或后台 Agent 打印数 MB 错误输出后，可能把对话挤到提示过长并卡住的故障。本机版本与二进制哈希都和基线一致。

I

私有调度仍然看不见

公开资料足以证明角色和工具往返契约，仍不足以还原 Claude Code 内部请求的逐字段形状、缓存分块、并行工具队列和重试退避。本页不会用 API 教程替这些未知项作保证。

07 / UNKNOWNS

公开证据还留着五个洞

  1. 2.1.247 发给模型的私有系统块、工具定义和 prompt cache 边界怎样精确序列化。
  2. Claude Code 对每一种 API stop reason 采用怎样的自动续跑、重试、降级和界面提示。
  3. 一个响应含有多个工具调用时，本地执行队列与结果回填采用什么精确顺序。
  4. 普通工具错误按类别重试多少次，是否退避，以及模型和 harness 各负责哪一段。
  5. 本地 CLI、Cloud、Remote Control、Desktop 与 IDE 在中断传播和持久化时序上有哪些差异。
