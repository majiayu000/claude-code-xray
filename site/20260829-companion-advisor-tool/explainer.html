01 / TERMS

四个角色先分开

用户

用户先选择 advisor，随后可以在 prompt 里要求咨询。选择只让工具具备资格，不能保证每回合调用。O

主模型

官方 API 称它 executor。它决定调用时机，拿回建议以后继续生成，也会用文件与运行结果核对建议。O

Advisor

它是 Anthropic 服务端的一次独立推理。它能读完整对话，却没有工具，也不会直接改文件或运行命令。O

Claude Code

它负责配置资格门和界面状态。Advisor 没有可写进权限规则或 hook matcher 的本地工具名。O

本页的独有状态转换很窄。主模型从执行进入咨询等待，拿到建议或 advisor 子调用错误后重新掌握生成控制权。模型选择留给 CTX-05，高速路由与费率回退见 CTX-06 Fast Mode。

02 / SEQUENCE

一次咨询怎样走完

01

用户先让 advisor 可用

交互会话可用 /advisor，持久设置可用 advisorModel，单次启动还可用隐藏的 --advisor。模型组合、组织 allowlist 和服务提供商会先过资格检查。O

02

主模型遇到关键决策点

常见时机包括方案确定前、同一错误反复出现时和宣布完成前。这些是模型倾向，没有固定触发规则。用户能提出调用要求，仍没有强制次数的设置。O

03

主模型发出空调用

server_tool_use 的 input 为空。主模型只发出咨询信号，不能在 input 里另塞一个问题。O

04

服务端组装完整上下文

Advisor 收到 system prompt、工具定义、此前轮次、工具结果和本轮已经生成的文字。它按自己的系统提示单独推理。O

05

建议回到主模型

结果进入 advisor_tool_result。主模型继续生成，通常采用建议；具体主张若和文件或真实运行冲突，它会说明冲突并调整。O

03 / FLOW

上下文整份过去，控制权原路回来

USER

用户要求

任务、约束与本轮提示进入主对话。用户可以要求在某个节点咨询。

EXECUTOR

主模型

空 input 发出调用。完整对话不会由主模型手工摘录，Anthropic 服务端负责组装。

ADVISOR

只读顾问

单独推理后返回建议。没有工具，没有文件写入，也没有自己的 context management。

用户输入 → 主模型判断时机 → 服务端附上完整 transcript → advisor 返回建议 → 主模型继续

看得见的状态

咨询期间，CLI 显示 Advising 和模型名。结束后显示 Reviewed 或 Declined。有可读内容时，按 Ctrl+O 展开。O

看不见的思考

Advisor 的 thinking blocks 在结果返回前被丢弃。主模型收到建议文本或服务端可处理的加密结果，不会接到 advisor 的内部思考。O

04 / LIMITS

失败发生在哪一层，决定还能不能继续

触发点返回或状态主模型随后怎样走停止边界
Advisor 子推理限流或过载工具结果带 too_many_requests 或 overloaded主请求继续，没有本次建议不能把它误读成主模型 HTTP 429
完整 transcript 太长或咨询超时返回 prompt_too_long 或 execution_time_exceeded主模型沿现有证据继续官方没有承诺自动压缩后重试 advisor
Advisor 模型不存在或临时不可用返回 model_not_found 或 unavailable主请求本身不失败用户不能从错误码推断恢复时间
组合不受支持或组织不允许Advisor 不附加；部分交互式 --advisor 启动直接报错退出已有会话通常无 advisor 工作，错误启动没有主循环启动退出时到此停止
订阅计划的用量边界Advisor 用量计入计划用量限制能否继续取决于主请求还能否获批；本轮没有运行证据不能把计划限制写成 advisor 子调用错误
主模型自身收到 HTTP 429整个 Messages 请求失败不能套用 advisor 工具错误的继续规则进入 Claude Code 的通用限流流程

OI“没有 advisor 也继续”有明确前提。API 只保证 advisor 子调用错误不会拖垮主请求。主模型限流和错误启动都落在这条保证之外；订阅计划只公开了 advisor 用量会计入限制，本页不再推断触发限制后的界面与恢复时机。

真实 advisor 咨询会启动付费请求，还会让服务端读取完整对话。研究边界禁止这样做，所以没有 R，页面保持 documented。

本轮只读了相邻主页面的唯一允许证据文件。它把 Advisor 明确留给独立 companion，并把 Fast Mode 保持为另一条路由状态机。L

06 / IMPLEMENTATION

配置、请求、结果各守一层

配置层

advisorModel 保存默认选择。/advisor off 清除它；禁用环境变量会让命令消失，并忽略已保存选择。O

请求层

这是 Anthropic API 执行的 server tool。Claude Code 权限规则与 hooks 没有对应 matcher，第三方云提供商也不承诺可用。O

结果层

成功结果可能是明文，也可能是加密块。后续轮次保留完整 result，服务端才能把加密建议重新提供给主模型。O

缓存边界

中途开关 advisor 不会让主模型的 prompt cache 失效，返回建议会进入后续 transcript。Claude Code 产品页写明 advisor 每次重读完整对话，没有跨调用复用。底层 API 后来提供可选缓存参数，本页没有证据证明 2.1.247 会启用它。OI

费用边界

每次咨询都增加 advisor 模型的输入与输出用量。订阅账户计入套餐池，API 账户按所选 advisor 模型费率结算。Advisor 选择生效以后才可能产生这部分用量。O

登录与账户资格

Claude Code 首次启动要完成登录或批准 API key。Advisor 随后还要求走 Anthropic API，并归属订阅账户或 API 计费账户。Bedrock、Google Cloud 与 Microsoft Foundry 的认证能用于 Claude Code，却不支持 advisor。未登录时命令是否可见，官方没有说明。O

产品 surface

本页确认的是官方写明的交互 CLI、设置与启动参数。后台会话只确认了错误参数下会无 advisor 启动。VS Code、JetBrains、Desktop、Remote Control 和 headless 会话都没有 advisor 专属的一手说明，本页不推断它们支持或不支持。OI

官方 changelog 在 2.1.117 记录过 Advisor Tool 的实验标签、说明链接、启动通知和错误恢复修复。2.1.247 的发布项没有单列 advisor 行为变化。这个版本边界只能说明公开记录，不能代替 2.1.247 的真实运行。O

07 / UNKNOWNS

账户和各端也还有缺口

未登录时命令怎样显示

Claude Code 首次使用会要求登录或批准 API key，失效且无法刷新的登录会让请求失败。官方没有说明重新认证以前是否隐藏 /advisor，也没有给出 advisor 专属报错。

哪些产品 surface 已经接入 advisor

交互 CLI、设置和启动参数有官方说明。错误的后台启动有一条降级规则。VS Code、JetBrains、Desktop、Remote Control、headless 会话以及后台会话的成功咨询路径均未得到 advisor 专属文档或本轮运行证据。

主模型到底按什么规则决定调用

官方只给了方案确定前、错误反复时和完成检查前这些倾向。2.1.247 的隐藏提示与启发式没有公开，不能写成固定时序。

Claude Code 给底层调用加了哪些上限

API 支持每请求调用上限和 advisor 输出上限。产品页没有公开 2.1.247 是否设置这些参数，也没有公开具体值。

加密建议在终端里怎样展开

API 文档说明部分 advisor 返回加密结果，Claude Code 文档只承诺有可读建议时可用 Ctrl+O 查看。本轮没有付费会话，无法核对逐字显示。

本机会话怎样保存 advisor 结果

隐私边界禁止读取私人 transcript、调试目录和会话文件。本页只确认官方要求后续轮次保留结果，没有猜测本机文件名或匿名化结构。
