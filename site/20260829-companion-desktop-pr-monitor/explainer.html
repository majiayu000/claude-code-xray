当前状态 documented Claude Code 2.1.247 伴页

PR 开出以后
会话继续看守

打开 GitHub PR 后，Desktop 会在会话里显示 CI 状态条，用本机 gh 轮询 checks，并把失败送回界面。用户可以让 Claude 自动修失败项，也可以等全部 checks 通过后 squash 合并。CI 结束会发桌面通知；PR 合并或关闭后，本地且已经停下的会话还能自动归档。O

官方没有说明 Desktop 怎样判定 PR 属于当前会话，也没有公布关联键、轮询间隔或 review 展示。本页把 CLI 已知行为单独标出，不把它挪成 Desktop 运行事实。没有真实登录实验，状态保持 documented。

重要结论旁边的字母说明它能走到哪里。本页有官方契约和本机只读观察，没有已登录的真实 PR 路径。

Anthropic 官方文档与官方 changelog，说明产品承诺和版本变化。

L

当前 shell 能找到 gh，却不能调用 claude，安装包元数据也被系统拦住。

本页没有。没有登录 GitHub，也没有创建、修改或合并远端 PR。

SEQUENCE

一条 PR 从出现到离开会话

下面只把官方明确承诺的 Desktop 路径串起来。PR 怎样在内部与 session 绑定，仍然留白。

01O＋I

打开 PR

当前任务开出 GitHub PR。官方只承诺打开 PR 后出现状态条，没有公开 Desktop 怎样判定它属于当前会话，也没有说明保存哪一个关联键。

02O

状态条出现

会话开始显示 CI 状态。PR monitor 依赖本机已经安装并认证的 gh。

03O

轮询 checks

Desktop 让 GitHub CLI 查询 check 结果。pending 继续等待，failure 被送到会话。

04O

失败后再改

Auto-fix 开启时，Claude 读取失败输出并迭代。开关关闭时，官方没有承诺自动修改。

05O

通过后合并

Auto-merge 开启且所有 checks 通过以后，Desktop 尝试 squash 合并。仓库必须先允许 GitHub auto-merge。

06O

通知与归档

CI 结束时发送桌面通知。PR 合并或关闭后，开启 auto-archive 的本地已结束会话才会自动归档。

LIMITS

五道门决定监控能走多远

Code tab 先检查账号与订阅。状态条还要能访问 GitHub，自动修复与自动合并也各有条件。远端失效仍没有一条已验证的恢复流程。

Code access使用 Desktop Code tab 必须登录 Anthropic 账号，并持有有效的 Pro、Max、Team 或 Enterprise 订阅。界面要求升级或在线登录时，要先完成对应步骤。O
GitHub CLIgh 必须安装并认证。缺安装时，Desktop 在第一次尝试创建 PR 时提示安装。O
Auto-fix用户要先开开关。关闭时停在失败展示，后续由用户处理。O
Auto-merge用户开开关，checks 全部通过，仓库也允许 GitHub auto-merge，三项缺一项都会停住。O
Auto-archive只处理 local 且已经停止运行的会话。PR merge 或 close 提供终态，设置仍要事先开启。O

已知停止点与未知断点

  • Anthropic 账号未登录或缺少有效订阅时，Code tab 不能进入这条路径。
  • 没有 PR 时，官方没有承诺 CI 状态条出现。
  • gh 缺失或未认证时，监控前置条件不成立。
  • Auto-fix 关闭时，失败不会自动触发修复。
  • 仓库没开 auto-merge 时，Desktop 不能替用户合并。
  • 会话仍在运行时，merge 或 close 不会触发自动归档。
  • 认证过期、仓库改名、PR 转移或权限撤回时怎样提示，官方没有说明。I

官方 changelog 公开了 CLI 的几个节点。它们帮助界定能力出现的时间，不能单独证明 Desktop 会发现任意既有 PR，也不能证明两端使用同一份缓存。

CLI footer 加入 PR review 状态，包含 approved、changes requested、pending 与 draft。O

2.1.27

加入 --from-pr，会话内成功执行 gh pr create 后会自动关联 PR。O

2.1.247

CLI footer 在终端重新聚焦时，若上次检查还不到一分钟，会跳过重复检查。O

Desktop

打开 PR 后出现 CI 状态条，Auto-fix、Auto-merge、通知与归档也有公开契约。PR 归属判定、关联主键、缓存位置与轮询周期没有公开。O＋I

本页停在主页面的远端一侧

UI-05 主页面讲 session、worktree、diff、terminal 与文件面板。这里从 PR 已存在开始，只追踪远端 checks 怎样回到那份会话。commit、push 与创建 PR 留给 PAR-04，Code Review 与 Ultrareview 留给 PAR-05，会话身份与恢复留给 CTX-02。

UNKNOWNS

还不能替 Desktop 填上的空白

这些问题会改变实验步骤、权限判断与故障恢复，暂时保留比补一个内部实现更可靠。

会话到底怎样绑定一个 PR

CLI changelog 说明 gh pr create 成功后自动关联，也提供 --from-pr。Desktop 文档没有公开它用 branch、URL、number 还是 session metadata。

checks 多久刷新一次

Desktop 文档只写轮询。前台、后台、失焦、网络失败与长期 pending 时的间隔、退避和停止条件都没有公布。

review 决策会不会进 Desktop

CLI 明确显示四种 review 状态。Desktop 只明确 CI checks 状态条。本页没有 R，也没有静态实现证据把两者接成同一份展示。

远端对象失效以后怎样恢复

PR merge 或 close 的归档条件已经公开。认证过期、仓库删除、改名、PR 转移或权限撤回时，错误提示、重试上限和重新关联办法仍未知。

Auto-fix 会试到什么时候

官方写明会读取失败输出并迭代，没有给最大轮数、费用边界、权限等待、重复失败或新失败出现后的停止规则。

通知会不会漏掉 rerun

官方承诺 CI 完成时发桌面通知。多次 rerun 怎样合并通知，系统拒绝通知权限以后有没有会话内补偿，资料没有说明。
