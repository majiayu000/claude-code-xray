COMP-SAFE-BARE · documented · Claude Code 2.1.247

把本机习惯留在门外

脚本加上 --bare -p 后，Claude Code 不再自动找 hooks、LSP、plugins、MCP、Skills、commands、agents、memory 和 CLAUDE.md。它只留下 Bash、读文件、改文件，再接受命令行明示的上下文、模型和权限。直连 Anthropic 时只读 Console API key 或显式 settings 里的 apiKeyHelper，用量记入 Console 账户，不由 Claude 订阅覆盖。

01 / TERMS

先分清自动发现和显式输入

我对照了官方脚本指南、CLI 参考和 2.1.81 发布记录。Bare 删掉的是启动时四处寻找配置与扩展的过程，脚本自己写出的参数仍有入口。

AUTO DISCOVERY

默认跳过

hooks、LSP、skills、commands、agents、plugins、MCP、auto memory 与 CLAUDE.md 不参加自动发现。官方 flag 还会设置 CLAUDE_CODE_SIMPLE。脚本因此少受某台机器已有配置的影响，启动时也少做一轮扩展扫描。

EXPLICIT INPUT

按参数带回

system prompt additions、settings、MCP、agents 与 plugin 都有显式 flag。额外目录中的 skills 是一个窄例外。凡是脚本确实依赖的内容，都应跟着调用参数或受控文件进入，不能再依赖操作者碰巧装过什么。

BASE TOOLSET

三类工具

默认工具集合只有 Bash、文件读取和文件编辑。--tools 控制内置工具可见性，--allowedTools 只预先批准调用，不会把未列出的工具隐藏。最小工具集合也没有替代文件系统边界。

02 / SEQUENCE

一次 Bare 调用怎样走完

下面只画公开可观察的顺序。内部函数先后没有官方调用图，不能拿推测补齐。

00
SHELL

脚本传入 Bare 与 prompt

常见入口是 claude --bare -p "…"。无效参数在运行开始前写到 stderr，进程以非零状态结束。O

01
STARTUP

跳过惯用扩展面

进程不自动读取用户与项目的 hooks、skills、plugins、MCP、memory 和 CLAUDE.md，也跳过 LSP 与 plugin sync。O

02
FLAGS

只装入脚本点名的东西

模型、system prompt、settings、MCP、agents、plugin 与权限可以通过对应 flag 明示。--add-dir 指向的目录会贡献 skills，不会贡献 commands 和 agents。O

03
AUTH

先过认证门

直连 Anthropic API 时，环境中的 API key 或显式 settings 里的 apiKeyHelper 必须提供凭据。OAuth、系统钥匙串和长期 OAuth token 都不会被读取。云提供商凭据走原有路径。O

04
AGENT LOOP

模型在三类工具内工作

显式 --model 决定当前会话模型。每次 Bash、读取或编辑调用仍由 permission mode 与 allow、ask、deny 规则判断。ask 属于权限规则层，没有独立的 CLI flag。O

05
EXIT

脚本按退出状态分支

成功返回 0，失败返回非零。缺少认证这类运行内失败会作为结果出现在 stdout。O

03 / FLOW

文件流被截断，flag 流继续

同一个功能面会因来源不同得到不同结果。页面把来源写出来，免得把“跳过自动发现”误读成“功能彻底删除”。

FILESYSTEM
自动来源

惯用 hooks、skills、commands、agents、plugins、MCP、memory 与 CLAUDE.md 被跳过。

结果

同一脚本不会因某台机器恰好装了扩展而自动改变。

FLAGS
显式来源

settings、MCP JSON、agents JSON、plugin 路径、system prompt 和模型参数进入本次调用。

结果

脚本作者重新承担依赖清单与可复现性。

AUTH
直连 Anthropic

API key 或 apiKeyHelper。

云提供商

Bedrock、Google Cloud Agent Platform 与 Foundry 继续读各自凭据。

TOOLS
可见性

Bare 默认只给 Bash、文件读取和文件编辑；CLI 用 --tools 控制内置工具可见性。

执行门

--allowedTools 只预先批准，--disallowedTools 可移除或阻止；ask 来自权限规则，未决调用交给 permission mode。

04 / LIMITS

三个门会让脚本停下来

Bare 只缩小加载面。认证、权限和进程退出仍各自决定脚本能不能继续。

AUTH GATE

凭据与账单分开算

只有订阅登录或钥匙串时，Bare 直连 Anthropic API 会缺少可用认证。Console API key 产生的 API 用量记入对应 Console 账户，不包含在 Claude 订阅中。Bedrock、Google Cloud Agent Platform 与 Foundry 沿用各自云账户的凭据和计费边界。

PERMISSION GATE

工具没有获准

--allowedTools 负责预先批准，不能限制工具可见性。deny 先于 ask 和 allow；ask 是 settings 中的规则层，没有对应的独立 CLI flag。未决调用由 permission mode 处理。

PROCESS GATE

参数或运行失败

参数错误发生在启动前。认证或模型请求失败发生在运行内。脚本最终都应读退出码，不能只看有没有文本输出。标准输出里出现错误说明，也不代表进程成功完成了任务。

未知边界仍在。官方 Bare 段落没有给 managed settings 的逐字段封闭矩阵，也没有解释显式 plugin 内每类扩展怎样与三工具集合组合。

06 / CONTRACT

脚本把依赖写在调用点

最小调用只携带 prompt。需要文件读取、固定模型与结构化结果时，把这些选择都明示出来。

claude --bare -p "Summarize README.md" \
  --model sonnet \
  --allowedTools "Read" \
  --output-format json

这段调用能说明什么

Bare 负责不自动发现扩展。model 负责当前模型，allowedTools 只预先批准 Read，output-format 负责结果形状。若要限制可见工具，应另用 --tools；文件访问范围和 deny 规则仍由权限边界处理。

需要 MCP 时

用 --mcp-config 明示 JSON。需要排除其他 MCP 来源时，再结合 --strict-mcp-config。不要指望项目的 `.mcp.json` 自动进入 Bare。

需要 Skill 时

--add-dir 指定目录后，Bare 会读该目录的 `.claude/skills/`。同目录的 commands 与 agents 仍跳过。其余组合行为列在未知项。

07 / BOUNDARY

Bare、Safe、Clean 各有自己的问题

这张表只做入口选择。Safe 与 Clean 的完整恢复链在相邻主页面。

入口主要角色保留面停止位置
--bare -pCI、脚本、SDK 调用三类内置工具、显式 flags、受限认证与权限判断输出完成、参数失败、认证失败或非零退出
--safe-mode交互用户与诊断者认证、模型、完整内置工具、正常权限与 managed policy故障消失后转入定向检查，仍在则进入 Clean
Clean 配置比较交互用户与诊断者空用户配置、无项目配置，组织外部 policy 仍可能存在逐项恢复时第一次复现就停

08 / UNKNOWNS

还有几块不能写死

这些缺口会改变安全判断或复现结果，所以留在页面上。

2.1.247 的内部跳过顺序

官方公开了可观察清单，没有发布 LSP、hooks、plugins、MCP 与 skills 的精确调用先后。本轮也没有动态 trace。

Managed settings 的逐字段行为

Safe Mode 明确保留 managed policy。Bare 官方段落没有给同样的封闭矩阵，本页不把两者等同。

显式 plugin 的组合结果

官方允许用 plugin flag 把插件带入本次调用，却没有在 Bare 总览里逐项说明其中 skills、commands、agents、hooks、LSP 与 MCP 怎样组合。

冻结二进制的真实失败文本

本轮没有可调用的 2.1.247 文件，也没有模型请求。认证失败的具体 stdout 文本与 provider 差异仍待隔离实验。

Skills 例外的引入小版本

研究日文档写明 `--add-dir` 目录中的 skills 可以加载，changelog 没给这个例外的单独引入条目。
