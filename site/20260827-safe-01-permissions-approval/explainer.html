权限规则、权限模式与审批

一次工具调用，可能绕回来好几次

工具还没执行时，Claude Code 会先收集拦截意见，再核对拒绝、询问与允许规则，随后让当前权限模式接手。钩子要求询问时，Auto 分类器仍可能先拒绝。审批给出允许或换了输入，deny 与 ask 还要再查。允许只是候选结论，拒绝会截断当前路径，defer 则把调用留到 resume 后重进。

这张图研究的是待执行调用怎样取得权限结论。沙箱能否真正放行、工具执行后的失败分类、Plan Mode 的方案审批，各有相邻页面承接。

01 / TERMS

先认清六个参与者

用户给任务，Claude 形成工具名和参数。后面的决定来自 Claude Code 权限层、钩子、规则、模式、分类器或审批界面。模型的文字指令不会自己改掉权限规则。O

待执行调用

工具名、输入参数和工具调用标识已经形成，副作用还没有发生。

PreToolUse

每个适用调用执行前的拦截点。它能允许、拒绝、要求询问、暂存，或整体换掉输入。

权限规则

deny、ask、allow 按这个顺序匹配。更具体的 allow 也盖不过较宽的 deny。

权限模式

模式规定未被规则提前解决的调用怎样走。Manual、Auto、Plan、dontAsk 等模式各有基线。

PermissionRequest

调用即将进入审批或无界面自动拒绝时出现。钩子或 SDK 宿主可以代表用户答复。

PermissionDenied

Auto 分类器已经拒绝后出现。它能告诉模型可以重试，却不能撤回已经发生的拒绝。

02 / SEQUENCE

一轮仲裁怎样开始

下面按时间讲一次常见调用。它只是进入仲裁的顺序。任何改写、暂存恢复和规则更新都会让路径回到较早的检查点。O I

Claude 形成调用。调用带着工具名和输入来到执行前边界。裸工具名 deny 可能早已让 Claude 看不见该工具，因此这种调用根本不会形成。

PreToolUse 收集意见。多个钩子冲突时，deny 优先于 defer，defer 优先于 ask，allow 排在最后。allow 仍要接受 deny 和 ask 规则回查。ask 进入 Auto 后不能被静默批准，分类器仍可拒绝。

规则和模式接手。deny 先截断，ask 要求审批，权限模式处理尚未解决的调用。allow 规则随后可以预批，SDK 的 canUseTool 接住最后仍需决定的请求。ask 在 Auto 中还可能先走到分类器拒绝。

审批可能改写未来。一次 allow 可以附带新输入，也可以写入规则或切换会话模式。修改后的输入重新检查 deny 与 ask，新增规则从后续调用起改变答案。

终点不止一个。允许进入执行，普通拒绝把错误交回 Claude，interrupt 停止当前执行，Auto 拒绝触发 PermissionDenied，defer 退出进程并等待 resume。

04 / LIMITS

停下来以后，还会继续分叉

拒绝当前调用

钩子 deny、规则 deny 或审批 deny 都会让工具不执行。理由通常交给 Claude，它可能换一个办法继续。CLI 主会话中，用户直接选 No 且不附评论会停止当前 turn。O

拒绝并中断

PermissionRequest 或 SDK deny 带 interrupt 时会停止当前执行。普通 deny 的默认值为 false，因此两者不能混写。O

自动拒绝

dontAsk 会拒绝本来需要询问的调用。无提示界面也可能在 PermissionRequest 没有给出决定时自动拒绝。Auto 分类器拒绝另有 PermissionDenied 事件。O

暂存待续

defer 没有执行工具，也没有宣告永久拒绝。它本身没有超时或重试上限，会话文件仍受 cleanupPeriodDays 保留清理约束，默认三十天。O

允许执行

规则、模式和审批都没有留下阻断时，工具才进入执行层。权限允许仍不等于沙箱、网络和工具自身一定成功。O I

Auto 拒绝后的重试

PermissionDenied 的 retry: true 只给模型一条“可以再试”的消息。旧调用仍然被拒绝，模型需要另发调用，无 verdict 时重试提示还会被忽略。O

恢复时工具已经不在

resume 找不到原工具时，进程以 tool_deferred_unavailable 和 is_error: true 结束。这个分支发生在 hook 触发前，不会重进 PreToolUse。O

批量调用例外　defer 只接得住该 turn 中一个工具调用。若同时有多个调用，defer 会被忽略，调用回到普通权限路径。交互会话也会忽略 defer 并给出警告。O

Auto 的使用门槛　2.1.247 基线已高于内建 Auto 起始模式的版本门槛。官方条件表写的是 All plans，Auto 本身不限定付费套餐；Pro、Max 与 Team 只是会把它作为内建起始模式。Team 和 Enterprise 管理员可以用托管设置关闭它。Anthropic API 与 Claude Platform on AWS 支持 Opus 4.6 以上、Sonnet 4.6 以上和 Fable 5；Bedrock、Google Cloud Agent Platform、Microsoft Foundry 与已登录的 Claude apps gateway 只支持 Sonnet 5、Opus 4.7 以上和 Fable 5。后一类 gateway 明确要求登录，API Provider 走各自的凭据。任何一项不满足，原本选择 Auto 的会话会以 Manual 启动。O

输入和权限分别流向哪里

updatedInput 替换完整工具输入对象。PermissionRequest 产生的新输入回到 deny 与 ask 检查。updatedPermissions 可写入仅本会话的内存，也可写入 local、project 或 user settings；具体作用域合并留给 ADM-01。

本页没有展开的实现面

Hook 配置、匹配器和全部生命周期留给 EXT-03。Bash 命令解析、文件边界与网络沙箱留给 SAFE-02。执行以后产生的成功、工具错误与输出整形留给 CORE-02。

07 / UNKNOWNS

仍然缺的证据

  1. 2.1.247 二进制怎样编码多来源钩子、规则匹配与界面状态。本页没有对应版本的本机静态样本或官方源码。
  2. CLI 原生用户审批改写输入时，是否调用与 PermissionRequest.updatedInput 完全相同的内部回查路径。公开契约只明确写了 hook 与 SDK。
  3. 多个 PermissionRequest hook 同时给出冲突决定时，更细的合并与显示顺序。deny 不能被 allow 越过已经确定，其余没有在引用契约中写明。
  4. 满足公开可用条件以后，Auto 分类器实际看到哪些上下文字段，又会怎样解释一个具体调用。
  5. dontAsk、无界面自动拒绝和 Auto 分类器拒绝，在 CLI、IDE、Desktop 与云端的可见提示及后续重试差异。

获得单独授权后怎样复现

  1. 固定 2.1.247，在全新临时目录通过命令参数传入临时 settings。
  2. 用无害固定调用交叉测试 PreToolUse 的四种结果和 deny、ask、allow 规则。
  3. 让 PermissionRequest 把输入改成会匹配临时 deny 的另一条无害调用，确认回查阻止执行。
  4. 在 dontAsk 与可用的 Auto 中区分规则拒绝、自动拒绝和 PermissionDenied。
  5. 在单工具 -p 调用上先 defer，再 resume 并用 updatedInput 允许，确认 PreToolUse 重入；另断开提供原工具的临时 MCP server，确认恢复在 hook 前以 tool_deferred_unavailable 结束。
  6. 分别测试 deny 的 interrupt false 与 true，只记录匿名事件、裁决和是否执行。
