普通 renderer 把更新写进终端原生滚动区。Fullscreen 重启当前对话，在备用屏幕只绘制可见消息，输入框留在底部。Screen-reader 一旦开启，通常会优先改成带标签的线性文本并使用经典 renderer。主题最后决定界面颜色，终端应用自己的配色仍由终端掌管。

01 / TERMS

先认清四个角色

Fullscreen 说的是绘图表面。它与窗口是否最大化没有关系。

O

renderer

Claude Code 把会话界面画到终端的路径。本页只比较 classic、fullscreen 与 screen-reader 的呈现结果。

O

classic

经典 renderer 使用终端主屏与原生滚动区。终端自己的查找和 tmux copy mode 能处理已经写出的文本。

O

fullscreen

替代 renderer 使用备用屏幕缓冲区，只保留当前可见消息的渲染树，并在应用内处理滚动、选择与 transcript 浏览。

O

screen-reader

无障碍呈现状态会输出平直的线性文本，去掉界面框线和只靠颜色表达的信息，并给消息加可搜索标签。

02 / SEQUENCE

一次切换怎样发生

用户动作先触发可重启检查。无障碍状态与终端条件随后选出呈现路径。

用户请求 fullscreen

在普通交互会话中运行 /tui fullscreen。裸命令只报告当前 renderer，default 则请求回到经典路径。O

CLI 先检查重启能否保留限制

会话级启动参数或临时 deny、ask 规则若无法交给新进程，Claude Code 会解释原因并停止，不切换，也不保存这次选择。O

允许切换时重启当前对话

CLI 保存 tui 选择，带回屏幕上的对话、权限模式、effort、模型与官方列明的部分启动状态。曾经 rewind 的会话从当前屏幕状态继续。O

启动选择器处理覆盖条件

禁用备用屏幕、no-flicker 值、失败记录、终端环境、保存的 tui 与官方功能开关共同决定起始 renderer。Screen-reader 对普通会话有更高的呈现优先级。O

renderer 把帧写给终端

Classic 继续累积原生 scrollback。Fullscreen 把当前可见消息画到备用屏幕，输入框固定在底部；主题 token 决定颜色。O

退出、回切或失败构成停止

用户运行 default 可回切。Fullscreen 在同版本连续启动失败后会维持 classic，升级或再次明确请求 fullscreen 才会重试。O

04 / LIMITS

门、失败和例外

这条状态机很本地，仍然会被重启能力、终端兼容性和附着会话卡住。

O

重启门

/tui 需要用新进程重启同一对话。无法转交的 system prompt 替换、tools allowlist 或会话内临时规则会让它拒绝切换。停止点发生在保存选择之前。

O

失败回退

一次失败让下次启动先走 classic；同版本第二次失败会持续留在 classic。成功画出首帧并稳定十秒，或正常退出，才算启动成功。

O

无障碍例外

普通 screen-reader 会话忽略 tui 并输出滚动文本。附着后台会话仍进入备用屏幕，没有原生 scrollback；这是官方列出的已知限制。

O

终端边界

Fullscreen 仍是 research preview。iTerm2 的 tmux 集成模式与它不兼容，少见终端或特殊配置也可能出现错位、残影与滚动问题。

L 证据怎样取得

只读运行固定二进制的 version、help、shasum 和 file。Help 明确列出 ax-screen-reader，并把结果描述为平直文本与无装饰边框。公开 settings schema 还列出 tui、theme、prefersReducedMotion 与 axScreenReader。

这些结果能证明 2.1.247 带有入口和静态契约。它们无法证明备用屏幕已经启动，也无法代替 VoiceOver 或 NVDA 的真实播报。

R 本轮没有真实实验。交互式 TTY 可能读取现有认证、写用户设置或触发付费会话，超出本轮安全边界。

06 / VERSION

2.1.247 所在的位置

固定版本已经拥有三条呈现路径。官方资料对 screen-reader 的最早版本留下一个冲突。

2.1.110

官方 changelog 记录 /tui 命令与 tui 设置，允许在同一对话里切换 fullscreen。

2.1.118

命名自定义主题进入 /theme，插件也能提供 themes 目录。

2.1.181 / 208

Accessibility 页把最低版本写成 2.1.181，官方 changelog 又在 2.1.208 记录新增 screen-reader。当前资料无法确定最早公开可用点。

2.1.236

从这一版起，fullscreen 启动失败会回退到 classic。更早版本仍会继续尝试 fullscreen。

2.1.247

本页固定快照。版本与完整 SHA-256 已在本机核对，renderer 的真实运行仍未验证。

主题文件

官方规定每个自定义主题是 JSON，可继承 dark、light、daltonized 或 ANSI base，再覆盖颜色 token。无效 token 会被忽略。

07 / UNKNOWNS

还不能写死的地方

缺 R 的部分保持空白。页面不拿官方承诺代替这台机器的真实屏幕。

首次启动路径

当前终端究竟会命中默认表中的哪一行，还取决于安装时间、功能开关、环境和失败记录。

失败状态存放

官方公开了计数和清零行为，没有公开 2.1.247 把本机状态保存在哪个结构中。本轮也不读取私人配置。

真实听读

VoiceOver、NVDA 与不同终端能否稳定按标签、停顿和 bell 工作，需要隔离 TTY 与辅助技术实测。

版本冲突

2.1.181 与 2.1.208 两个官方口径怎样对应测试、发布或默认开放，现有一手资料没有解释。

主题对比度

自定义 token 在低色深终端和不同背景下的实际对比度，需要逐终端检查，JSON 合法不能保证看得清。

attached 体验

Screen-reader 用户附着后台会话时会进入备用屏幕。离开方式有官方说明，完整播报体验仍缺 R。
