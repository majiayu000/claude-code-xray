One package trip

一次安装要经过七个站点

O这条线从用户已经决定找插件开始，到组件进入指定 scope 的已启用集合结束。组件随后怎样执行，交给 EXT-01、EXT-03、EXT-04 与 EXT-06。

01 CATALOG

加入目录

注册 marketplace 的来源与名字。到这里仍然没有安装插件。

02 PICK

精确选包

用名字或带 marketplace 的限定名查找条目，确认来源与说明。

03 SCOPE

确定作用域

交互界面让人选 user、project 或 local。shell 默认写 user。

04 VERSION

解析版本

先看插件 manifest，再看目录条目；git、archive 和 command source 各有后备规则。

05 DEPS

求解依赖

同一依赖的范围取交集。跨目录依赖还要过根 marketplace 的许可。

06 CACHE

复制到缓存

普通 source 按目录、包名和版本落盘。旧版本可以与新版本短时并存。

07 ASSEMBLE

装配组件

读取固定组件入口，写下安装和启用状态。会话是否马上接入，要看安装摘要。

Gates and stops

安装会在哪三道门停下

TRUST GATE

来源受策略控制

O管理员可限制 marketplace。检查发生在网络或文件动作之前。插件与目录能以用户权限执行代码，来源不可信就不该加入。

SOLVER GATE

依赖必须同时成立

O缺依赖、版本无交集、没有匹配 tag、跨目录未获许可，都会让安装或启用失败。已有可用状态不会因一次 range conflict 被随手覆盖。

SESSION GATE

落盘不等于当前会话已接入

O会话内安装可能马上激活，也可能要求 reload。shell 命令只改会话外状态，现有会话要 reload，下一场会话则在启动时读取。

停用为何会失败

OR依赖仍被已启用插件需要时，Claude Code 拒绝单独停用，并给出正确顺序。先停依赖方，再停依赖；重新启用依赖方时，依赖会在同一 scope 一起启用。

卸载留下什么

OR指定 scope 的安装记录被撤掉。最后一个 scope 卸载时，持久数据默认会删，传 --keep-data 可保留。旧缓存版本先带 orphan 标记，后台稍后再清。

prune 会不会误删手装插件

O不会。它只处理因依赖自动安装、如今又没有安装方需要的插件。用户主动安装的插件不会进入 prune 集合。

Implementation edge

能确认到哪里，版本差异就写到哪里

部位2.1.247 可以确认的行为仍需留意的例外
版本键manifest version 优先，随后看 marketplace entry。git、archive 和无版本本地目录有各自后备值。command source 总按产物哈希处理，marketplace 的 version 不参与它的解析。
依赖求解范围取交集，git-backed source 选满足全部范围的最高标签。npm、archive 和 command 的约束不控制抓取版本，只在加载时检查。
缓存副本普通 marketplace 插件复制到版本目录。更新和卸载先标记旧目录。command link mode 原地使用。插件组件路径不能逃出根目录。
状态装配enable 会传递到依赖，disable 受反向依赖保护。高优先级 scope 或 managed policy 能阻止目标 scope 的更改。
卸载清理uninstall 撤掉 scope，prune 可带走无主自动依赖。持久数据可用 keep-data 保留，orphan 缓存另走后台清理。

复现边界

不要把配置根指向真实用户目录。不要读取真实插件列表，也不要登录或启动 Claude 会话。这个实验只需要本地文件与 CLI 管理命令，不调用模型，也不产生付费会话。
