先认四个角色

谁把活递给谁

这条链里有两把钥匙。模型凭据让 Claude Code 能推理，仓库凭据让作业能评论、建分支和 push。少一把，作业都走不到完整回写。

01 EVENT

仓库事件

评论、issue、PR、MR、push、schedule 或手动 dispatch。它只提供触发条件和上下文。

02 RUNNER

CI 作业

平台按 workflow 或 pipeline 配置启动隔离作业，注入允许的 secret 或 OIDC token。需要本地工作区时，job 另加 checkout 步骤。

03 EXECUTOR

Claude Code

在 runner 中接收 prompt、仓库内容和工具许可。普通自动化 prompt 没有被放行的工具时，不能直接用 shell 或仓库 API。O

04 WRITER

回写身份

GitHub App token、GITHUB_TOKEN、GitLab job token 或 project token 决定谁能写评论、commit 和 MR。

一次动作的时间顺序

从评论到待审变更

下面走的是常见路径。某些自动化 job 直接带 prompt，不需要等 @claude。GitLab 的提及触发还需要 webhook 或 listener 把评论变成 pipeline trigger。

1
用户或平台

产生 repo event

人发评论，PR 或 MR 更新，定时器到点，或工作流被手动调用。

状态从静止变为事件已发出
2
CI 调度器

匹配 workflow 与 job 条件

事件名、分支、rules 和 job 的 if 共同决定 runner 会不会启动。未匹配时，链在这里结束。

未匹配即不运行
3
Workflow steps

准备上下文与凭据

需要本地文件时，job checkout 当前 ref。模型 secret 可由 CI 直接注入，OIDC 或 federation 则换取 Anthropic、AWS、Google Cloud 或 Azure 的短期身份。仓库回写另用 App 或 CI token。O

各 step 的先后由 workflow 决定
4
Claude Action

在 Claude 启动前检查触发者

GitHub Action 默认拒绝无写权限的触发者和 bot。官方云提供商示例先生成 App token 并完成 OIDC 登录，随后才进入 Action 的角色检查。无权限请求仍可能留下云端审计记录并消耗 Actions minutes。O

门禁失败时不启动 Claude，run 仍已开始
5
Claude Code

读取上下文并执行

Action 或脚本把事件内容变成 prompt，传入允许的 CLI 参数与工具。Claude 可读 checkout 工作区，也可通过获准的仓库 API 读取提交和 issue，再按权限改文件或调用 API。

工具未放行则无法完成相应动作
6
仓库平台

接收回写

GitHub 可更新原评论、push 新分支与 commit，再给出 PR 创建入口。GitLab 可用 API 工具更新分支、评论或 MR。

结果进入待审状态
7
CI 与审阅者

收尾或停止

action 输出 success 或 failure，job 受 timeout、取消和并发规则约束。审阅者再决定是否建 PR、批准 MR 或合并。

自动执行结束，人类审批继续

五段传送带

事件正文、代码上下文和凭据走不同通道。secret 由 CI 注入，不能写进仓库。需要改工作区文件的 job 才依赖 checkout，纯日志或 API 读写路径可以跳过这一步。

模型身份

API key 与长期订阅 OAuth token 可作为 secret 注入。Anthropic federation 或云提供商 OIDC 用于换取短期身份。它们决定谁来付费、模型请求发到哪里。

仓库身份

GitHub App token、自动 GITHUB_TOKEN、GitLab job token 或 project token。它回答谁能把结果写回去。

权限门、失败与停止

链会断在哪里

大多数故障发生在 Claude 开始改代码之前。把事件、身份、工具和时间限制分开看，能更快找到停止位置。

触发门

事件或 job 条件不匹配，runner 不启动。GitHub 的 @claude 要作为完整触发词出现；GitLab 还要让 listener 确实调用 pipeline。

角色门

GitHub Action 默认要求 issue 或 PR 触发者有写权限，并拒绝 bot。这个检查保证 Claude 不会启动，却未必早于 workflow 里的 token 生成与云登录。公开仓库若要避免无权限请求消耗 runner，应在凭据步骤前另加权限检查。

凭据门

模型 secret 缺失、OIDC trust 条件不符、区域或模型不可用，Claude 不会得到有效推理身份。仓库 token 权限不足时，执行可以结束，回写仍会失败。

工具门

普通自动化 prompt 需要显式允许 shell 或仓库 API 工具。GitLab 少了 mcp__gitlab，job 无法评论或开 MR。

停止条件

  • job timeout 到期
  • workflow 被取消
  • 并发策略取消旧 run
  • 模型或工具返回失败
  • 文档支持的迭代上限用尽

开通与费用

安装与配置需要仓库 admin access。订阅 OAuth token 适用于 Pro、Max、Team 和 Enterprise。GitHub 托管 runner 会消耗 Actions minutes。API key 按 API tokens 计费，OAuth token 则占用对应的 Claude 订阅额度。O

二次 CI 例外

默认 GITHUB_TOKEN 写出的 commit 不会再触发 workflow。想让 Claude 的 push 接着跑 CI，需要 GitHub App 或自定义 App token，并让下游 workflow 监听相应事件。O

一手来源与复现

怎样把 documented 补成 verified

复核者需要隔离测试仓库的管理权限、可用的 API 预算或适用订阅、runner 分钟和写入授权。固定 action SHA，记录匿名化状态，不输出任何环境变量或 token。

最小复现路径
  1. 固定 action commit，并在 job 内只记录 Claude Code 版本。
  2. 让有写权限的人、无写权限的人和 bot 触发同一事件，记录 token 生成、云登录、Action 门禁和 Claude 启动的先后。
  3. 分别运行带 checkout 的文件修改任务，以及不 checkout 的 API 只读任务，记录两条路径的输出位置。
  4. 制造错误 secret、缺少 allowed tool 与短 timeout，核对停止位置和远端残留。
  5. 清理测试分支、评论、变量、token 与 App 安装。
