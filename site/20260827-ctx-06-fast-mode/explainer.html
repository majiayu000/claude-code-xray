Fast Mode 的路由、计费与回退

同一台 Opus，换一条快线

打开 Fast 后，Claude Code 把受支持的 Opus 请求送进高速推理配置，成功的 token 按 Fast 费率计。Fast 限流或 usage credits 耗尽时，请求会改走标准速度。组织禁用、模型白名单和网络预检失败会挡在入口处，高速线路根本不会启动。O

FAST · Opus 5 或 4.8最高约 2.5 倍输出速度
STANDARD · 同一模型限流冷却与额度耗尽时承接请求
FAST INPUT$10每百万 token
FAST OUTPUT$50每百万 token
01 / TERMS

先分清四个容易混在一起的量

模型

Fast 沿用同一组模型权重与能力。在 2.1.247 里，支持对象是 Opus 5 和 Opus 4.8。O

速度配置

官方 API 用高速 speed 选项与 beta header 选择这条线路。成功响应的 usage.speed 为 fast。O

偏好与会话状态

保存的 fastMode 偏好通常跨会话保留。逐会话 opt-in 能让新会话从关闭开始，同时保留那份偏好。OL

effort

effort 调整思考量，Fast 调整推理服务速度。两者可以同时使用，状态机留在 CTX-05。O

Advisor 有独立的工具开关、调用条件与缓存位置。本页不把它并入 Fast。

02 / SEQUENCE

一次开关动作，按这个顺序走

用户要求打开

交互终端运行 /fast，或在用户设置里写入 fastMode。非交互模式有更窄的启动条件。

Claude Code 先过资格门

它核对第一方线路、usage credits、组织开关、模型 allowlist 与 Fast 可用性检查。任何一扇门关闭，界面解释原因，请求留在标准速度。

必要时切到 Opus

当前模型不支持 Fast 时，打开动作会切到 Opus。2.1.247 的默认 Fast 目标是 Opus 5。界面显示 Fast mode ON，提示符旁出现 ↯。

下一次请求走高速配置

第一次在这段对话里打开 Fast 会重建缓存线路，整段上下文按 Fast 未缓存输入价重读。随后成功的 input 与 output token 分别按每百万 10 美元和 50 美元计。

回包确认实际速度

API 的 usage.speed 能区分 fast 与 standard。Claude Code 用 ↯ 和开关提示给用户看状态，不会把标准回退伪装成仍在高速运行。

账单从第一枚 Fast token 开始

订阅账户一旦发出 Fast 请求，就从第一枚 token 起扣 usage credits，即使套餐内普通用量尚未用完。Console 付费组织把这部分与其他 API 请求一起按 token 结算。Fast 的输入和输出单价分别是标准 Opus 的两倍，缓存与数据驻留倍率仍会另算。O

关闭只改变后续速度

手动关闭 Fast 会把后续请求送回标准速度，模型仍停在 Opus。已经建立的 Fast 缓存线路在同一段对话里继续保留，所以随后再次打开时，不会再次按未缓存输入价重读整段上下文。逐会话 opt-in 只改变新会话的初始开关，不会删除保存偏好。O

偏好与实际速度要分开看

开关显示的是用户偏好，usage.speed 才是服务器报告的单次实际速度。Fast 429 期间，↯ 变灰，当前请求落回标准线路，冷却结束后自动恢复。额度耗尽的处理不同，本次交互会话会关闭 Fast，保存偏好仍然保留。O

04 / LIMITS

四种失败，停在四个不同位置

触发条件状态怎样变用户看到什么随后怎样收费
组织未启用、模型不在 allowlistFast 不进入开启态组织禁用或模型不允许的提示请求继续按标准线路
预检无法直达 Anthropic可用性检查失败，Fast 不启动网络连接问题或当前不可用标准速度与标准费率
Fast 429 限流临时切到 standard，冷却后自动恢复↯ 变灰回退请求按标准费率
usage credits 耗尽交互会话关掉本次 Fast，保存偏好不变额度耗尽通知被拒请求改用标准速度重试
529 或普通服务故障公开契约没有确认同一条标准回退可能进入通用重试或错误流程没有成功响应就不能据此断言标准费率

OI官方 API 页把容量不足的 529 写成错误；Claude Code 页只明确承诺 Fast 限流与额度耗尽时走标准速度。服务故障回退仍是未知项，因果图没有把它画成既成事实。

05 / OBSERVATION

本轮只核静态证据，没有花一枚 token

版本与摘要

保留安装文件返回 Claude Code 2.1.247，SHA-256 与任务基线完全一致。L

帮助与安装包

帮助页展示模型、settings 与 print 模式的通用 fallback。安装包有限字符串核对命中 Fast 开关、逐会话 opt-in、speed 与额度耗尽提示。L

真实实验

未启动 Claude 会话，未改设置，也未制造 429 或 529。Fast 从第一枚 token 开始计费，本页因此保持 documented。R 缺失

研究时活动命令已升级到 2.1.248。本页所有本机结论仍以保留的 2.1.247 安装文件为准。

06 / IMPLEMENTATION

配置、请求与显示，各自保存一层状态

设置层

fastMode 保存用户偏好。fastModePerSessionOptIn 控制新会话是否必须重新打开。环境变量可以彻底禁用 Fast。OL

请求层

Fast API 形状包含 beta header 与 fast speed。响应 usage.speed 才是某次请求实际走了哪条线路的服务器证据。O

显示层

Fast mode ON 与 ↯ 表示开启。限流冷却时 ↯ 变灰。模型切换引起开关变化时，CLI 与 Remote Control 会重新同步状态。O

版本层

Fast 的默认模型几次变更。2.1.219 起是 Opus 5；Opus 4.7 已退出 Fast 支持，2.1.247 不应再沿用旧教程。O

07 / UNKNOWNS

还不能写死的地方

529 与普通 5xx 会不会切标准速度

平台 API 会把 Fast 容量不足列为 529 错误。Claude Code 文档的自动标准回退只覆盖 Fast 限流与 usage credits 耗尽。2.1.247 的精确重试矩阵没有公开。

可用性检查缓存怎样保存和失效

官方只说过去成功的检查结果可以缓存后继续使用，没有公开本机文件位置、TTL 或清除条件。本轮也没有读取私人配置来猜。

各层 Fast 限额是多少

官方说明 Fast 有独立限流头与 tier-specific limits，没有在 Claude Code 页给一组适用于所有套餐和组织的固定数字。

多端提示是否逐字一致

官方承诺 CLI、VS Code 与 Remote Control 同步开关状态。本轮没有真实多端会话，无法逐字符核对全部降级通知。
