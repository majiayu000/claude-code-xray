当前状态 documented Claude Code 2.1.247 基线 2026-08-27

一次任务共用一份工作目录

用户先选环境和项目。Desktop 随后把会话绑定到一份工作目录。Claude 与 editor 写文件，terminal 从这份目录执行命令，diff 把修改送回用户审阅。Git 项目里的并行会话各自进入 worktree，面板仍然围绕各自那份目录工作。O＋I

本页有官方契约与本机静态证据，没有启动付费会话的真实运行证据，所以状态保持 documented。

SEQUENCE

从选项目到新一轮 diff

官方流程里，项目与权限先于第一条消息。面板只是在任务推进时给同一批文件提供不同入口。

O

选环境与目录

Local 直接使用所选机器和文件。项目目录先划定这次会话能看见的代码现场，也会随会话保留下来。用户还要在发消息前选好模型和权限模式。

O

建立独立会话

每个 session 保存自己的聊天历史、项目目录与代码变化。侧栏可以同时放着多项任务，但切换会话也就切换了当前任务的上下文和文件现场。

O

给 Git 会话隔离

Git 项目里的并行会话进入各自的 worktree。每份 worktree 有自己的文件和分支，因此一项任务的未提交修改不会直接铺到另一项任务面前。

O

读写与运行

Claude 或 editor 把改动写到会话目录。terminal 从同一个工作目录启动，所以测试、脚本和 git status 面对的是这项任务正在变化的文件。

O

审阅再反馈

diff 按文件收集当前修改和增删统计。用户可以对具体行留言；提交留言以后，反馈回到同一会话，下一轮修改又形成一份新的 diff。

工作侧

session working directory

Local 会话看用户选中的本机目录；Git 并行会话则看分配给自己的 worktree。chat 负责交付任务，editor 直接保存磁盘文件，公开流程能确认它们最终都围绕会话目录推进任务。worktree 隔开文件和分支，却仍共享仓库的 Git 元数据及文档列明的项目资源。O＋I

这条回路同时保留对话和磁盘状态。聊天保存用户要求与反馈，目录保存文件变化，terminal 的测试会读取同一批文件，diff 再展示已经出现的修改。用户切到另一会话时，聊天历史、项目目录与代码变化也随之切换。若会话使用 worktree，切换后的面板面对另一份 checkout。“共用”只限同一会话，不表示不同会话会共用未提交修改。O＋I

LIMITS

先过访问门槛，再看任务停在哪里

Code tab 有账号与订阅要求。进入任务以后，权限、停止与冲突提示都在用户看得见的位置；失败也先落到目录、Git 与环境。

Access使用 Code tab 必须登录 Anthropic 账号，并持有 Pro、Max、Team 或 Enterprise 订阅。若界面要求升级，要先订阅；若要求在线登录，完成登录后重启应用。O
ManualClaude 准备编辑文件或运行命令时先等待用户接受。用户拒绝以后，目录保持原样，会话停在这里询问下一步。O
Stop点击停止会立即打断 Claude。若只在运行中发送纠正消息，当前动作不会立刻中止；Claude 会在动作完成后读取消息，再决定下一步。O
File warning文件打开后若磁盘内容又被 Claude、terminal 或其他程序改变，editor 会先警告，再让用户选择覆盖磁盘内容或放弃自己的编辑。O

常见断点

  • 项目文件夹已经不存在
  • 仓库需要 Git LFS，但机器没有安装
  • 文件权限阻止访问
  • Desktop 没拿到 shell 中的工具路径

O worktree 还是新 checkout，被忽略的依赖和环境文件也可能缺席。

EXPERIMENT

这次只核到程序在，不声称流程跑过

本轮没有打开新的 Code 会话。静态结果能钉住版本和入口，不能替代面板真实运行。

2.1.247 留存并匹配

显式运行留存二进制会返回 2.1.247 (Claude Code)。SHA-256 与固定基线一致。帮助文本列出 --worktree、resume、continue、permission mode 与 IDE 参数。L

本机应用包元数据显示版本 1.37937.3。它只能证明应用安装在机器上，无法证明登录、权限、面板或 worktree 已经执行。L

在线索引已经变化

2026-08-30 抓取的官方索引哈希与 2026-08-27 固定快照不同。本页保留旧基线，不把今天的索引倒写成当日证据。L

R 仍为空

真实路径要先登录 Anthropic 账号，并使用 Pro、Max、Team 或 Enterprise 订阅。本轮没有检查登录态或订阅状态，也没有启动可能消耗额度并读取私人项目的任务。普通 Git 实验无法证明 GUI 行为，所以没有拿它充当 Desktop 实验。

这些 surface 没有验证

Cloud、SSH 与 WSL 都没有 R。本页对项目会话和面板协作的说明只按官方资料记录，不能当成这三个环境已经在本机跑通。App Preview 与 PR monitor 仍只保留为相邻功能边界。

IMPLEMENTATION

隔离了文件，仍有共享部分

把 worktree 当成整机沙箱会误判权限和文件来源。它首先隔开 working directory 与 branch。

各自拥有

文件与分支

并行 session 的未提交修改留在自己的 worktree。该会话里的 terminal、editor 与 diff 都以这份任务现场为对象，另一会话则面对另一份目录。O＋I

仍然共享

仓库与项目资源

官方列出 Git 元数据、项目级插件，以及符合条件的已保存权限批准。O

可能缺席

忽略文件与依赖

新 checkout 不会自然带上主目录中的未跟踪文件和被忽略文件。.worktreeinclude 只能按规则复制匹配且被 Git 忽略的文件；依赖和工具仍可能需要初始化。O

版本钉住两层

Claude Code 引擎基线为 2.1.247。Desktop 外壳另有应用版本号。本页没有把两者混成一版。

离开本页的地方

worktree 的锁和清理交给 PAR-03，会话恢复交给 CTX-02，IDE 桥接交给 UI-04。App Preview 与 PR monitor 只保留边界。

UNKNOWNS

公开资料还没回答这些细节

未知项会改变复现实验的设计，先留着比猜一个内部实现更可靠。

pane 布局怎样和 session 持久绑定

官方只描述用户能拖动、缩放和重新打开 pane，没有公开内部数据结构。本轮也没有读取应用私有数据。

diff 的精确基线与刷新粒度

官方说明它展示文件修改和增删统计，没有说明每次比较 Git HEAD、index、Claude 单轮改动，还是另一份内部快照。

三方同时写一个文件时的顺序

file pane 能发现磁盘已变化并警告。Claude、editor 与 terminal 极短时间内同时写入时怎样排序，仍缺官方说明和 R。

非 Git 项目的并行隔离退路

官方明确说明 Git 项目自动使用 worktree，也说明 Windows 本地 Code tab 需要 Git。非 Git 目录能否获得等价隔离，现有资料没有讲完整。
