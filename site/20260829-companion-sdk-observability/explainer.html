两路记账

宿主从 SDK 消息流读取 usage 和每次 query 的估算成本。与此同时，Claude Code 子进程生成 metrics、events 与 traces，再用会话、提示和工具调用身份把记录送往 OpenTelemetry 收集端。导出失败默认只丢遥测，Agent 任务仍可继续。 O

成本字段用于开发观察和近似预算。权威账单仍要查 Usage and Cost API 或 Console。本页没有付费运行证据，状态保持 documented。

读图前的四个词

先把两路数据分开

消息流给宿主做逐次核算，OTel 给收集端做运行观察。两路都带身份字段，口径和停止位置各不相同。

01

step

一次模型请求与响应。一个 step 可因并行工具调用产生多条共享 message ID 的 assistant message。

02

result

普通 query 只发一个。流式输入每个用户 turn 都发一个，其中 usage 只算当前 turn 的主 Agent，成本和 modelUsage 则保留本次 call 的运行累计。

03

telemetry

CLI 产生的 metrics、log events 与 beta traces。SDK 传入配置，CLI 直接导出。

04

关联身份

session.id 串会话，prompt.id 串一次用户动作，tool_use_id 串起工具 span、decision 与 result。Hook span 还要另开详细 beta tracing。

图里每一步都保留证据身份。OTel exporter 的异步批次不能被画成与 result 同时完成。

01

宿主配置并发起 query

开发者在进程环境或本次调用的 env 中选择 exporter。TypeScript 的 env 会替换继承环境，Python 会覆盖到继承环境之上。 O

02

SDK 启动 CLI 子进程

SDK 通过本地 pipe 与 Claude Code 通信，并把 OTel 配置传给子进程。调用方已有活跃 span 时，SDK 可把 W3C trace context 一并传入。 O

03

会话与提示取得身份

SDK init 和最终 result 暴露 session ID。OTel 默认在记录上带 session.id，events 用 prompt.id 关联这次用户动作触发的 API 和工具事件。 O

04

每个 step 交出 usage

assistant message 带输入与缓存 token。逐步核算只取没有 parent_tool_use_id 的主 Agent message，再按 message ID 去重。此处的输出 token 仍是占位数。 O

05

工具进入 span 与 event

tool span 包住权限等待和执行。tool_use_id 同时出现在 span、tool_result 与 tool_decision；拒绝调用只有 decision。普通 beta traces 不含 Hook span，后者还要设置 ENABLE_BETA_TRACING_DETAILED 和 BETA_TRACING_ENDPOINT。 O

06

result 按输入模式结账

普通 query 的 total_cost_usd 和 modelUsage 是本次 call 合计，多轮 session 要由应用累加各次 call。流式输入每个 turn 的 usage 只含本 turn 主 Agent，total_cost_usd 和 modelUsage 是当前 call 的运行累计，不能逐条相加。所有模式下 usage 都排除子 Agent，另两项包含子 Agent。 O

07

CLI 按间隔导出批次

默认 metrics 每 60 秒发送一次，traces 与 logs 每 5 秒发送一次。干净退出会尝试 flush，短超时仍可能丢数据。 O

08

collector 失败时丢遥测

endpoint 不可达或拒绝数据，CLI 默认不把错误交给应用，Agent 继续运行。开启 OTel stderr 诊断后，宿主才能从回调读取 exporter 错误。 O

两条轨道在后端会合

权限、失败与停止

三处最容易算错

Agent 结果和 telemetry 送达各有状态。Agent 失败以前产生的消耗仍要入账。

usage 口径混用

  • 逐步主链先排除子 Agent 再按 ID 去重
  • 流式 turn usage 不能充当 call 累计
  • 整棵 Agent 树读取 modelUsage 或总成本

错误 result 仍有成本

  • 成功和错误 result 都要读取
  • 预算错误的 usage 可能少算越界响应
  • 进程 crash 可能把成本字段归零

遥测独立失败

  • 三个信号分别开关
  • SDK 不能使用 console exporter
  • 进程被杀会丢缓冲批次
内容权限门　默认 telemetry 只记录结构。prompt、工具参数、工具正文与原始 API body 都要显式开启。原始 body 含完整会话，只应进入经过批准的观测管道。 O

本机观察

停在只读边界

本页没有用空进程或文档示例冒充真实 Agent。状态因此是 documented。

NO R

没有启动付费调用

验证消息、成本和 OTLP 双路关联需要模型真正运行。任务禁止开启新的付费 Claude 会话，所以没有 collector 样本，也没有真实 exporter 故障注入。

实际做过的只读核对

  • CLI 入口不可用　本轮非登录 shell 中 claude 不在 PATH，版本与帮助命令返回 command not found。
  • 固定二进制未取得　常见安装根目录中的限定查找没有给出可核匹配，不能证明机器未安装。
  • 官方契约已互核　成本指南、SDK observability 与 Monitoring 对消息口径、span 层级和导出失败的描述能够互相对上。
  • 隐私边界保持　没有读取 transcript、真实 cwd、prompt、工具内容、token、cookie 或完整 UUID。

实现与版本

固定在 2.1.247

live 文档可以继续变化。这里把会改变观测结果的版本门槛单独列出。

费用口径

SDK 用构建时价格表计算 total cost，也可采用 modelPricing。价格变化、未知模型和客户端无法表达的账单规则都会造成偏差。这个字段适合开发观察，不适合终端计费。

信号开关

telemetry 总开关之外，每种信号还要选择 exporter。CLAUDE_CODE_ENHANCED_TELEMETRY_BETA 产生普通 beta traces。Hook span 还需要 ENABLE_BETA_TRACING_DETAILED 和 BETA_TRACING_ENDPOINT。SDK 下不能选 console exporter，因为 stdout 正在承载消息通道。

身份与付费边界

官方 Quickstart 的常规路径要求 Anthropic 账户，并从运行 Agent 的进程环境读取 ANTHROPIC_API_KEY。模型请求产生 API 用量，费用归认证所对应的账户或云提供商。本页的成本字段只是客户端估值。第三方产品没有得到 Anthropic 事先批准时，不得向自己的 Agent SDK 用户提供 claude.ai 登录或额度，应使用官方列出的 API key 或云提供商认证。 O

证据缺口

还欠一轮双路实测

下面几处会影响实际对账或故障判断，页面没有用肯定语气补齐。

两个 session 字段能否直接 join

官方分别把 SDK result 的 session ID 和 telemetry 的 session.id 解释为会话身份。本轮没有 2.1.247 的同次运行样本，无法证明两处值逐字相等。 I

主 Agent 与子 Agent 怎样逐项对账

官方提供 query_source、agent identity、modelUsage 和成本 metric。本轮没有混合模型与子 Agent 的双路样本，无法给出固定版本的完整核算矩阵。

exporter 到底重试多久

官方说明默认静默失败、批量发送和有界 flush，没有公布 2.1.247 的完整重试次数、退避和退出超时。

断线恢复会不会重复投递

collector 断开再恢复时的批次边界、丢失窗口和重复语义没有做真实故障注入。

固定本机二进制在哪里

任务给定版本和 SHA-256，本轮 shell 没有解析到 claude，也没有取得匹配安装文件，因此缺少正向 L 证据。

获准付费实验以后

  1. 固定捆绑 Claude Code 2.1.247 的 SDK 版本，启动只写临时目录的本地 collector。
  2. 分别运行普通 query 和含两个 turn 的流式输入，并让只读子 Agent 执行一个可辨认步骤。
  3. 排除带 parent tool use identity 的 message 后按 ID 核主链 step usage。普通 query 读取一次 result；流式输入保留最新运行累计，不把各 turn 的 total cost 相加。
  4. 先开普通 beta traces，确认没有 Hook span；再加详细 beta tracing 的开关和 endpoint，核对 Hook span 与 tool use identity。
  5. 把 OTLP endpoint 换成本机拒绝端口，确认 Agent result、stderr 诊断和 telemetry 丢失各自的状态。恢复后比较正常退出与提前终止，结束时删除全部临时数据。
