AGENT SDK / EXTERNAL SESSION STORAGE

把会话送到另一台 host

Claude 先在本地写 transcript，SDK 再把每批条目镜像到外部 store。另一台 host 恢复时先取回同一 session 的有序条目，随后才启动 Claude。工作目录里的文件不会跟着 transcript 回来。O

状态 documented COMP-SDK-SESSION-STORAGE 基线 2026-08-27 Claude Code 2.1.247
读图时先记住

外部 store 是 transcript 镜像。它不会替代本地首写，也不会保存文件 checkpoint。镜像可以缺段，host 必须把 mirror_error 当作持久化告警。

HOST A本地 JSONL 先落下
›
SESSION STORE按 session key 追加镜像
›
HOST Bload 后物化并 resume

01 / 四个词足够读完本页

先认清镜像的边界

TERM 01

transcript

prompt、工具调用、工具结果和回复组成的会话记录。它保存对话上下文，不保存工作目录文件。

TERM 02

SessionStore

host 实现的适配器。必需方法只有 append 与 load，后端可以是 S3、Redis 或数据库。

TERM 03

SessionKey

projectKey 与 sessionId 找到主记录。可选 subpath 指向子 agent 或 sidecar，host 应把它当作不透明值。

TERM 04

完整性水位

host 额外记录的批次序号、最后 UUID 或健康状态。官方接口没有这个字段，本页把它作为缺段检测建议。I

02 / 一次跨 host 恢复

load 发生在子进程启动以前

这条时序来自官方契约。它讲清数据何时交接，也保留一处很要紧的失败分支。外部镜像写坏了，agent 仍会继续跑。
Host A 发起 query

host 把同一个 store 适配器交给 SDK。新 session 开始积累 transcript。

O
Claude 子进程先写本地批次

镜像依赖这次本地写入，所以 store 与关闭持久化或文件 checkpointing 不能同用。

O
SDK 调用 append

条目是 JSON-safe 对象。适配器要按收到的顺序保存，并让后续 load 返回 deep-equal 的对象。

O
Host A 保存 session id

它还应监看 mirror_error。没有这一步，应用可能把一段不完整的外部记录当成健康记录。后一条是部署建议。

I
Host B 发起 resume

工作目录要匹配原运行。SDK 在启动 Claude 以前向 store 请求这个 session。

O
SDK 物化临时配置目录

load 命中后，SDK 写出临时 transcript，指向该目录启动子进程，运行结束再删掉临时目录。

O
会话从旧上下文继续

新批次仍先写临时本地副本，再镜像回 store。恢复链到此闭合，工作区文件仍由 host 另行提供。

O

03 / 数据与文件流

五个位置，各自只保一部分

01 / HOST A

应用状态

持有 adapter、session id、持久化健康状态和后端凭据。

02 / LOCAL

首写 JSONL

Claude Code 子进程先写本地 transcript。新 session 的本地副本默认会留下。

03 / STORE

外部镜像

按 key 保存有序 opaque entries。保留、加密、访问控制由部署方管理。

04 / TEMP

恢复物化

Host B 的 SDK 在临时配置目录重建 transcript，运行结束删除这一份。

05 / WORKSPACE

另行准备

源码和改动不在 transcript 里。host 要单独提供匹配的工作目录或版本。

04 / 权限门、缺段与停止

查询可以继续，镜像已经不完整

O 缺一批

append 最终失败

拒绝最多尝试三次，超时不重试。SDK 发出 mirror_error，丢掉这一批，agent 继续。

  • 重试可能重复送达，按 entry.uuid 去重。
  • 从 store 恢复的运行结束后，临时副本也会删除。
O 并发

summary 会竞态

官方要求 summary 的 read-fold-write 使用事务、CAS 或每 session 锁。主 transcript 没有公开的全局单写者协议。

  • Redis 参考实现用原子追加。
  • S3 参考实现警告多个写者的时钟偏差会打乱 load 次序。
O 权限

模型与 store 各有凭据

transcript 会保存工具调用与结果。后端 client、TLS、IAM、租户隔离和保留规则都由 host 管理。

  • 第三方开发者把 Agent SDK 放进自己的产品时，除非事先获 Anthropic 批准，必须使用 API key 或受支持的云平台凭据。不得提供 claude.ai 登录，也不得代用户转发 Free、Pro 或 Max 方案凭据。
  • 模型用量归提供 API key 的 Claude Console 组织或相应云平台账户，并按该账户结算。SDK result 里的费用只是客户端估算，正式账单以 Console、Usage and Cost API 或云平台账单为准。store 自身的费用另算。
  • 个人直接使用订阅凭据属于另一种身份与条款，不能把这类凭据转作第三方产品的认证来源。存储凭据仍应遵守最小权限。agent 的工具权限不等同于 store 的访问控制。I
I 版本

没有公开兼容矩阵

条目应按 opaque JSON 保存。官方 changelog 仍在修复恢复路径，也没有承诺任意新旧 SDK 互相读取。

  • adapter 与 SDK 版本一起固定。
  • 发现未知条目、乱序或水位倒退时，停止原 session 的写入。
建议的停止线

应用一旦看见 mirror_error、缺失 UUID、水位倒退或并发租约冲突，就把外部 session 标为不健康。先保留脱敏诊断，再由人工决定修复、分叉或开新 session。这个策略是 I，官方 SDK 不会替 host 阻断查询。

06 / 实现检查单与版本

让 adapter 保持无知，让 host 保持谨慎

  • ORDER

    append 内保持条目顺序，load 按同一顺序返回。JSON 键序可以变化。

    O
  • IDEMPOTENCY

    按 entry UUID 去重。被 SDK 重试的批次可能再次送达。append 超时表示结果不确定，SDK 不会重试。

    O
  • SUBKEYS

    实现 listSubkeys 才能完整恢复子 agent transcript。subpath 不要解释或改写。

    O
  • CONCURRENCY

    summary 更新必须串行。主 session 在应用层加租约，或让第二个写者 fork。

    I
  • RETENTION

    SDK 不会自动删除外部 store。TTL、生命周期和删除级联由 adapter 负责。

    O
  • WORKSPACE

    恢复前准备匹配 cwd 和源码版本。transcript 不承担文件恢复。

    O

版本边界

本页显示 Claude Code 2.1.247 的项目基线。SessionStore 同时受 Agent SDK 包版本约束。

TypeScript 在 0.2.113 首次加入 alpha 接口。Python 在 0.1.64 加入对应能力。TypeScript 0.3.222 修过 store resume 漏带用户 settings 的问题。

当前官方文档还标出 0.3.232 与 0.3.234 的差异。部署记录应同时写 SDK、捆绑 CLI 与 adapter schema 版本。最后一项是 I。

与 SDK-01 主页面的边界

本页从 transcript 本地批次已经写成开始，只追踪外部镜像、另一 host 的恢复和持久化失败。普通消息循环、result、session id 与本机 resume 仍由 SDK-01 Agent SDK 运行时会话循环 解释。

07 / 仍然不知道

接口没有替部署回答这些问题

2.1.247 与具体 SDK 包组合运行时，append 批次的实际边界和延迟。
两台 host 同时 resume 同一 session 时，主 transcript 的确切交错方式和冲突信号。
load 返回一段可解析却已经截断的记录时，子进程会在哪一步停止。
不同 SDK 版本之间，哪些 transcript entry 变更可以兼容，哪些必须迁移。
进程崩溃、append 超时与临时目录清理同时发生时，最后可恢复的外部水位。

安全复现提要
  1. 固定 SDK、捆绑 CLI 与 adapter 版本，先确认模型凭据、用量归属和测试上限，再在隔离 store 上跑官方 conformance suite。
  2. Host A 发一条无敏感信息的短会话，只记批次序号、UUID 集合和散列后的 session id。
  3. 依次制造重复 UUID、append 拒绝、超时与缺一批，核对 mirror_error 和 store 水位。
  4. Host B 用匹配 cwd 恢复。随后让两个 host 同时尝试同一 session，对照无锁、租约与 fork。
  5. 用相邻 SDK 版本重复 load。发现未知条目或顺序异常就停止原 session，不记录 prompt 和工具内容。
