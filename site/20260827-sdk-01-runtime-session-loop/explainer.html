Host 到 session 的一程

一次调用怎样变成可续接的会话

host 发出任务以后，消息会分批到达。它沿着消息流看见初始化、多轮回复和最终结果，再从结果里保存会话编号。下一次调用带回这个编号，旧对话便接着走。

01 · 四个词已经够用

先分清消息和会话

TERM 01

查询

host 交给 SDK 的一次运行。TypeScript 调用返回可异步迭代的消息对象。

TERM 02

消息

运行过程中的一帧。初始化、完整回复、工具结果和最终结果各有自己的类型。

TERM 03

session id

会话的稳定标识。成功或错误 result 都携带它，连接在 result 之前断掉时可能拿不到。

TERM 04

resume

下一次查询指定某个 session id，SDK 便从那段对话历史继续。文件是否还在原样，属于另一件事。

02 · 一次调用的时间

result 是终态标记，流耗尽才算收完

这条时序来自官方契约。启动 hook 的消息可能早于 init，少量系统事件也可能晚于 result。host 因此要把迭代器读完。

host 发起查询

输入可以是一个字符串，也可以是异步消息流。

O
SDK 拉起 CLI 子进程

子进程拥有工作目录、shell 和本地 session transcript，host 与它通过 stdio 通信。

O
收到初始化

system init 带来 session 元数据。TypeScript 可在这里先读到 session id。启动 hook 事件可能排在它前面。

O
进入多轮循环

assistant 消息带文字或工具请求。工具结果以 user 消息送回，模型再决定下一步。

O
最后一轮不再请求工具

SDK 产出一条完整的 text-only assistant 消息。

O
result 给出终态

subtype 说明正常结束、命中上限或执行错误，session id 也在这里。

O
继续读到流耗尽

prompt suggestion 等少量系统事件可以尾随。迭代结束后，这次调用才完整收束。

O
host 要守住两次交接

把 result 当作 break 条件，是这里最容易出现的误读。它宣告 agent loop 已有终态，却不等于消息通道已经关闭。host 可以在看见 result 时记录 subtype 与 session id，但仍要继续消费，直到异步迭代自然结束；随后才把这次调用视为收束。

会话续接发生在下一次 query。host 把保存的 ID 放进 resume，新进程据此载入原来的对话历史，再产生一条新的消息流。这个动作不会让上一个消息迭代器“复活”，也不保证工作目录里的文件回到上次状态。若故障发生在 result 之前，host 没有可靠 ID，此时只能报告失败，不能猜测某个会话。

03 · 进程和数据去哪里

host 读消息，CLI 持有运行现场

HOST

应用代码

送入 prompt，消费异步消息，保存截断或安全存放的 session id。

SDK

进程监管

创建查询对象，管理 stdio 通道，把协议帧整理成 SDK 消息。

CLAUDE

CLI 子进程

驱动 agent 循环、工具回合与终止判断，并把 transcript 写到本地状态。

API

模型请求

CLI 通过网络请求模型。用量归当前选中的凭据来源。API key 与云平台凭据走相应账户，订阅 OAuth 可计入 Claude 方案用量限额。

result.session_id

第一次运行结束后由 host 保存

resume ›
options.resume

下一次查询用它找回同一段对话历史

凭据来源决定用量归属

Agent SDK 拉起 Claude CLI，CLI 会按认证优先级选择凭据。现有 claude login 的 OAuth 凭据能被自动采用。没有更高优先级凭据时，Pro、Max、Team 或 Enterprise 订阅登录是默认回退。API key 与云平台凭据仍排在它前面。

第三方不能擅自替用户提供订阅登录。Anthropic 要求第三方在提供 claude.ai 登录或使用限额前先取得批准。用订阅 OAuth 发出的 Agent SDK 请求可计入对应 Claude 方案的用量限额；用 API key 发出的请求继续按 Claude Platform 的随用随付方式计费。

每次 query 的 result 会给出费用估算。这个数字由客户端计算，正式账单要以 Claude Console 或 Usage and Cost API 为准。

04 · 门、失败和停止

结束有几种，续接也有前提

运行途中

  • 权限门工具请求先经过允许、拒绝或回调决策。本页只画出这道门，规则细节留给 SDK-02。
  • 主动中断流式输入模式可调用 interrupt。TypeScript 的 abort controller 和 close 也能停止运行，close 会强制结束底层进程。
  • 持久化门TypeScript 关闭 session persistence 后，对话不会写盘，也就不能留给后续 resume。

result 所报的终态

  • success任务正常完成，result 字段含最终文本。
  • error_max_turns工具回合碰到上限，仍可取得 session id。
  • error_max_budget_usd客户端费用估算碰到上限，仍可保存会话编号。
  • error_during_executionAPI 失败、取消或进程崩溃等中断了循环。
一次性查询的异常顺序

错误 result 会先进入消息流，随后查询抛错，底层进程以非零状态退出。流式输入会话通常还能继续，进程崩溃例外。

06 · 实现切口与版本

两条流别混在一起

输入模式

字符串 prompt 是一次性输入。异步消息输入让 host 在同一运行中继续送消息，并支持排队和实时中断。

输出粒度

默认只收完整 assistant。打开 partial messages 后，原始增量事件会插进消息流，完整 assistant 和 result 仍然保留。

会话续接

resume 按 ID 载入指定会话的对话历史。它不会复制或还原工作目录里的文件。

01system/init会话元数据与 ID
02stream_event仅在 partial 模式出现
03assistant完整回复或工具请求
04user工具结果或流式用户输入
05result终态、费用摘要与 session id
06system?可能存在少量尾随事件
版本边界

本机固定文件 2.1.247 已核准，默认入口已更新到 2.1.250。官方 Python SDK 0.2.145 changelog 记载它捆绑 2.1.247。8 月 30 日的官方文档索引摘要也已不同于 8 月 27 日基线，本文没有把后续附加字段写成基线必要条件。

07 · 仍未验证

空白要留在图上

  1. 2.1.247 在本机由真实 SDK 调用时，启动 hooks、普通消息和尾随事件会组成哪一种具体序列。
  2. 中断恰好落在 init 后、工具执行中或 result 后时，消息尾序和可续接状态怎样变化。
  3. 本机现有 session 的跨目录查找没有验证，私人 transcript 也没有读取。
  4. TypeScript 与 Python SDK 在不同宿主上的进程退出时机、stdio 缓冲和异常包装差异。

安全复现提要

使用空白配置目录和临时项目，固定 SDK bundle，再发出一条无敏感信息的短请求。只记消息类型、相对顺序和散列后的 session id。第二次查询带 resume，随后用极小轮数上限复现错误 result。最后打开 partial messages 核对增量事件与完整消息并存，并把迭代器读到耗尽。
