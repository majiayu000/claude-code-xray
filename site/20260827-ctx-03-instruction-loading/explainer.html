一次启动，形成一套当下可见的指令

目录决定先读哪几页

用户从一个目录启动 Claude Code。它先收集宽范围指令，再沿这个目录的祖先链向下拼接。等用户或 Claude 要读取具体文件时，子目录 CLAUDE.md 和带路径条件的 Rules 才会按需加入。

多份文件都会留下。后读到的内容没有客户端强制覆盖前文，冲突时模型可能任选一种解释。需要客户端强制的边界应交给权限，或能阻断目标工具调用的 PreToolUse Hook。

01 / TERMS

四张会混在一起的纸

CLAUDE.md

共享说明

放在项目根或 .claude/ 中，适合团队共同遵守的架构、命令和约定。

CLAUDE.local.md

个人补充

项目内的私人偏好，通常加入 gitignore。同一目录里排在共享说明之后。

rules/*.md

拆分规则

可递归组织。没有路径条件就随会话装入，有路径条件就等匹配文件被读取。

@path

内容导入

把另一份文件展开进上下文。相对路径按发起导入的文件计算，最多递归四跳。

02 / SEQUENCE

一次启动里的五步

关键时间点只有两个。启动决定基础集合，读文件动作再补上局部集合。

扫描从哪里开始，会改变基础集合。从仓库根目录启动时，根目录以下的 CLAUDE.md 暂不出现；从更深目录启动时，Claude Code 会向上追溯，把途中每层的 CLAUDE.md 和 local 文件按由远到近的次序拼接。用户层先进入，项目里更靠近启动目录的内容随后出现。

确定启动目录

Claude Code 以进程启动时的工作目录为扫描落点。

装入宽范围层

托管与用户指令先进入上下文，项目层随后出现。

沿祖先链拼接

从文件系统根方向走到启动目录，越近的目录越晚出现。

展开导入

遇到外部项目导入时，首次会经过用户批准门。

读文件再补页

嵌套 CLAUDE.md 与路径 Rules 在目标文件被读取时加入。

03 / FLOW

文件怎样变成模型上下文

发现、筛选、拼接属于客户端流程。最后的遵循仍由模型解释。

文件系统

  • 托管、用户、项目与 local 文件
  • 递归 Rules
  • 被导入文件
→

Claude Code

  • 按 scope 与启动目录发现
  • 按 paths 与目标文件筛选
  • 处理排除项和导入批准
→

当前上下文

  • 多份内容共同保留
  • 延迟规则随读取追加
  • 压缩后按契约重注入
已写进官方契约

启动扫描、嵌套延迟加载、路径匹配和压缩重载都有对应事件原因。

仍缺运行证据

仅执行 cd 是否重建新目录的整条祖先指令链，官方没有承诺。本页不把它画成必然步骤。

压缩后的恢复也分两种。项目根 CLAUDE.md 会从磁盘重新读取，嵌套文件仍要等 Claude 再次读取对应子树。带 paths 的 Rule 也靠重新匹配目标文件触发。因此，会话先前见过某份局部指令，不代表压缩后它会立刻回到上下文。

04 / LIMITS

权限门、冲突和停止位置

外部导入

项目指令首次导入工作目录外文件时会列出目标并请求批准。拒绝后导入保持禁用。

排除来源

--setting-sources 可跳过 user、project 或 local。项目 Rules 随 project source 一起受控。

附加目录

--add-dir 默认只扩大工具访问。额外环境开关打开后，才加载那里的指令文件。

诊断停机

safe mode 关掉自定义内容但保留管理员策略。bare 跳过 CLAUDE.md 自动发现。

冲突没有硬裁判

目录越近、项目规则越具体，内容会在上下文里出现得更晚。官方 SDK 仍明确说明，各层是 additive，层级间没有硬覆盖规则。

顺序可以帮助人定位来源，不能当作覆盖表。同一条要求在用户文件和项目文件里互相冲突时，两段文字仍同时留在模型上下文中。后出现的项目内容较具体，也没有客户端规则负责删掉前一段。排查时可以先用 InstructionsLoaded 确认哪些文件已经进入。需要阻断某项工具动作时，再使用权限或对应的 PreToolUse Hook。InstructionsLoaded 与 CwdChanged 只负责观测。

结果 模型可能选择其中一条。把“严禁执行”只写进 CLAUDE.md，无法得到客户端级保证。

停止条件 找不到文件、source 被排除、路径不匹配、导入未批准或 safe mode 生效时，相应指令不会进入普通加载链。

ACCESS

未登录证据止于本地检查

安装后的版本命令和帮助可以在本机检查程序与参数。启动交互会话前，官方要求先有可用账户或云提供商凭据。可选入口包括 Claude Pro、Max、Team、Enterprise、Claude Console，以及组织配置的 Bedrock、Vertex AI 或 Foundry。

本页只把 claude --version 与 claude --help 算作 L。官方没有承诺登录界面出现前已经完成指令扫描，因此未认证状态不能证明 CLAUDE.md 已进入模型上下文。

COST

实验会占额度或产生账单

订阅 OAuth 会占用相应套餐的使用量。Pro 与 Max 的使用已含在订阅中，Console 或 API key 路径按 API token 计费，Bedrock、Vertex AI 与 Foundry 则记到云提供商账户。

环境里若有 ANTHROPIC_API_KEY，用户批准后它会排在订阅登录之前。一次加载顺序实验要启动会话、读取文件并发送模型请求，因而会消耗套餐额度或计费 token。版本、帮助和哈希检查不创建模型会话。

06 / IMPLEMENTATION

2.1.247 的可见实现边界

可观测事件

InstructionsLoaded 会报告文件、scope 与装入原因。

  • session_start
  • nested_traversal
  • path_glob_match
  • include 与 compact

事件没有裁决权

这个 Hook 异步运行，只用于审计和观测。它不能阻止或修改指令装入。CwdChanged 同样不能拦截目录变化。

近期修复

2.1.211 修正 project source 排除对嵌套 Rules 的作用。2.1.198 修正符号链接路径触发规则。2.1.247 没有声明改动这条主链。

07 / UNKNOWNS

还不能写死的五件事

这些问题需要一次隔离、匿名、获批预算的会话实验。

仅改变工作目录会不会重算祖先指令

官方只保证 CwdChanged 事件，并把嵌套指令装入绑定到读文件动作。单独一次 cd 的效果仍未知。

用户在会话中 cd 到另一个目录，能够确定的只有 CwdChanged 会记录旧目录与新目录。官方文档没有承诺此刻重新执行启动扫描。随后读取新目录下的文件，才有文档支持的 nested_traversal 或 path_glob_match 装入路径。

同一 Rules 目录里的精确文件顺序

官方说明会递归发现 Markdown 文件，没有公布同一层多份规则的完整排序算法。

编辑已装入文件以后何时生效

官方资料没有在本页主契约中给出通用即时热重载保证，需要结合 prompt caching 文档与运行事件核对。

冲突在不同模型上的实际遵循率

官方已经说明没有硬覆盖。具体模型、上下文长度和压缩会怎样改变遵循率，仍需测量。

本机所有装入原因的真实事件序列

没有运行新 Claude 会话，因此没有收集 2.1.247 的 InstructionsLoaded 事件。
