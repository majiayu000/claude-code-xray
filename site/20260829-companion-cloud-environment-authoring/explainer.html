配置改动生效后，新会话才接手

Owner 把网络级别、环境变量和 setup script 写进共享 Cloud Environment。新会话启动时读取修改后的配置，运行中的会话继续用旧值。 setup script 只有在缺少可用缓存时执行，成功后留下文件系统快照。脚本变更、允许域名变更或缓存约七天到期会触发重建。官方没有公开 revision ID、历史回滚或单独 Publish 动作，本页因此只把编辑前后称作“配置代际”。 OI

01 / TERMS

先分清配置、会话和快照

OWNER

组织 Owner

在 Team 与 Enterprise 的 Cloud environments 管理页创建、编辑和归档共享环境。其他成员在选择器里看到只读项。 O

ENVIRONMENT

环境定义

一组给新云会话使用的字段，公开范围包括名称、网络级别、环境变量和 setup script。 O

CONFIG GENERATION

配置代际

本页为了区分编辑前后的配置采用的研究术语。官方文档没有把它定义成可寻址的 revision。 I

NEW SESSION

新会话

启动时复制环境变量，并选择已有快照或执行 setup script。配置编辑只从这里向后生效。 O

SETUP SCRIPT

预置脚本

在 Ubuntu 24.04 上以 root 身份运行的 Bash 脚本。它发生在 Claude Code 启动之前。 O

FS SNAPSHOT

环境缓存

setup script 成功后生成的文件系统快照。安装包、文件与 Docker 镜像能留下，运行中的进程不能。 O

02 / SEQUENCE

管理员改动配置，新会话走完六步

取得编辑入口

Owner 从管理页处理共享环境。Admin 无法打开该页，环境选择器另有 Admin 或 Owner 编辑入口。 O

填写四类字段

选择网络级别，填写 `.env` 行和 Bash 脚本，再给环境命名。 O

让修改生效

官方说明编辑后的值进入以后启动的会话，却没有为通用环境管理流程明确列出 Save changes 按钮，也没有发布审批或 revision ID；这里把编辑生效视为一次配置切换。 I

启动新会话

会话复制当前环境变量。运行中的旧会话不会重读这次修改。 O

决定是否构建

有可用快照就直接复用。缺少快照时先运行 setup script，成功后生成快照。 O

进入 Claude Code

预置阶段成功以后 Claude Code 启动，随后每次会话都会运行适用的 SessionStart hooks。 O

配置改动生效与缓存重建是两件事。环境变量的新值会进入以后启动的会话，官方触发缓存重建的清单只点名 setup script、allowed network hosts 与约七天有效期。页面没有把环境变量编辑画成无条件重建。 O

03 / FLOW

配置流和文件流各走一条线

配置流 / 每个新会话读取
  1. 网络策略None、Trusted、Full 或 Custom 控制会话网络出站路径。
  2. 环境变量启动时复制一次，随后成为命令可读的普通变量。
  3. 旧会话保持原值编辑不会回头改动已经运行的会话。
  4. 归档切断新入口已有会话继续，新会话不能再选择该环境。
文件流 / 缓存按条件重建
  1. 没有快照setup script 先以 root 身份运行，最长约五分钟。
  2. 成功落盘文件、工具链、安装包和 Docker 镜像进入快照。
  3. 后续复用新会话从快照启动并跳过 setup script。
  4. 触发重建脚本或 allowed hosts 变化，或者快照约七天到期。

磁盘内容能留下

工具、依赖、文件和拉取完成的镜像随快照进入以后会话。 O

进程状态会消失

数据库服务、容器进程和后台任务需要每次会话重新启动。 O

恢复不会重跑脚本

已有会话恢复时跳过 setup script，SessionStart hook 仍按会话生命周期运行。 O

04 / LIMITS

权限门在编辑前，失败多在启动时

ACCESS + ROLE GATE

先满足登录与席位，再检查角色

使用 Claude Code on the web 要先登录 Anthropic 账户；研究预览适用于 Pro、Max、Team，以及拥有 premium seat 或 Chat + Claude Code seat 的 Enterprise 用户。进入组织共享环境后，管理页只给 Owner；环境选择器另有 Admin 或 Owner 编辑入口。 O

VISIBILITY GATE

环境变量不适合放密钥

使用环境的人可以读取变量，Claude 运行的命令也能读。可由 agent proxy 附加的密钥应放 API credential，避免进入会话 VM。 O

SCRIPT STOP

非零退出挡住新会话

setup script 退出非零时，会话启动失败。网络级别设为 None 后，依赖联网的安装也会失败。非关键命令可以明确处理错误。 O

TIME STOP

约五分钟是构建预算

长下载和串行安装可能让缓存构建超时。官方建议并行独立步骤，把单个重任务移到 SessionStart hook 的后台路径。 O

ARCHIVE STOP

归档只拦新会话

环境会从选择器消失，显式绑定它的 routine 也不能再启动。已经运行的会话继续使用原配置。 O

VALIDATION UNKNOWN

字段级拒绝规则没有公开

文档解释了 `.env` 解析与 allowed hosts 格式，却没有列出提交修改前的全部无效状态、错误文案和部分生效规则。这里保持未知。 I

本轮停在只读核对

documented

编辑共享环境会改变远端组织状态，启动缓存构建还会消耗账户用量。本轮没有登录、创建、保存、归档或启动会话，因此没有 R。

  • 三个常见独立安装位置也没有可执行文件。 L

06 / IMPLEMENTATION

“版本化”目前只能落到可观察行为

BASELINE / 2026-08-27 / 2.1.247

公开契约支持两代配置并存

编辑生效以后，旧会话保留启动时拿到的变量，新会话读取修改后的值。缓存又有自己的生命周期。这个现象足以区分配置代际，却不足以证明服务端暴露不可变 revision 对象。 OI

07 / UNKNOWNS

四处缺口仍需测试组织

服务端有没有正式 revision

公开文档没有 revision ID、并发更新、保留期或回滚契约。服务端可能保留内部版本，本轮没有证据把它画进状态机。

提交前怎样拒绝无效字段

环境名称、`.env` 行、域名通配符和脚本长度分别怎样校验，哪些错误允许部分保存，公开材料没有完整说明。

构建失败以后旧快照怎样处理

新快照构建失败时，旧快照会不会继续服务新会话，重试何时发生，界面有没有手动重建动作，都需要真实实验。

哪些网络改动一定触发重建

官方点名 allowed network hosts。只切换 None、Trusted、Full、Custom 而不改域名清单时，缓存是否重建仍没有精确契约。
