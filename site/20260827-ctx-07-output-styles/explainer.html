NO. 10 OUTPUT STYLES

CTX-07 Claude Code 2.1.247 documented

同一位 Claude，换一套出场规矩

用户选中的 Output Style 会在新会话开始时进入系统提示，随后持续约束主会话的角色、语气和默认格式。它不增加知识，也拿不到新的工具权限。

01 发现从用户、项目、managed policy 或插件找到样式
02 选择由设置层级或强制插件确定生效名称
03 注入新会话组装系统提示并加入样式正文
04 呈现每轮按样式回复，权限仍由独立规则裁定
01 / TERMS

先把四种证据分开

O官方契约

Anthropic 文档、changelog 与官方 SDK 文档公开承诺的行为。

L本机静态证据

2.1.247 二进制、CLI 帮助和公开字段留下的本机证据。

R真实实验

本轮没有。真实模型请求与真实配置写入都在授权边界外。

I研究者推断

官方没有公开的连接处，只保留成待验证解释。

样式定义

一份 Markdown。frontmatter 提供名称与开关，正文提供要加入系统提示的指令。O

生效选择

outputStyle 保存样式名称。终端里的 /config 会把选择写到项目本地设置。O

呈现

角色、语气和默认输出格式会变。Claude 已知的内容不会随样式增加。O

02 / SEQUENCE

一次选择要等到新会话才落地

准备定义

Claude Code 扫描内置样式，以及当前配置范围内的自定义样式。O

用户选择

终端运行 /config，或直接写 outputStyle。菜单选择落在项目本地设置。O

解析胜者

设置层级决定选中的名称。强制插件可以覆盖用户选择。O

会话开始

Claude Code 组装系统提示，加入样式指令，并按开关决定是否保留软件工程指令。O

持续回复

主会话每轮都受样式约束。非 Default 样式还会得到遵循样式的提醒。O

运行中的会话改了样式，下一条回复仍沿用旧系统提示。执行 /clear 或新开会话以后，新选择才生效。O

这里会发生两次读取。Claude Code 先在允许的来源里寻找样式定义，再从设置层级和强制插件中确定生效名称。/config 写下的是选择结果，Markdown 正文仍留在样式文件中。启动新会话时，程序才按这个名称取出正文，组装新的系统提示。O

所以，在运行中的会话里修改选择，只改了下一次会话启动时要读取的状态。当前会话已经带着旧系统提示运行，不能靠下一条普通用户消息替换它。这个生效边界也解释了为什么官方要求执行 /clear 或重新开始会话。

03 / FLOW

定义文件、设置值和系统提示各管一段

样式来源

内置样式、用户目录、项目嵌套目录、managed policy、插件。项目同名定义由离工作目录最近者取胜。O

设置值

Managed 高于一次启动的 --settings，随后依次是项目本地、共享项目、用户设置。O

插件强制

force-for-plugin 会覆盖用户的 outputStyle。多个强制插件采用最先加载者。O

→

Default

沿用既有系统提示。

自定义样式保留编码指令

keep-coding-instructions: true 时，软件工程指令与自定义正文一起进入系统提示。

自定义样式替换编码角色

开关缺省为 false。Claude Code 省去软件工程专用指令，加入样式正文。

对话中的提醒

非 Default 样式在会话过程中还会收到遵循样式的提醒。精确频率没有公开。

04 / SURFACES

这套选择入口没有铺到每个界面

终端

/config 提供 Output style 菜单，选择结果写入项目本地设置。这是官方写明的完整入口。O

Desktop

官方要求在设置文件里填写 outputStyle。Desktop 中的 /config 打开 Claude Code 设置页，不会出现终端菜单。O

IDE

VS Code 与 JetBrains 属于 Claude Code surface。Output styles 文档没有给它们列出独立选择入口，本页不把终端菜单推广到 IDE。I

Web

Web 会话不使用本机配置。官方没有写 Web picker 或项目样式在云端的加载规则，本页将支持情况留作未验证。OI

Agent SDK · TypeScript

可在传给 query() 的内联 settings 中设置 outputStyle。它不是顶层 Options 字段，加载定义还要启用相应 setting sources。O

Agent SDK · Python

没有编程式选择 Output Style 的选项。已有设置来源可以加载样式；纯代码部署应改用 append 或自定义系统提示。O

AUTH & USAGE

真实回复需要有效认证。终端可使用 Claude 订阅、Console 或受支持的云提供商；多数 surface 需要订阅或 Console 账户，Desktop 要求付费订阅。测试 prompt 会计入订阅额度，或按 API token 进入 Console 与云提供商账单。官方没有保证这类测试请求免计用量或费用。O

05 / LIMITS

样式能影响决定，不能替工具开门

权限门独立存在

Proactive 会鼓励立即行动，permission mode 仍决定哪些工具动作可直接运行。权限规则由 Claude Code 执行，系统提示里的句子不能授予访问权。O

主会话边界

普通 subagent 使用自己的系统提示，不受主会话样式影响。fork 会继承父会话完整系统提示，因此带走样式。O

错误设置会被跳过

无效 JSON 或被拒绝的值会触发 Settings Error 或 Warning。非交互运行没有修复对话框，Claude Code 会跳过坏文件或坏值；可用 claude doctor 查看细节。O

安全模式停用定制

2.1.247 的 --safe-mode 帮助明确列出禁用 output styles，内置工具和 permissions 仍正常工作。managed policy 与强制样式同时出现时的细节留作未知。L

06 / OBSERVATION

这页有 O 和 L，没有 R

R = 0
没有发送测试 prompt

本机静态结果

L保留的安装文件返回 Claude Code 2.1.247，SHA-256 与研究基线完全一致。

L帮助中可见 --settings、--setting-sources、--safe-mode 与独立权限选项，没有独立 --output-style。

L安装物的定向静态字符串包含 outputStyle、相关 frontmatter 字段和五个内置样式名称。

这些结果只能证明 2.1.247 安装物带有相应入口与字段。它们没有证明样式正文在某次真实请求中怎样注入，也没有证明模型这次遵循了多少。

07 / IMPLEMENTATION

五种内置取向，同一套权限边界

Default

既有软件工程系统提示。

Proactive

少停顿，多做合理假设，仍接受权限门裁定。

Concise

结果靠前，减少铺垫。错误、安全警告与破坏性确认保持完整。

Explanatory

工作期间加入教育性 Insights。

Learning

协作式学习，会留下少量 TODO(human) 让用户完成。

O额外的样式指令会增加输入 token。Explanatory 和 Learning 按设计会写得更长，Concise 倾向缩短输出。提示缓存能减轻同一会话首轮之后的重复输入成本。

VERSION CUT

Concise 在 2.1.237 加入。旧 /output-style 在 2.1.73 弃用，2.1.91 移除。2.1.178 又明确了嵌套项目中同名样式由最近目录取胜。2.1.247 已包含这三段变化。O

研究时 PATH 已更新到 2.1.248。本页所有本机静态结论都来自保留的 2.1.247 安装文件。官方索引在 2026-08-28 仍为 202 个入口，散列已经变化，因此本页保留 2026-08-27 给定散列作为基线。

08 / UNKNOWNS

官方契约停在这些地方

样式正文插在系统提示的哪个精确位置

官方确认自定义指令进入系统提示，也确认软件工程指令可被保留或省去。完整系统提示没有公开，字节级排列仍未知。I

样式名称找不到或文件损坏时怎样逐字报错

设置文档给出了通用错误与跳过规则。缺失样式、空正文和坏 frontmatter 的逐字错误与回退值没有 R 证据。I

不同来源提供同名定义时的完整顺序

已知嵌套项目目录取最近者，设置值遵循设置层级，强制插件覆盖用户选择。用户、managed policy 与插件的定义文件同名时，官方没有在一张统一表里写完全部组合。I

长会话里的样式提醒多久重发一次

官方只说非 Default 样式会收到提醒。压缩、恢复与长会话中的精确重发时点没有公开。I

安全模式碰到 managed 强制样式时谁赢

2.1.247 帮助一边说安全模式禁用 output styles，一边说 admin-managed policy settings 仍适用。两者同场时的样式正文是否注入，现有证据不够。I

IDE 与 Web 能否选择并加载同一套样式

官方只给终端和 Desktop 写了选择办法。Web 不使用本机配置，IDE 与 Web 的独立 picker、项目样式发现和云端加载行为没有在本轮得到官方契约或真实实验。I
