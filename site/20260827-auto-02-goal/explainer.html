持续目标与续跑

/goal 让完成条件留在会话里

用户显式输入目标以后，Claude Code 立即开始工作。每个 turn 收尾时，另一个小模型只根据对话里已有的证据评估条件。未满足就续一轮，满足或判为不可完成就清掉 goal。

普通 prompt 没有这层续跑器。官方只公开了显式命令入口，因此本页不会把普通长任务推定成 goal。O + I

O 官方契约 L 本机静态或帮助 R 本轮真实实验 I 研究者推断
核验票据 029

本轮没有启动会消耗套餐用量或按 token 结算的 Claude 会话，也没有读取私人 transcript。页面有 O 与 L，没有 R，所以状态保持 documented。

01 · 先认清四样东西

goal 留下条件和裁决记录

官方只承诺会话级条件、状态统计与 transcript 里的理由。它没有公开一个独立 goal 文件。

可观察的保存单位就是原会话。用户可以查看条件与最近一次评估理由，也可以退出后恢复同一会话；页面却不能据此断言磁盘上存在某个固定文件，更不能编造内部字段。已经达成、失败或被清除的记录仍可留在 transcript 里，只有 active condition 会参与下一次续跑。

TERM 01条件

用户在显式命令后写下的可核终态。上限 4,000 个字符，最好带检查办法。

TERM 02主 turn

主模型会在这一轮读文件、改代码和跑工具。goal 不改变原有的权限规则。

TERM 03评估器

小型快速模型。它看条件和对话，不独立读文件，也不自行执行检查命令。

TERM 04会话记录

最近理由、达成或失败结果会进入 transcript。active condition 会随原会话恢复。

03 · 数据和状态怎样流

评估器只能看 Claude 已经说出来的证据

用户写下完成条件

普通任务要变成持续目标，必须走公开的显式入口。

→
主模型工作并呈现证据

测试退出码、构建结果或文件计数需要出现在对话里。

→
小模型只读条件和对话

它返回裁决与短理由。评估 token 按配置的小模型计费。

Not yet met

goal 保持 active，理由进入下一 turn。

Met

goal 清除，transcript 记一条 achieved。

Impossible

goal 清除，transcript 记一条 failed 和理由。

条件写得越能核对，评估器越容易作出稳定判断。测试是否退出成功、目标文件是否存在，或者某个计数是否达到给定值，都应由主模型运行检查并把结果写进对话。评估器不会越过对话去补跑命令。条件只写“把事情做好”时，它得到的证据也会含糊，续跑次数随之更难预料。

04 · 权限、失败与停止

卡住时先看 goal 是否仍是 active

官方没有给 goal 定义名为 blocked 的 evaluator verdict。Agent View 的 Needs input 属于相邻机制。

本页所说的 complete 对应评估器给出 Met，随后 active goal 被清除，transcript 留下 achieved。blocked 只用于研究任务的交付状态，`/goal` 的产品裁决仍是上述三种。等待用户批准、后台任务未返回或无进展保护触发时，会话可能暂时停住，goal 仍可保持 active。只有 Impossible 才会把这次目标收束成 failed。

等待权限

Manual mode 会照常询问。会话此时需要用户输入，active goal 没有因此变成 Impossible。

等待后台结果

还有后台任务时暂不评估。2.1.247 会做退避 check-in，两次用户消息之间最多三次空闲唤醒。

无进展保护

连续几轮没有工具进展时，循环会暂停并交还控制权。goal 仍是 active，下一条用户 prompt 后再继续。

不可恢复错误

自管认证失效、余额耗尽、压缩也解不开的上下文溢出或模型不可用会清除 goal，并要求修复后重设。

瞬时错误

rate limit 与服务器过载会保留 active goal。宿主管理认证时，认证失败也交给宿主恢复。

用户主动结束

clear 及其别名会移除 active goal。开始新对话的清除命令也会移除它。

续跑前还要确认登录方式和费用归属。每个主 turn 都会用模型，收尾的评估器也会消耗小模型 token。O

先有可用认证

Claude Code 支持 Claude Pro、Max、Teams、Enterprise 账户，也支持 Console 和组织配置的云提供商。当前凭据还要能正常发起模型请求。

订阅与席位额度

Pro、Max 的用量包含在订阅内，界面上的会话成本估算不等于实际账单。Teams、Enterprise 从成员的席位额度扣用量。

按 token 结算

Console API 和云提供商按 token 向组织或云账户计费。环境里的 API key 获准后可优先于订阅登录，费用会跟实际采用的认证方式走。

06 · 实现与版本边界

状态跟着原会话，turn 边界交给 Stop hook

创建面会话级内置命令。一个会话只允许一个 active goal。O
触发面主 turn 正常结束后走 session-scoped prompt Stop hook。用户中断引起的停止不会触发普通 Stop hook。O
状态面条件、最近理由和结果进入会话 transcript。独立本地文件与字段 schema 未公开。O + I
恢复面仍 active 的条件随原会话恢复，turn 数、计时与 token 基线从零重新算。O + L
权限门workspace 必须受信任。disableAllHooks 或 managed 的 allowManagedHooksOnly 会拒绝 goal。O + L

恢复只接续仍处于 active 的条件。用户可以用 continue、指定会话的 resume 或恢复选择器回到原会话，条件会重新进入评估循环；已评估 turn 数、计时器和 token 基线从零开始。这个重置不会把旧结果改写成新结果，也不能把已经 achieved 或 cleared 的 goal 重新激活。

版本线索　2.1.139 加入 goal。2.1.234 处理不可恢复错误和后台 check-in。2.1.239 修复 resume picker 恢复并加入退避。2.1.246 把空闲 check-in 限为三次。2.1.247 没有新增 goal changelog 条目。

07 · 仍然不知道

公开契约停在会话级，不给本地 schema

本地字段

active goal 的精确字段名、对象结构与写入原子性没有公开，本轮也没有读取私人 session 文件。

评估请求

不同提供商上的完整 payload、重试次数、超时阈值和缓存办法仍未知。

Impossible 阈值

官方说明了裁决含义，没有公开内部 prompt 与置信阈值。

异常退出落盘

Ctrl+C、进程崩溃和断电各自在何时保存 active goal，官方 resume 契约没有逐项展开。
