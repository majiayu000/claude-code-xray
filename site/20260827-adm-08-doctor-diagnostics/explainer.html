01 · TERMS

先分清三个动作

SHELL / O+L

claude doctor

CLI 起不来时也能用。官方称它为不启动会话的只读安装诊断。它读取当前目录设置时不弹信任提示，适合先收集版本、安装方式、运行平台与配置解析结果。

SESSION / O+L

/doctor

2.1.247 的完整 setup checkup。它能诊断并修复问题，也会检查扩展的上下文成本与慢 hooks。这是另一条入口，可能进入模型请求和写入阶段，本轮没有实跑。

STOP / R

Fix 建议

shell 结果把恢复动作写成下一条命令，随后退出。用户没有明确执行它，安装就不会改变。建议命令属于新的管理动作，应先核对目标与影响，再另行批准。

02 · SEQUENCE

一次检查怎样走完

用户启动

从 shell 运行子命令。它不启动 Claude 会话，也没有修复参数。固定版本运行还能避免 PATH 已更新后混入另一版行为。

收集信号

读取安装身份、版本、运行平台、更新状态与当前目录设置。当前目录不会先弹信任提示。联网条件不足的远端项目仍可能进入结果树。

逐项判定

能确认的项目显示通过或 warning。缺少远端响应时保留无法验证，不补一个乐观答案。每个状态只覆盖对应检查，不能替整机健康背书。

显示建议

状态树把问题和 Fix 放在一起。shell 入口停在命令建议，不替用户执行。安装、升级、导入与清理都在这条边界之外。

进程退出

用户可以手工执行建议，或另开会话运行可修复的 /doctor。两者都需要新的明确动作。退出码只能说明进程怎样结束，不能代替逐项读取。

  • 更新通道、自动更新状态和最近结果
  • 当前目录里可加载的设置

R 观察　空白替代配置目录仍出现应用状态 JSON 与备份，共 427 字节。doctor 没有改安装和项目设置，但“零写盘”不成立。这里只核对文件数量、大小与匿名化顶层键，没有读取任何真实用户配置。

看到 OK

先读项目名称，再判断它覆盖到哪里。官方给出的 WSL 搜索反例说明，Search 显示 OK 时仍可能漏掉跨文件系统结果。单个绿项不能推出所有相关功能都正常，也不能代替针对眼前故障的复现。

看到 warning

把提示和紧邻的 Fix 一起记录，再停下来核对。隔离实验里的安装方式警告附带了安装命令，doctor 只打印它，没有代替用户执行。进程最后仍返回了 0。记录里还应保留运行版本和平台，免得后来拿另一版结果混用。

看到无法验证

先检查本轮是否关闭网络，或者是否缺少远端响应。证据不足时维持未知，不能把它改写成故障，也不能当作通过。需要联网、登录或读取更多配置时，应先取得新的授权，并把新增检查单独记录。

04 · LIMITS

停在哪里才算安全

建议停住了

隔离实验发现安装方式未设置，doctor 显示 claude install，随后退出。安装没有发生。执行这条命令会进入独立的安装机制，本页也不会替它说明写入范围。

无法确认就保留未知

实验关闭非必要流量后，Remote Control 显示未验证。没有 server response 也没有被包装成 OK。恢复网络后会得到什么，本轮没有证据。

退出码不等于全绿

本轮有一条 warning，shell doctor 仍返回 0。自动化脚本不能只看退出码判断机器健康，还要保存逐项状态和无法验证的原因。

会话检查会越过只读边界

2.1.247 的 /doctor 能诊断并修复问题。只想收集证据时，停在 shell 输出，不进入这条路径。模型费用、权限提示与具体修复写入都保持未知。

R · 没有模型请求

实验使用 shell 子命令、空白替代配置目录和固定版本二进制，没有登录，也没有进入 Claude 会话。自动更新、遥测与非必要流量同时关闭。

R · 没有执行恢复动作

Fix 行只打印命令。版本与安装文件没有改变，Project purge、配置导入和升级也没有发生。

R · 有少量本地状态写入

运行后多出应用状态文件和备份，共 427 字节。只核对匿名化顶层键，没有展开值。

范围

这次实验只覆盖 macOS arm64 native 的 shell doctor。会话内可修复的 /doctor 只记录官方入口，没有实跑。npm、Homebrew、WinGet、Windows、Linux 与 WSL 仍需各自验证。

06 · IMPLEMENTATION

实现边界与版本变化

2.1.247 本机锚点

缓存二进制是 Mach-O arm64，SHA-256 与研究基线一致。本机 PATH 已升级到 2.1.248，本页 L 与 R 都绕过 PATH，直接调用固定版本。

旧界面停在 2.1.205 之前
  • 2.1.105 加入状态图标与 f
  • 2.1.178 统一平铺结果树
  • 2.1.203 接收 broken command 警告
  • 2.1.205 改成可修复的 setup checkup
2.1.248 不倒灌

基线后的 2.1.248 新增 server-managed settings 诊断。本页不会把这项新能力写进 2.1.247 的结论。

OK 的含义有限

官方给过明确反例。WSL 跨文件系统可能让搜索漏结果，doctor 仍显示 Search 为 OK。状态项说明检查通过，不承诺业务效果穷尽无误。

07 · UNKNOWNS

还不能写死的地方

UNKNOWN 01

闭源二进制内部每项检查的函数顺序、并发方式和超时值没有公开。

UNKNOWN 02

哪些失败会让 shell doctor 返回非零退出码，官方没有完整矩阵。本轮 warning 返回了 0。

UNKNOWN 03

进入会话内 /doctor 后送给模型的材料、费用和各类修复的权限提示没有安全实跑。

UNKNOWN 04

npm、Homebrew、WinGet、Windows、Linux 与 WSL 会产生哪些状态写入，不能从一次 macOS native 实验外推。

UNKNOWN 05

Search、MCP 与远端可用性检查的 OK 究竟覆盖多深，官方没有给出完整保证，现有反例也不能推导出穷尽范围。
