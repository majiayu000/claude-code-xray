01 / TERMS

先认清三条路

Slack 里都可能出现 @Claude，运行位置和身份却不同。把名字分清，后面的权限与停止条件才不会串线。 [O]

旧 Claude Code in Slack

个人连接 Slack 与 claude.ai。编码请求进入 Claude Code on the web，使用提问者已连接的 GitHub 仓库与个人计划限额。

Claude Tag

Team、Enterprise 的共享频道代理。Owner 给它独立身份、仓库和连接，频道里的人共用同一组访问。

Legacy 与 New

同一个 Slack app 的两种版本。Enterprise 可以按 scope 选择 Legacy、New、Off 或 Inherit，迁移期间可并存。

Channels

把外部事件推入正在运行的本地 CLI 会话。它的 capability、通知信封与回复工具留给 UI-08。

回到 UI-08 查看 Channels 的运行中注入协议。本页只负责 Slack 委派与退役矩阵。

02 / SEQUENCE

一条频道消息怎样变成工作

两条路都从 Slack 消息出发，也都回到那条线程。中间的账号、仓库和会话归属已经换了。 [O]

1
频道成员

在 Claude 已加入的频道或线程里写下任务。旧路径可以在 Code + Chat 中判断编码意图，也可以用 Code only 全部送去代码会话。Claude Tag 的频道任务由任何获准成员发起。

2
Slack app

旧路径收集线程或近期频道上下文，再决定走普通聊天还是 Claude Code on the web。Claude Tag 把首条消息交给频道会话，并在该消息下建立线程工作会话。

3
身份与仓库

旧路径从提问者个人已连接仓库中自动判断，选错后可 Change Repo。Claude Tag 先建空 sandbox，首条消息点名频道已获授权的仓库后才克隆。

4
云端执行

旧路径新建 claude.ai/code 会话。Claude Tag 在每条线程自己的 sandbox 里运行同一套网页端引擎，仓库内的 CLAUDE.md、hooks 和 skills 在克隆后加载。

5
原线程

旧路径发状态、完成摘要与 View Session、Create PR 等按钮。Claude Tag 用可原地更新的 checklist 报进度，再把回复、文件或 draft PR 放回线程。

6
继续或收住

Claude Tag 允许频道里的其他人直接在线程回复并接着引导。任务安静一段时间后 sandbox 释放；下次回复会重建 sandbox，线程会话继续。

04 / GATES

哪里会停，谁能放行

安装 app 只是第一关。身份、频道、仓库、环境和花费都可能让任务停住。 [O]

旧路径可通过

个人账号有 Claude Code on the web，至少连接一个 GitHub 仓库，Claude app 已加入目标频道。

旧路径停止

没有网页端 cloud environment 时，代码会话不会启动；没有 web access 时只得到普通聊天回复。

Claude Tag 可通过

Owner 完成 workspace 配对，给 scope 选 New，授予组织共享 environment、频道访问和仓库。

仓库门

新会话开场没有仓库。仓库没被授予该频道，点名也无法克隆；改完授权要开新线程。

环境门

Claude Tag 频道若指向个人 cloud environment，会话立即失败，重试无效。Owner 要换成组织共享环境。

花费门

组织或频道上限不足时，Claude Tag 拒绝新工作，并说明是限额还是余额阻止，不会悄悄中途截断。

退役门

Legacy scope 到账号团队给出的 cutover 日期后停止回复，直到把该 scope 改为 New。

线程停止

Claude Tag 首条消息在还没有回复时被删，会话关闭。空闲只释放 sandbox，线程与会话仍可在后续回复时续接。

迁移不会搬运个人连接。New 起初没有外部访问，Owner 需要重新连接 GitHub 和其他工具。代码由 Claude GitHub App 署名，旧路径的 PR 若仍挂在提问者名下，说明该 scope 还在 Legacy。 [O]

05 / EVIDENCE

本页有 O，R 缺席

本轮完整核对官方 Slack、Claude Tag、迁移和平台资料。没有登录 Slack 或 Anthropic 组织，没有发消息、创建云任务或消耗用量。 [O]

OAnthropic 官方契约，本页主要依据
L本机静态或帮助证据，本轮未取得功能证据
R真实安全实验，本页缺失
I研究者推断，只标边界

本机观察 当前 shell 调用 claude --version 返回 command not found，预期安装目录又被环境拒绝读取。固定的 2.1.247 与二进制哈希来自研究基线，不能充当本轮 L。页面因此保持 documented。

为何没有 R 真实运行需要登录、安装或连接 app、发 Slack 消息并建立收费云端工作。任务边界禁止这些动作。可恢复的匿名化步骤已写进 evidence.md。

06 / VERSION

退役是一段过渡

迁移指南把 Team、Enterprise 的旧路径列入 Legacy 过渡，同时给 Enterprise 留下按 scope 切换的空间。具体 cutover 日期由账号团队告知。 [O]

NEW

产品切向 Claude Tag

Team、Enterprise 的新方向采用组织共享身份，旧路径按迁移设置继续过渡。

2026-08-27

本页固定基线

Claude Code 2.1.247，官方索引 202 个入口。本轮不拿 8 月 30 日索引替换基线哈希。

CUTOVER

Legacy 进入停服

Enterprise 迁移期可以让 New 与 Legacy 分 scope 共存。到指定日期后，Legacy scope 才停止回复。

Team 的差别 Team 使用一个 Enable Claude Tag 开关。官方迁移页说明开关只在没有 scope 仍路由到旧 app 时出现；旧连接不会自动变成新访问包。

视觉与实现取舍 本页用一张路由卡、一张差异矩阵和两条并排行程呈现同一组事实。单文件 HTML 无外部字体、脚本、图片、追踪或 iframe，窄屏表格可横向查看。

07 / UNKNOWNS

还不能写死的地方

这些缺口会改变真实可用性，官方没有给统一答案，本轮也没有登录态实验。

这个 workspace 哪天停止 Legacy

官方只给迁移机制，具体 cutover 日期要向 Anthropic account team 确认。

旧路径怎样给仓库候选排序

官方保证按对话上下文自动选择并允许用户更改，没有公开评分、阈值和多候选 UI 的触发条件。

Claude Tag 没听到仓库名时怎样处理编码请求

官方 Claude Code 用户指南只保证首条消息点名已授权仓库后才克隆。追问、解释或其他选择行为没有统一承诺。

当前 scope 与花费还剩多少

这取决于组织设置、频道上限和余额。没有管理员访问就不能从公开文档得出。

本机 2.1.247 暴露了什么相关入口

本轮 shell 找不到 claude，安装目录也无法读取。Slack 与 Claude Tag 主要运行在 Anthropic cloud，本页不借固定版本号补本机实现结论。
