EXT-06 · documented · Claude Code 2.1.247

LSP 接通代码语义

用户要求查一个符号的定义或引用后，Claude 才会发起这页的主动作。插件提供文件扩展名到语言服务器的映射，LSP 工具把语义位置送回模型。服务器起不来时，这次调用只得到错误，普通搜索没有自动接管保证。

编辑后诊断来自另一种触发动作，本页把它留在主链旁边说明。Grep、Glob、Read 可以继续帮 Claude 找文本和读文件，是否改用它们由模型下一步决定。

01 / TERMS

先分清三个角色

代码智能插件

保存 server 命令与扩展名映射。它负责接线，不包含语言服务器二进制。

语言服务器

用户另外安装的本机进程。它读项目语义，通过 stdio 回答定义、引用、类型和符号查询。

LSP 工具

Claude 可调用的内置工具。定义、引用等导航结果从这里回到 agent 循环。编辑后诊断另走自动注入旁路。

02 / SEQUENCE

一次查询怎样走完

这条主链只跟随一次导航查询。用户让 Claude 查某个符号的定义或引用，Claude 选择 LSP 工具，客户端再根据目标文件的扩展名找到已登记的 server。语言服务器程序要由用户另外装进 PATH。官方没有说明 2.1.247 在插件登记后何时创建进程，所以图中把映射登记和进程启动分开，后者保留为未知。

用户提出导航问题

例如查一个符号在哪里定义，或列出它的引用。模型随后决定调用 LSP，这一步是本页唯一的主要用户动作。

O + I

先过可用性边界

LSP 必须留在本次会话的工具集合里，代码智能插件也要启用。调用本身无需常规审批，Read 路径 deny 规则仍会约束它。

O + L

扩展名选 server

Claude Code 从 .lsp.json 或 plugin.json 取得映射。同一扩展名冲突时，先注册者接管。

O

进程通过 stdio 对话

命令需要出现在 PATH。stdout 只走协议，日志写 stderr。启动时点的完整内部顺序仍未公开。

O

结果回到模型

server 成功时，定义或引用位置经 LSP 工具返回。server 无法启动时，同一次调用返回错误结果。

03 / FLOW

主链只有一次导航查询

本页状态转换

用户的自然语言问题先变成一次 LSP 工具调用。server 返回定义位置、引用位置或类型信息，工具层把语义结果交回模型。模型随后可以读取目标文件，继续回答或修改代码。

  • 起点是用户要求查符号
  • 终点是语义结果进入模型
  • 错误也作为这次工具结果返回
≠

编辑诊断属于旁路

Claude 修改文件才会触发这条路。默认配置把类型错误和警告直接放进 Claude 的上下文，不需要新的导航查询。diagnostics: false 可以关闭它，定义与引用仍可使用。

  • 触发动作是文件编辑
  • 结果直接注入上下文
  • 不计入本页主要状态转换
04 / ACCESS

登录、费用与权限

先有可用会话

个人可以用 Claude.ai 的 Pro 或 Max 账户登录。组织还可以用 Team、Enterprise、Claude Console，或通过 Bedrock、Google Cloud 与 Microsoft Foundry 接入。

费用跟随认证方式

订阅用户先消耗套餐额度，超额能否继续取决于 usage credits 与组织设置。Console 和云提供商按 token 计费。官方没有为 LSP 单列一项附加价格，模型回合仍照常计入用量。

免询问不等于无边界

LSP 在工具表中无需常规审批。--tools 可以限制会话里的工具，裸工具名 deny 可以移除 LSP，Read 路径 deny 规则可以拒绝匹配调用。allow 与 --allowedTools 只让匹配调用免于询问，不负责限制工具。插件未启用、--safe-mode 关闭插件或 --bare 跳过 LSP 时，查询不会进入 server。

05 / LIMITS

四个停止位置

CONFIG SKIPPED

缺 command 或扩展名映射的配置会被跳过。它不占住扩展名，后面的有效 server 仍有机会接管。

EXECUTABLE MISSING

command 不在 PATH，插件 Errors 页会显示可执行文件不存在。插件只带配置，不替用户安装 server。

PROTOCOL BROKEN

stdout 混入日志、header 超过 64 KiB 或 body 超过 32 MiB，Claude Code 会断开 server，并把它计作 crash。

RESTARTS EXHAUSTED

崩溃默认会重启。restartOnCrash 可以关闭，maxRestarts 限制次数，耗尽以后 server 停止。

普通搜索是一条可选支路。 LSP 返回错误后，Claude 仍可能调用 Grep、Glob 或 Read。官方没有承诺客户端自动替换这次调用。Grep 找的是文本，Glob 找的是路径，Read 负责读取文件。它们能帮模型继续排查，却没有类型、引用和接口实现的语义保证，也不会补回编辑后的自动诊断。

07 / IMPLEMENTATION

配置旋钮与版本线

工具是否处于 active，和眼前这个文件能否得到结果，是两件需要分开看的事。没有代码智能插件时，LSP 工具保持 inactive。2.1.247 的会话只要曾经有一个可用 server，工具便会在余下会话中保持 active。后来打开的文件若没有匹配 server，或匹配的 server 已经启动失败，工具仍可能显示可用，单次调用会返回错误。这个状态不能证明进程还健康，也不能证明每种文件都有语言支持。

注册阶段还会处理扩展名冲突。几个已启用 server 同时声明一种扩展名时，先注册者取得它，其他 server 不会为这种扩展名启动。无效配置会先被跳过，不会占住扩展名。这样一来，配置错误、命令缺失和运行中崩溃会停在不同位置，排查时也应分别查看插件错误、PATH 和协议进程。

公开配置

command
必须能从 PATH 执行
extensionToLanguage
把文件扩展名映射到语言标识
diagnostics
默认开启编辑后诊断推送
startupTimeout
限制启动等待
restartOnCrash
默认开启崩溃重启
maxRestarts
给重启设置终点

版本边界

  1. 2.0.74 加入 LSP 工具。
  2. 2.1.50 加入启动超时。
  3. 2.1.205 起崩溃重启和关闭超时可用。
  4. 2.1.235 起工具曾经有 server 可用便保持 active。
  5. 本页固定在 2.1.247。
08 / UNKNOWNS

还缺哪几块证据

server 究竟在哪个事件上 spawn

官方公开了插件注册、文件映射与失败行为，没有给出固定版本从编辑或首次导航请求走到进程创建的完整内部时序。

LSP 结果怎样裁剪和排序

文档列出能力，没有发布固定到 2.1.247 的完整输入输出 schema、所有错误码与大结果整形规则。

错误以后模型怎样选下一步

它可以重试 LSP，也可以调用 Grep、Glob、Read，还可以停下来说明限制。官方没有确定性 fallback 策略。

诊断与工具事件怎样精确交错

编辑结果、诊断注入、hooks 与下一次模型请求的精确排序需要一次获准的隔离会话实验。
