伴页 · IDE capability matrix

同一条路，两种工作台

VS Code 把 Claude 做成图形面板，计划批注和改动审阅都留在编辑器里。JetBrains 把插件接到独立 CLI，工作从终端起步，diff 可以回到 IDE。

选择 VS Code 时，你得到更完整的图形审阅面。选择 JetBrains 时，终端仍是主入口。两边共享的会话桥由 UI-04 解释。

01 · terms

先认清三个落点

本页看的是用户动作最后落在哪个界面。会话怎样连接、令牌怎样鉴权和选区怎样穿过本地服务，都由 UI-04 继续讲。

图形面板

VS Code 扩展默认打开它。提示与会话入口都在面板里，计划和 diff 也在编辑器中审阅。

独立 CLI

JetBrains 插件靠它运行。VS Code 的终端入口是否复用扩展所带 CLI，必须按实际扩展版本核对。

宿主 IDE

它掌握选区与活动文件，也处理快捷键和原生 diff。插件把这些入口接给 Claude Code。

02 · sequence

一次动作怎样分叉

用户从安装走到审阅，中间有四个检查点。plan 与 default 两个配置值把流程送往不同审阅支路，权限仍决定改动能否继续。

01

先让插件和运行入口都就位

VS Code 安装扩展后获得图形面板。JetBrains 要求独立 CLI 与插件同时存在，装完插件还要重启 IDE。VS Code 的最低宿主版本和终端 CLI 打包方式缺少与 2.1.247 配对的冻结资料，本页不作确定断言。

O + I
02

用户选中代码并发送提示

VS Code 可以自动附上高亮文本，也能隐藏选区。JetBrains 连接后会共享当前选区或活动标签页。两边都有插入文件引用的快捷键。

O
03

当前模式选定审阅支路

选用 plan 时，VS Code 会打开完整 Markdown 计划并允许行内评论，JetBrains 沿用 CLI 的审阅与批准。选用 default 时，流程跳过计划文档，等文件改动进入 diff。

O + I
04

分支各自在审阅门停住

plan 等用户批准计划。default 下，VS Code 展示并排差异；JetBrains 则按 Diff tool 使用 IDE viewer 或 terminal。批准或接受让对应分支继续，拒绝会停掉这次应用。

O

安装
I · 基线待核

安装扩展即可使用图形面板。官方在线资料对最低宿主版本和终端 CLI 打包方式出现过冲突；没有 2.1.247 同日快照，本页不固定这两项。

双件套

先装独立 CLI，再装 Marketplace 插件并重启。插件不自带 CLI。

上下文选择
可见开关

自动看见高亮文本。用户能隐藏选区，也能插入带路径和行号的引用。

规则阻断

连接时共享选区或活动标签。匹配的 Read deny 会挡住选区和活动文件提示。

Diff
明确交互

default 提供并排差异。用户能接受或拒绝，也可改写建议稿后继续给指令。

位置可选

Diff tool 可选 IDE viewer 或 terminal。官方没有写出与 VS Code 相同的按钮组。

Plan review
专用文档

计划作为完整 Markdown 文档打开，支持行内评论，批准后才进入改动。

终端审阅

Plan 沿用 CLI 的审阅与批准。官方 JetBrains 页面没有写专用图形计划批注面。

Terminal handoff
O + I · 可切换

useTerminal 可把入口切到终端。集成终端能否直接调用扩展所带 CLI 要按扩展版本核对；外部终端用 /ide 接回。

原生入口

常规用法就是在 IDE 终端运行 claude。外部终端同样通过 /ide 连接。

快捷键
焦点与会话

Cmd 或 Ctrl 加 Esc 切焦点。再加 Shift 可开新会话标签，Option 或 Alt 加 K 插入引用。

启动与引用

Cmd 或 Ctrl 加 Esc 快速启动。Cmd 加 Option 加 K，或 Alt 加 Ctrl 加 K 插入引用。

平台限制
宿主门槛

Restricted Mode 不工作；缺少对应预编译二进制时会报告 unsupported platform，系统也可能先截走 Cmd 加 Esc。

部署位置

Remote Development 要装在远端 host。WSL2 的 NAT 或防火墙可能挡住 IDE 检测。

04 · limits

五个地方会停下来

账户还没有准入

两类 IDE 第一次运行都要登录。直接使用 Anthropic 服务时，需要付费 Claude 订阅或 Claude Console 账户，不要求另填 API key。VS Code 官方还列出 Amazon Bedrock、Google Cloud 的 Agent Platform 等第三方提供商入口，认证与计费随后服从对应提供商。O

CLI 不在 PATH

JetBrains 会直接无法启动 Claude Code。VS Code 的图形面板与终端入口不是同一项保证；当前扩展能否把所带 CLI 暴露给集成终端，需按版本核对。O + I

上下文被用户或规则挡住

VS Code 的隐藏开关和 JetBrains 的 Read deny 都会让下一次提示少带一部分编辑器上下文。O

审阅尚未批准

plan 等计划批准，default 等 diff 决定。自动编辑模式减少停顿，也会扩大 IDE 配置文件被改写的风险。O

宿主或连接错位

JetBrains 插件装在本地 client、WSL2 网络受阻或外部终端没有 /ide 时，原生 diff 和选区共享都不会接上。O

06 · implementation

2.1.247

固定基线来自 2026-08-27。官方索引当日有 202 个入口。2.1.246 已修复 VS Code 恢复 Plan 模式的问题，目标版本包含这项修复。

在线 IDE 文档会继续更新，官方没有提供与 2.1.247 同日冻结的两类插件兼容表。最低 VS Code 版本与终端 CLI 打包方式在审查前后出现过冲突，本页撤掉固定答案。页面只把稳定的官方差异当作 O；JetBrains 专用图形计划批注面继续列为未知。

公共 session bridge 留在 UI-04。本页只处理宿主、入口、视图和平台限制，是非计数 companion。

07 · unknowns

还缺五块证据

  1. 2.1.247 与基线当日两类插件的精确版本配对，包括最低 VS Code 版本和终端 CLI 打包方式。
  2. JetBrains 各 IDE 处理部分接受、冲突和文件已变化时的统一行为。
  3. JetBrains 是否在某个插件版本里提供官方未写明的专用图形 plan review。
  4. VS Code 用户改写建议稿以后，插件传回 Claude 的具体差异格式。
  5. 不同键盘布局与系统级占用下的冲突，以及用户自定义映射后的结果。

08 · sources

一手来源与复现办法

  • VS Code 官方文档，证明 VS Code 这一列的七个操作面
  • JetBrains 官方文档，证明 JetBrains 这一列的入口与限制
  • 权限模式官方文档，证明 JetBrains 沿用 CLI 的 Plan 审阅与批准
  • Claude Code 官方 changelog，限定 2.1.247 与相邻版本变化
  • Anthropic 官方仓库的 2.1.247 changelog 快照，证明目标版本标签
展开安全复现步骤
  1. 建一个不含私人内容的一次性仓库，固定 Claude Code 2.1.247，并记录两类插件版本。
  2. 分别安装官方插件。JetBrains 另装独立 CLI。
  3. 用 default 模式新建会话；选中两行无敏感信息的文本，再用隐藏开关或 Read deny 重发。
  4. 请求改一个字面量，记录 diff 的位置，分别接受和拒绝，并比较文件哈希。
  5. 进入 Plan，记录计划出现位置、批注入口和批准后的文件哈希。
  6. 从集成终端和外部终端重复连接，只保存匿名结果，不保存提示、会话 ID、令牌或 transcript 名。
本页只比较七个操作面。会话桥的连接、鉴权、选区传输与会话历史统一回到 UI-04 主页面。
