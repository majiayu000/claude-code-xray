CORE-02 · 工具执行层、结果整形与失败分类

校验通过以后，工具才有资格执行

Claude Code 先核对工具名、schema 和工具专属条件。合格调用随后经过 PreToolUse 与正常权限流，获准后才会分派实现。原始输出会被收进有大小边界的结构化结果。输入拒绝、运行失败、abort 和用户取消各有自己的返回路径。

O官方把校验、hook、权限、成功与失败事件的先后写清了。I工具名怎样映射到本机具体函数仍未公开，本页只画出必要的分派连接。

01

先分清请求、结果和停止范围

这几个词混在一起，权限拒绝就会被误写成执行失败，用户取消也会被误写成 failure hook。

CALL

工具请求

模型提交工具名、输入对象和调用 ID。模型为何选它由 CORE-01 解释。

GATE

执行前门禁

名称与输入先校验，随后才轮到 PreToolUse 和权限流。

SHAPE

结果整形

实现产生的内容被整理成工具专属结构，超大内容会截断、分页或落到工作文件。

ABORT

中断型失败

failure hook 的 is_interrupt 表示错误以 abort 进入 Claude Code，用户按键取消走另一条返回路径。

CANCEL

用户取消

运行中工具被用户取消时，hook 不触发。中断说明直接放进工具结果。

RETRY

下一步选择

错误回到循环后，Claude 可以改参数，也可以换工具。官方没有给所有内置工具承诺统一自动重试。

O官方契约

Anthropic 文档、帮助、changelog 与官方仓库。

L本机证据

版本、帮助、安装文件与匿名静态标记。

R真实实验

本页没有。模型调用会消耗订阅额度或产生按量费用，本轮没有启动。

I研究推断

只补官方未公开的实现连接，保留不确定性。

02

一次调用要过八个位置

O时间从模型已经提交调用开始。第三、四步是本页必须保留的门，执行不能越过它们提前发生。

01 RECEIVE

接收调用

Claude Code 拿到 tool_name、tool_input 与 tool_use_id。

02 VALIDATE

三项校验

确认工具名存在，再检查输入 schema 和工具专属条件。

03 PRE HOOK

PreToolUse

hook 可以 deny、ask、allow、defer，也能替换整个输入对象。

04 PERMISSION

正常权限流

deny 和 ask 规则仍要评估。hook 给出的 allow 不能跨过它们。

05 DISPATCH

分派实现

I名称落到 Read、Edit、Bash 等能力。内部注册表没有公开。

06 EXECUTE

实际执行

Bash 启动独立进程，Edit 应用替换，Read 读取内容。

07 SHAPE

分类并整形

成功触发 PostToolUse。执行失败触发 PostToolUseFailure。输出按工具规则限制体积。

08 RETURN

回到循环

结果与调用 ID 关联。Claude 收到它以后再决定继续或停下。

校验拒绝

tool_use_error 直接回到循环。PreToolUse 和 failure hook 都不出现。

PreToolUse 拒绝

调用在 hook 门停止。实现没有启动，后面的权限流无法把它重新放行。

权限拒绝

PreToolUse 已经运行，工具仍不执行，也不会触发 PostToolUseFailure。

03

数据返回，副作用留在原处

PostToolUse 可以改 Claude 最后看到的结果。它在执行后才出现，文件和进程已经发生的变化不会随结果改写而撤销。

进入执行层

  • 精确工具名
  • 通过校验的输入对象
  • 关联调用与结果的 ID
  • PreToolUse 与权限决定
→

离开执行层

  • 成功时带 tool_response
  • 失败时带 error 与可选 is_interrupt
  • 超大内容已截断、分页或改为文件指针
  • 结果送回 agentic loop
OPostToolUse 的 updatedToolOutput 必须符合对应工具的输出形状。替换失败时沿用原结果。替换成功也只改变 Claude 看到的内容。
04

同一句“失败”藏着五条路

先看实现有没有启动，再看错误从哪里来。这个顺序决定 hook 是否出现，也决定后续该检查输入、权限、进程还是用户操作。

05

本机只做静态核对

本轮不发 prompt，不读取私人会话或登录凭据，也不改 hooks 或 settings。结果能确认版本和公开表面，无法升级成端到端验证。

核对结果

  • 版本为 Claude Code 2.1.247
  • 二进制 SHA-256 与固定基线相同
  • 官方索引 SHA-256 与固定基线相同

L静态字符串存在不证明运行时一定走过某条分支。端到端 R 会调用模型并使用当前选中的认证路径，本轮没有启动。

登录与费用边界 本轮没有读取登录凭据，也没有检查当前账号身份，因此不知道这台机器若启动会话会选哪条认证。官方列出三类常见路径。Claude Pro、Max、Team 与 Enterprise 通过 Claude.ai OAuth 登录，用量先计入订阅额度。Claude Console 使用 API 凭据，按 API 用量计费。Amazon Bedrock、Google Cloud’s Agent Platform 与 Microsoft Foundry 使用各自云凭据，token 费用记到云账户。云提供商开关或 API key 还可能排在订阅登录之前，所以已有订阅不能证明一次新实验不会产生额外账单。没有另行确认认证路径、账单归属并取得模型调用授权前，本页不启动端到端 R。
06

公开实现轮廓到哪里为止

工具专属行为有文档，统一注册表没有。页面把公开契约画实，把内部连接留白。

PreToolUse 还能修改输入

updatedInput 会替换整个输入对象。hook 也能让调用进入 ask、deny、allow 或 defer。deny 优先级最高。

Edit 在执行时继续做专属检查

它检查是否读过文件、old_string 是否精确匹配、命中是否唯一。这里的失败发生在工具能力内部。

成功结果也可以后处理

PostToolUse 能增加上下文或替换结果。内置工具的替换值要过输出 schema，副作用已经无法收回。

并行调用各自收尾

自 2.1.161 起，一个 Bash 失败不会取消同批其他调用。每个工具先得到自己的结果，PostToolBatch 再在整批结束后出现一次。

重试没有统一承诺

公开 loop 契约只保证结果回给 Claude。它可能纠正输入、改用其他工具或停止，页面不虚构统一次数和退避。

版本差异

2.1.247
修复超大 hook 或后台 agent 错误输出挤爆上下文，也修复输出文件写入失败后的无界内存增长。

2.1.246
修复 MCP 中断被误报为完成无输出，也让中途被打断的命令显示中断状态。

07

还有五件事不能写死

这些缺口会直接影响调试结论，因此保留在页面上，不用静态字符串把它们补成事实。

内部注册表

工具名到实现的数据结构、函数名和异常继承没有公开。

全量 schema

官方没有发布覆盖 2.1.247 每个内置工具输入、输出、大小上限和错误码的版本化总表。

本机端到端顺序

没有 R，Read、Edit、Bash 与用户取消还没有在新会话里逐项复核。

系统信号映射

POSIX signal、Windows 进程状态与 is_interrupt 的完整对应关系没有公开。

实现级自动重试

除官方点名的特例外，内置工具是否按错误类型自动重试、重试几次和怎样退避仍未知。

安全复现顺序

  1. 先运行 version 与 help，不传 prompt。
  2. 核对版本化二进制和官方 llms.txt 的 SHA-256。
  3. 打开 O1 到 O8，按本页时序和认证费用边界逐项对照。
  4. 只有另行确认认证路径与账单归属，并获得模型调用和会话写入授权后，才安装一次性 hooks 并制造成功、输入拒绝、权限拒绝、执行失败、abort 与用户取消。
