输入仍会送达，只是走不同的线

Claude 忙着时，你的话去了哪里

普通消息先排队，可能在工具结束后插入当前回合，也可能成为后续回合。命令通常等当前回合收尾，少数命令立即执行。/btw 走旁路，interrupt 则提前截断当前路径。

O决定去向的关键有两个。你送进来的是哪类输入，以及 Claude 当时正处在哪个边界。

普通消息工具结束后进当前 turn
或最旧一条开启下个 turn
排队命令当前 turn 结束后
逐条运行
立即命令提交后马上执行
/status 是官方示例
/btw独立旁路回答
主 history 不收录
Esc / Ctrl+C两者都能中断

01 · TERMS

四个词就够用

这里的 turn 是一次用户消息带起的一轮 Claude 工作。排队并不等于一律等到下一轮。官方把工具调用结束也当作普通消息可以进入的时点。

T-01

当前 turn

Claude 仍在生成文字、调用工具或等待这一轮工作收尾。

T-02

工具边界

当前一组工具调用结束。排队的普通消息可以在这里交给 Claude。

T-03

后续 turn

当前轮已经结束，队列里最旧的普通消息成为下一轮输入。

T-04

旁路

/btw 读取已有上下文并单独回答，不进入主会话历史。

02 · SEQUENCE

一条消息的两次机会

O普通消息先等当前工具。工具回来时，它有机会进入仍在运行的 turn。若这一轮已经结束，CLI 才把最旧一条拿来开启下一轮。

T+00
running

Claude 发起工具调用

用户还能继续在输入框打字。输入框与正在流动的回应是两条独立的界面路径。

T+01
queued

用户按 Enter

消息列在输入框上方。这个 Enter 本身不会打断当前 turn。用 Ctrl+X Enter 可明确标记为只排队。

T+02
boundary

工具调用结束

若 turn 还活着，CLI 把普通消息交给 Claude，Claude 可在同一轮调整方向。命令与 shell 命令继续等。

T+03
next

当前 turn 收尾

仍在队列里的普通消息只取最旧一条开启后续 turn。命令和 shell 命令也从这时开始逐条运行。两类输入混排时谁先走，官方没有说明。

03 · FLOW

输入先分类，再谈时间

这张图把官方可见契约连成一条因果链。内部队列对象和远端取消协议没有公开，连接部分保留 I 身份。

USER

文字或语音转写

语音先在 Anthropic 服务转成文字，再插入光标处。hold 默认等待 Enter，tap 可自动提交。

CLI INPUT

提交动作

Enter 采用普通调度。Ctrl+X Enter 明确只排队。立即命令可绕过等待。

ROUTER · I

输入分类

普通消息、命令、shell、/btw 与 interrupt 进入各自路径。内部函数名未知。

BOUNDARY

工具或 turn 收尾

普通消息可在工具结束后注入。命令等 turn 结束。interrupt 提前制造停止点。

DESTINATION

当前轮、下轮或旁路

主消息进入对话链，! shell 命令及输出也进入 conversation context。/btw 留在终端内存线程，退出后消失。

Queued Prompt

它保存用户的转向意图，等工具边界或后续 turn 再交给 Claude。队列可用 Up 取回编辑。

Voice Prompt

它先多走一段音频上传与转写，落到输入框以后仍受同一提交与排队规则约束。复用调度器这一句是 I。

04 · LIMITS

停止有代价，旁路有边界

Esc 会保留已经做完的工作并立即发送队列。Ctrl+C 也能中断运行操作，官方没有交代它随后怎样处理队列。两者都没有自动撤销既有副作用的保证。

动作主 turn历史与上下文权限或失败门
运行中按 Enter继续运行普通消息在工具边界或后续 turn 进入工具不结束时仍需等待，或由用户 interrupt
Ctrl+X Enter继续运行明确标为等待轮次，从不打断需要 Claude Code 2.1.247 或更高版本
Esc当前回应或工具停止已完成工作保留，既有队列随即发送已发生的外部副作用没有自动回滚保证
运行中的 Ctrl+C中断运行操作队列之后怎样处理没有公开无运行操作时，它先清空输入，再按一次退出
! shell排队时等 turn 结束命令及输出进入 conversation context默认自动回答，回答成本与普通 prompt 相同
/btw继续运行主 history 不收录，终端线程退出即失效无工具，看不到未完成回复；缓存温热时仍有回答成本
语音输入取决于最终提交动作转写文字进入输入框Claude.ai 账户、本地麦克风与远端转写服务，组织策略可禁用
VOICE
音频不会在本地完成转写。API key、Bedrock、Vertex AI、Foundry、Web 和 SSH 远端环境没有这条 CLI 录音能力。官方要求没有另列套餐门槛，组织策略仍可关闭它。转写本身不消耗 Claude 消息或 token；文字提交以后，官方没有给后续 prompt 与回答提供同样的用量豁免。

05 · EXPERIMENT

本轮只做了静态核对

L保留的 2.1.247 安装文件哈希与基线一致，五个关键动作名都在。R本轮没有真实交互路径，页面因此保持 documented。

已经核过

  • 2.1.247 安装文件的 SHA-256 完全匹配基线
  • chat:queueSubmit 与 chat:submit 均存在
  • voice:pushToTalk、app:interrupt 与 chat:cancel 均存在
  • 当前默认命令入口已经升级到 2.1.248

刻意没有做

  • 没有启动新的付费 Claude 会话
  • 没有读取私人 transcript 或会话结构
  • 没有请求麦克风权限或上传音频
  • 没有改设置、keybindings 或正在运行的会话

06 · IMPLEMENTATION

静态动作名能证明多少

I动作名支持“界面动作分流”这一解释。它们没有公开队列数据结构、持久化位置或取消协议，所以因果图停在官方可观察边界。

2.1.247

官方 keybindings 文档把 chat:queueSubmit 的最低版本钉在这里。Queued Prompt 本身更早，官方 changelog 在 0.2.75 已记录工作中按 Enter 排队。基线安装物含 voice:pushToTalk，当前官方文档说明 hold 与 tap 的行为；所列证据没有钉住 Voice 或 tap 的首次发布版本。研究时活动入口为 2.1.248，本页仍固定在 2026-08-27 基线。

页面不声明队列写进某个文件。官方没有给出这个落点，本机也没有读取私人会话数据来猜。

07 · UNKNOWNS

七项尚无答案

这些未知项会改变调试结论。它们留在页面上，避免把产品界面行为扩写成未经公开的实现事实。

队列落点

内存结构、崩溃恢复与确切文件位置没有公开。

并行工具栅栏

立即命令名单

跨类型顺序

取消传播

语音竞态

08 · REPRODUCE

获准以后怎样复现

实验只需要匿名序号与时间点。无需保存真实 prompt、音频、路径或 transcript 文件名。

展开六步隔离实验
  1. 在无私人内容的临时目录启动明确版本 2.1.247。
  2. 让 Claude 运行一个持续数秒、无网络、可安全停止的只读工具。
  3. 运行中提交两条带序号消息，观察工具边界和最旧优先顺序。
  4. 分别用 Ctrl+X Enter 与 Esc 重做，比较只排队和中断释放。
  5. 用 /btw 问已有上下文，确认主 turn、工具访问和 history 边界。
  6. 另获麦克风授权后测试 hold 与 tap，让无敏感转写汇入同一队列。
