Runtime switchboard

插件启用以后，接出两条运行线路。

一条把插件根目录里的 bin/ 接进 Bash 的 PATH，等 Claude 需要时才调用。另一条启动 monitor，持续把 stdout 逐行送回当前会话。monitor 会出现在任务面板，用户可以要求取消，会话结束也会收走它。

O这两条出口都以插件已经启用为前提。中途禁用不会截停已经运行的 monitor。通过 claude.ai 组织设置分发的插件另有一条明确限制，不能携带 bin/。

Four labels

先认四个部件

已启用插件

安装与启用已经完成的包。本页从这里接手，不重复 marketplace、依赖求解与 scope 写入。

Executable

位于插件根目录 bin/ 的文件。启用期间，它的目录进入 Bash 工具的 PATH。

Monitor

由插件声明的会话级后台 shell 命令。它持续产出事件，也接受取消和会话结束这两个停止条件。

通知

monitor 写到 stdout 的每一行。Claude Code 把它送给 Claude，界面用描述文字呈现摘要。

O官方契约

Anthropic 直达文档能明确证明的公开行为。

L本机证据

本机程序、帮助或静态文件。本轮入口被环境权限拦住。

R真实实验

本轮没有。任务不允许开启付费交互会话或启动真实 monitor。

I研究推断

只负责连接公开步骤，不能冒充已运行事实。

One enable, two routes

会话装配时分路

O默认 monitor 随会话开始或插件重载启动。延迟 monitor 等到指定 skill 首次派发。Executable 自己不常驻，它只让后续 Bash 调用多一个可解析目录。

01 ENABLED SET

读取已启用集合

插件生命周期页已经决定哪些包可装配。本页不改这份选择。

02 ROOT

定位插件根目录

组件路径和运行文件都以当前版本的插件根目录为界。

03 SPLIT

接出两条出口

PATH 线路等待 Bash，monitor 线路进入进程与通知循环。

PATH 线路

Claude Code 把 bin/ 加到 Bash 工具的 PATH。Claude 后来发出裸命令名时，shell 才解析并运行文件。

  1. 目录进入工具环境
  2. Bash 请求经过权限门
  3. 命令运行并返回结果

Monitor 线路

always 立即启动，延迟型等一次 skill。唯一名称防止重载或重复派发拉起同名进程。

  1. 后台 shell 命令启动
  2. stdout 逐行成为通知
  3. 取消或会话结束后停止
Process line

monitor 怎样把外部变化送回会话

命令在会话工作目录运行。需要插件内脚本时，作者要用插件根目录变量或先切换目录。它无沙箱运行，信任级别与 hook 一样，不能把“后台”理解成“隔离”。

Odescription 会出现在任务面板和通知摘要。每一行 stdout 都作为通知送到 Claude。事件到达时，Claude 可以插入响应，用户仍可继续当前对话。

Gates and stops

三道门会改写运行结果

DISTRIBUTION GATE

组织分发拿掉 executable 出口

OOrganization settings > Plugins 只适用于 Team 或 Enterprise 套餐。claude.ai 会拒绝带顶层 bin/ 的插件；一般 marketplace 或本地插件仍可使用这条线路。

HOST GATE

monitor 只进交互式 CLI

OBedrock、Google Cloud Agent Platform 与 Foundry 没有 Monitor 工具。禁用遥测或非必要流量也会关掉它。项目作用域的 @skills-dir 插件同样不加载 monitor。

PERMISSION GATE

后台命令仍受 Bash 规则约束

OMonitor 沿用 Bash 的 allow 与 deny。它运行时不进沙箱，来源和命令都需要按可执行代码看待。

禁用为什么没有立刻停掉 monitor

O官方明确写明，会话中途禁用插件不会停止已经运行的 monitor。它会继续到会话结束。禁用影响后续装配，不能当成本会话的 kill 开关。

账户换了以后，组织设置还在不在

O这项插件分发需要 Team 或 Enterprise 套餐。组织同步与当前认证身份和组织相连；用户改用组织外账户时，该组织的设置不会下发。直接从 api.anthropic.com 获取服务器设置时，Bedrock、Google Cloud Agent Platform、Foundry 等第三方提供商变量和非默认 ANTHROPIC_BASE_URL 会让客户端跳过获取。不过 Bedrock、Google Cloud Agent Platform、Foundry 与 Claude Platform on AWS 可改走自托管 Claude apps gateway，由已登录 gateway 的客户端取得等价的远程 managed settings。

卸载为什么不能抹掉正在用的旧版本

Omarketplace 插件更新或卸载后，旧版本目录先成为 orphan，后台约十四天后再清理。清理只在至少仍安装一个插件时运行。卸载最后一个插件以后，orphan 会留在磁盘，等到再次安装插件才恢复清理。这个宽限让已经加载旧版本的并发会话继续运行。完整的卸载与 prune 状态机见 EXT-05 主页面。

Local boundary

本轮没有把文档写成实验

只读检查尝试了版本、总帮助、plugin 帮助和安装目录列表。当前执行环境找不到可用的 claude 入口，随后又以权限错误挡住版本与帮助。本页没有把任务给出的 2.1.247 基线改写成 L。

真实 monitor 会启动无沙箱后台进程，还可能让事件触发模型请求。任务禁止开启新的付费 Claude 会话，也不能影响现有会话，这条路径没有安全的 R。

R本轮没有真实实验，页面状态保持 documented。官方契约足以说明公开机制，进程信号、事件合并和热禁用后的 PATH 变化仍留作未知项。

Contract matrix

两条出口的运行边界

部位ExecutableMonitor
启动时点插件启用时把目录接入 Bash 环境，命令调用时才起进程。默认随会话开始和插件重载启动，也可延迟到一次 skill 派发。
用户可见可在 Bash 工具调用中使用裸命令名。description 出现在任务面板和通知摘要。name 只由公开字段表定义为插件内唯一标识。
数据流Bash 输入命令，进程结果回到工具调用。shell 进程的每一行 stdout 进入通知通道。
权限调用发生在 Bash 工具里，仍经过 Bash 权限。沿用 Bash allow 与 deny，无沙箱运行。
停止单次命令按自身退出、超时或后台任务规则收尾。用户要求取消，或当前会话结束。
禁用与卸载热禁用后的 PATH 撤回时序没有公开完整契约。热禁用不停止既有进程。旧版本约保留十四天，清理只在仍有插件安装时运行；最后一个插件卸载后，要等再次安装插件才继续清理。

Open circuits

还有四处不能写死

事件合并

高频、多行与并发通知怎样排队、去重，最后形成几次模型请求，官方没有说明。

进程信号

取消时先发哪种信号、子进程树怎样清、何时强制终止，没有公开契约。

PATH 热撤回

会话中途禁用插件以后，既有 Bash PATH 何时去掉对应目录，文档没有给出时序。

失败与重启

monitor 异常退出后是否重启、怎样退避、任务面板保留多少历史输出，公开说明仍不完整。
