ADM-05 · REQUEST CONTROL DESK

每次模型请求先过企业网关

Claude Code 带着网关凭证和模型名发出请求。网关认出开发者，检查模型权限与个人额度，再把模型名换成具体上游的标识。通过的请求继续流式转发，拒绝时把可读错误送回终端。［O］

01 / TERMS

先分清两套凭证

开发者向网关证明身份。网关再用自己保管的凭证访问模型提供商。客户端无需拿到 AWS、Google Cloud、Foundry 或 Anthropic 的上游密钥。［O］

客户端凭证

企业自建 Claude apps gateway 使用 OIDC 登录后签发的短期 bearer。其他网关也可收 bearer、API key 或动态 helper 的输出。

上游凭证

只留在网关基础设施内。它可能是云角色、provider API key 或工作负载身份。

模型目录

客户端请求 canonical 模型名。网关可按 provider、区域或部署名改写实际 ID。

额度账本

Claude apps gateway 用 Postgres 保存周期内花费、限额和管理审计。

上游故障转移

网关按顺序试上游。指定状态码、超时或缺少模型时才继续下一项。

下文用 Claude apps gateway 说明企业自托管方案怎样执行身份、模型和花费规则。组织已有的其他 gateway 只要符合通用协议也能接入，具体限额与路由实现由该产品负责。

进入主链前，管理员与开发者各做一件事

  • 管理员通过设备管理下发 forceLoginMethod 和 forceLoginGatewayUrl。开发者的登录选择器没有 gateway 入口，个人设置里的地址也不会生效。
  • 地址只能解析到私网，生产入口必须使用 HTTPS。HTTP 只允许 localhost 或 loopback。
  • 开发者用企业账号完成浏览器登录。此后不需要 claude.ai 账号、API key 或订阅，模型费用由组织的上游 provider 账户承担。

［O］

这套入口有明确缺口

  • 无人值守 CI 没有 service-token 登录流，应直接连接 provider。无显示器的远程开发机仍可由开发者在另一台设备批准登录。
  • WebSearch、Remote Control 与一小时 prompt cache 不可用，缓存只用五分钟 TTL。
  • 认证只支持 OIDC。单个 gateway 不支持多个 OIDC issuer，Windows 也不能作为 gateway server。

［O］

02 / SEQUENCE

一次模型请求的五个时点

网关已经启动，管理员已经下发地址，开发者也已经登录。单轮请求只走这一条状态链，待认证请求 → 已绑定企业主体 → 已判定模型与额度 → 已转发或拒绝 → 结果回到 Claude Code。

T0 · 客户端

发模型请求

Claude Code 带 gateway bearer、模型名、版本与能力头，把请求送到已配置的私网地址。［O］

T1 · 网关

绑定身份与模型

网关从 token 读用户和组，再执行服务端 availableModels。凭证无效停在 401，模型未获准停在 400。［O］

T2 · 网关

检查个人额度

一次 Postgres 查询得到有效 cap 与周期花费。超额便停止转发，返回不可重试的 429。［O］

T3 · 网关与上游

改写并流式转发

网关换成上游模型 ID，按顺序尝试 provider。获准的 SSE 与 ping 持续回到客户端，特定故障才切下一项。［O］

T4 · 停止

记账或返回错误

成功流结束后按 token 用量记账。失败则保留可恢复语义，Claude Code 显示错误，并按错误类型重试、降级或停下。［O］

04 / LIMITS

额度先拦，费用后记

每个推理请求先查到期内花费。超过任一有效 cap 就停在网关。通过的请求完成后再按 token 用量累加，所以这套数字用于花费熔断，正式账单仍需对 provider 报表。［O］

75% / 95%

接近上限

2.1.225 及以后，客户端读取成功响应里的统一限额头，在两个阈值各提醒一次。

429

已经超额

响应带 billing_error、重置时间、retry-after 与 x-should-retry false。Claude Code 直接显示 gateway 文案。

2 s

账本不可用

Postgres 预查超时默认放行。管理员可切换 fail closed，让请求收到 spend limit unavailable。

05 / EXPERIMENT

本地假网关接住了一次 429

实验没有联网，也没有使用真实凭证。2.1.247 以 bare、无持久化、空工具模式向 127.0.0.1 发送一个点号。假网关只记录匿名字段，随后返回不可重试的 429。［R］

先核静态基线

保留的本机二进制报告 2.1.247 (Claude Code)。SHA-256 与给定基线完全相同。［L］

gateway --help 公开了 --config <path>，说明该版本带企业认证与遥测 gateway 入口。［L］

POST /v1/messages?beta=true

x-api-key present · authorization absent

anthropic-version present

这次实验只证明客户端会把 API key 放入对应请求头、保留模型名并把网关 429 显示出来。它没有证明真实 OIDC、provider 改写、Postgres 额度判定或跨上游故障转移。页面因此保持 documented。

06 / IMPLEMENTATION

部署要守住的契约

Claude apps gateway 把协议翻译和限额实现装在同一个二进制里。其他 gateway 也能接 Claude Code，但运营方必须自己维护下列转发约定。［O］

启动与状态文件
gateway.yaml 定义监听、OIDC、session、Postgres 和 upstreams。秘密从环境变量或挂载文件展开。进程启动时校验 schema，关键项失效便退出。Postgres 保存设备授权、额度计数与管理审计。［O］
协议与流式传输
Anthropic Messages 路径至少提供 /v1/messages，并原样转发 anthropic-version、anthropic-beta 和请求体。SSE 与 ping 要边到边发。包完整缓冲会让客户端停住，长思考时丢 ping 也会触发超时。［O］
错误与自动恢复
普通第三方 gateway 应保留上游错误体，因为 Claude Code 会按错误文案识别可降级能力。Claude apps gateway 对云厂商可能泄露账号信息的错误做安全归一，并用 capability_rejected token 保留恢复语义。［O］
2.1.247 的版本边界
gateway 子命令从 2.1.195 提供。额度警告和带重置时间的 429 从 2.1.225 提供。2.1.233 增加云上游安全错误语义。2.1.248 才让模型发现请求同时发送两个认证头，2.1.247 仍按凭证类型只发一个。2.1.251 的 /usage 花费条不属于本页基线。［O］
07 / UNKNOWNS

这轮仍然没有验证的地方

这些缺口会影响企业部署判断，现阶段保留为未知，不用本地假网关补成运行事实。

真实企业登录

没有 IdP、私网域名和 TLS 证书，未验证设备登录、token 刷新与离职后的实际失效延迟。

真实 provider 改写

没有云账号与获准模型，未验证 canonical ID 到 Bedrock、Google Cloud 或 Foundry ID 的现场请求。

并发额度一致性

没有 Postgres 与并发流量，未观察许多 agent 同时越过 cap 边缘时的交易顺序和提示时间。

组织自己的第三方 gateway

它的 WAF、错误包装、缓存和重试策略不在本机。协议文档能给要求，不能替代该部署的验收。
