01 / TERMS

矩阵里有四条不同的线

认证说明你凭什么发请求。计费说明谁收钱。模型门说明能调哪一个部署。组织门还能在启动前或请求处收窄选择。

ENTRY

登录入口

浏览器 OAuth、Console 邀请、第三方平台向导或云端环境变量把用户带到对应路线。

CREDENTIAL

凭据形态

订阅 OAuth、Anthropic key、AWS 与 GCP 凭据链、workspace key、Azure key 或 Entra token 各自归平台管理。

BILLING

计费主体

费用会落到 Claude 订阅组织、Anthropic Console 组织、AWS、GCP、Azure 或 AWS Marketplace。O

MODEL GATE

模型门

账号默认只是起点。管理员 allowlist、云端启用、区域、配额和部署名继续决定可见结果。O＋I

02 / SEQUENCE

从选路到第一次可用

这段只走管理员选型和可用性检查。多个凭据怎样竞争、登录怎样续期和切换怎样持久化，由 ADM-02 继续解释。

管理员或个人选路线

先定订阅、Console、AWS、GCP 或 Azure，费用归属随之确定。

平台准备身份

邀请成员、分配角色，或准备云账号、项目与 workspace。

用户交出凭据

OAuth、API key 或云 SDK 凭据链向所选平台证明身份。

模型门逐项检查

组织策略、模型批准、区域、部署名、IAM、RBAC 与配额都可能挡住请求。

首个请求给出结果

成功后开始计量。失败则停在登录、权限、模型或配额对应的位置。

03 / FLOW

一条路线上的四个角色

用户只在本机启动 Claude Code。身份提供者、模型提供者和付款组织可能属于同一家公司，也可能分在不同平台。

USER

用户

选择入口并提供被批准的身份。用户能看见错误，通常无权补组织席位、云部署或配额。

CLAUDE CODE

本机客户端

按所选 provider 组织请求，并把模型名换成对应平台识别的 ID、推理配置或部署名。

PROVIDER

身份与模型平台

Claude.ai、Anthropic API、AWS、GCP 或 Azure 核验凭据，并检查目标模型能否调用。

PAYER

付款组织

订阅席位消耗包含额度或 credits，API 与云路线由所属账号按量结算。

O＋I 同一个人可以同时属于多个组织。当前请求由哪份凭据获胜仍要回到 ADM-02 认证来源选择与凭据生效。

订阅停在席位或额度

账号要有可用计划。Team 与 Enterprise 还可能受席位类型、管理员开关和组织策略影响。

Console 停在邀请或 key

成员先接受邀请，再由角色决定能创建哪类 key。费用进入 Console 组织。

Bedrock 停在模型与 IAM

AWS 身份有效以后，模型启用、区域与调用权限仍要逐项成立。

Platform on AWS 停在 workspace

Marketplace 订阅、AWS 关联组织、workspace ID 与凭据缺一项，请求都会失败。

Google Cloud 停在项目

项目要启用 API，目标模型要获批，区域有配额，当前身份还要具备 IAM 权限。

Foundry 停在部署

Azure 身份过关后仍需实际部署名和 RBAC。缺省模型不可用时会报错。

05 / EXPERIMENT

本页停在 documented

官方契约已经能支撑比较。真实账号实验会触发登录、云权限或付费模型请求，本轮没有授权，当前 shell 也找不到可调用的 claude 命令。

O＋L

指定的 ADM-02 页面元数据和官方契约已经核对。没有 R，页面不写 verified。

L

CLI 不在当前 PATH

claude --version 与 claude --help 都返回 command not found。这只说明当前研究 shell 无法调用它。

L

主页面边界一致

指定的只读 ADM-02 页面写明 2.1.247 和 documented，并把凭据竞争与登录切换留在自己的主链。

R

远端路径没有运行

没有登录、查询状态、创建 key、读取私人配置或发出模型请求，也没有产生费用。

06 / DETAILS

会改变选型的细节

展开项都来自官方契约。它们解释矩阵里的例外，不延伸认证状态机。

订阅与 Console 分开计量

Claude 订阅凭据按计划或组织规则计量。Console API key 按量计费，付费订阅不会自动替 Console API 账单付款。

O / Authentication 与 Deployment overview

组织限制只覆盖能核验的身份

Claude.ai 登录可核验组织成员身份。环境 key 无法核验时会在启动处被挡住，云 provider 则交给云 IAM。

O / Authentication

模型别名会随 provider 解释

同一个别名在不同 provider 上会映射成不同 ID。官方建议团队部署固定版本，避免升级后集体移动。

O / Model configuration

第三方 provider 的回退并不一致

Bedrock 与 Google Cloud 会在内置默认不可用时提示并做本次启动回退。Foundry 没有同类启动检查。

O / Model configuration

Claude Platform on AWS 是独立组织

AWS Marketplace 会建立一个 AWS 关联 Anthropic 组织。既有 Console 组织的 key 不能直接搬过去使用。

O / Claude Platform on AWS

网页端跟着订阅凭据

Claude Code on the web 要求 Claude.ai 登录。Console key 和第三方 provider 不会把这项订阅能力带过去。

O / Feature availability

2.1.247 位于两次模型检查改动之后

2.1.219 改过若干 provider 的默认模型，2.1.211 改过显式选择模型时的启动检查。本文固定 2.1.247，也排除官方注明 2.1.248 才开放的三方 provider 能力。

安全复现办法

  1. 固定 Claude Code 2.1.247，记录二进制散列和研究日期。
  2. 在获准的隔离环境里一次只配置一种入口，并给 Console 或云账号设置费用上限。
  3. 匿名记录 provider 类别和可见模型族，不保留邮箱、组织 ID、workspace ID、资源名或 token。
  4. 发出一条最小请求，记录成功或失败类别，再撤销临时凭据并核对账单归属。
  5. 取得 O、L、R 三层互证后，再评估 verified。
