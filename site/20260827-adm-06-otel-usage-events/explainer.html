使用事件、OpenTelemetry 与隐私边界

动作变成记录，出口由你指定

启用以后，Claude Code 会把会话启动、prompt、API 请求和工具结果等动作变成指标或事件，先按默认规则隐藏正文，再分批送往你配置的观测后端。邮箱、账户标识和终端类型等身份字段仍可能随记录出现。内容开关一旦打开，prompt、命令、路径和工具输出都可能离开本机。

先抓住边界

组织 OTel 发往 Claude Code 最终解析出的 exporter endpoint。Anthropic 的运营遥测另走自己的数据流。默认脱敏仍会保留身份元数据，OAuth 邮箱在可用时会进入标准属性。

Terms

四个名词就够用

指标

按时间累计的数值。会话数、token、成本估算和代码行数属于这一类，默认 60 秒导出一次。

事件

一次动作的结构化记录。prompt 提交、API 请求、工具结果和权限决定都有各自的生成时点，默认 5 秒一批。

Trace

把一次 prompt 下的模型请求和工具调用串成 span。2.1.247 仍属 beta，默认关闭，并有单独的内容风险。

下游消费者

Collector、SIEM、时序数据库与团队报表负责保存、查询和告警。Claude Code 只生成并导出原始记录。

本页不展开

成本优化、权威账单、团队采用率和 ROI 都依赖这些记录，却有自己的统计口径。它们只在这里出现一次，作为导出后的消费者。

O 成本字段是估算值，权威账单要回到 API provider。

Sequence

一轮会话里的生成顺序

下面是官方事件契约允许确认的先后。一个 prompt 可能带出多次 API 请求与多个工具动作，图中的中段会重复。

启动前配置

打开 telemetry，再为 metrics、logs 或 traces 选择 exporter。

会话开始

session counter 增加一次，并带上可用的标准属性。

提交 prompt

生成 user_prompt。正文默认隐藏，只保留长度。

模型请求

每次 API 请求生成 api_request，失败放弃后生成 api_error。

工具分支

拒绝只留下 decision。工具执行完成才有 tool_result。

批量导出

events 与 metrics 按各自 interval 发往所选后端。

O 同一轮的事件可用 prompt.id 归组，再用 event.sequence 排序。借 transcript 内部字段做更细 join 会随版本变化。

Flow

三段数据流，两个控制点

Claude Code会话动作触发 metrics、events，beta trace 另行启用。
›
字段与内容门默认正文 redacted。身份属性和显式内容开关决定记录里还有什么。
›
Exporter 与后端console、Prometheus 或 OTLP。endpoint、protocol 与 credentials 决定出口。
O 与 I 的分界 官方说明 exporter 失败会留下 debug 诊断，却没有承诺失败时是否阻塞主会话、何时丢弃或退出时一定 flush。本页把这些都留在未知项。
2.1.247 的管理边界 Managed settings 会移除一批冲突的 endpoint、protocol 与 credential，exporter selector 还要逐项设置。官方到 2.1.251 才修复低作用域 beta trace endpoint 绕过固定 collector，以及项目设置开启详细 tracing 或 raw API body logging 的问题。2.1.247 不能视为已经可靠锁住目的地和内容面。

Fields

先认事件，再看它带了哪些字段

O 记录跟着动作生成。动作发生到哪一步，相应的记录就在那一步出现。排查缺失事件时，先确认动作有没有走到生成点，再检查 exporter。这样可以避免把“工具被拒绝”误报成“tool_result 导出丢失”。

记录生成条件读记录时要留意什么
session counterClaude Code 会话开始时增加。OAuth 登录可带邮箱、Claude 账户与组织字段。直接 API key、Bedrock、Vertex 或 Foundry 没有 Claude 账户字段，只填 user.id 与 session.id。
user_prompt用户提交一次 prompt 时生成。默认只留下长度，正文写成 redacted。同一个 prompt 引出的后续动作可用 prompt.id 归在一起。
api_request 与 api_error每次模型 API 请求都有 request。内部重试最终放弃后才有 error。api_error 记录的 attempt 是总尝试数。它结束的是这次请求，不能单凭这一条判断整个会话随后也停止。
tool_decision 与 tool_result权限决定和工具执行结果分开生成。拒绝调用时没有 tool_result。要判断工具有没有真正执行，应先看 decision，再找 result。命令、路径、URL 与输入通常受工具详情开关控制。2.1.214 起另有 Desktop 例外。

关联顺序

prompt.id 用来收拢同一轮 prompt 带出的请求和工具动作，event.sequence 给会话内记录排序。一个 prompt 可以触发多次请求，也可以触发多个工具动作，中间几步重复出现属于正常情况。

缺失怎样解释

O 被拒绝的工具调用按契约不会生成 tool_result。Collector 不可达时则要查看 debug 诊断。I 官方没有公开队列上限、丢弃规则与退出 flush 保证，因此缺一条记录时还不能直接断言它在哪一段消失。

Privacy limits

默认隐藏内容，身份仍然可见

字段层默认状态隐私判断
标准身份OAuth 可用时包含邮箱、账户与组织标识，还会有安装标识和终端类型。邮箱没有客户端关闭开关。直接 API key 或云 provider 没有 Claude 账户字段。组织仍需在 telemetry backend 过滤或脱敏。
prompt 与回复默认只记录长度，正文显示为 redacted。分别受 prompt 与 response 开关控制。response 开关未设置时会跟随 prompt 开关。
工具细节参数与输入通常默认不记录。Desktop 自有会话里的内置 MCP server/tool 名称是例外。2.1.214 起，这组 host-authored 名称会留在 decision/result 的 tool_parameters，即使 details 关闭。details 打开后还可出现 Bash 命令、路径、URL 与输入。
Raw API bodies默认关闭。打开后可含系统 prompt、完整历史和工具结果。文件模式会在指定目录写未截断正文。
默认

正文 redacted。仍有身份、长度、时间和行为元数据。

Prompt 或回复

用户输入或模型文本进入组织后端。

Tool details

命令、路径、URL、搜索模式和工具参数可能出现。

Raw bodies

完整会话历史可能进入事件或本地文件。风险最高。

O Extended thinking 在 raw API bodies 中仍会脱敏。I 这条保证不能替部署方决定邮箱、命令和正文在后端保留多久。

登录方式会改字段

O OAuth 可带邮箱和 Claude 账户字段。直接 API key、Bedrock、Vertex 与 Foundry 只带安装侧的 user.id 和会话标识。当前官方文档说 gateway 会带 IdP subject、邮箱和 groups，本页没有在 2.1.247 上做运行核对。

Anthropic 运营遥测另有两路

O Usage metrics 记录延迟、可靠性与使用模式，由 DISABLE_TELEMETRY 关闭。Error reports 可能含已脱敏的错误消息与堆栈，由 DISABLE_ERROR_REPORTING 关闭。两者都不等同于组织 OTel。

Local evidence

核到二进制，没有启动会话

只读静态核对
<2.1.247 binary> --version
shasum -a 256 <2.1.247 binary>
<2.1.247 binary> --help
strings <binary> | rg <allowlist>
  • L 版本输出为 2.1.247。
  • L SHA-256 与基线给定值一致。
  • L 二进制包含启用开关、三类 exporter 和五组内容开关。
  • R 缺失。没有发 prompt，没有连接 collector，也没有读取私人会话。

这能证明本机指定版本带有配置入口，不能证明运行时字段、默认值或失败行为。

验收边界 取得 R 需要登录可用的模型 provider 并提交合成 prompt，这可能产生订阅或 API 用量。本轮没有获准执行。Desktop、gateway、Bedrock、Vertex、Foundry 与 self-hosted runner 也都没有做真实导出核对。

Implementation boundary

2.1.247 有两处版本陷阱

诊断标签

当前文档把自有 collector 故障写成 [3P telemetry]。官方 changelog 说明 2.1.248 才把 Anthropic exporter 故障改标为 [Anthropic telemetry]。

子进程隔离

Claude Code 不把 OTEL_* 传给 Bash、hooks、MCP 和 language server。子程序要另配自己的出口与凭据。

管理员锁定

2.1.251 修复了 beta trace endpoint 与详细 tracing/raw body logging 的低作用域绕过。这个修复晚于本页基线，2.1.247 的目的地与内容面不能写成已可靠锁定。

版本结论 在 2.1.247 上只看到 [3P telemetry] 不能直接断言组织 collector 有问题。要结合 endpoint、exporter 配置和相邻 debug 行判断。

Unknowns

官方还没有承诺这些运行细节

Collector 长期不可达时会怎样

队列上限、退避、丢弃和内存策略没有公开。本页不猜。

退出时是否保证 flush

官方给了默认导出间隔，没有给正常退出或中断时的 flush 保证。

Exporter 失败是否影响主会话

官方只说明 debug 诊断，没有说明它是否改变主会话退出码、工具结果或停止条件。

后端会保留数据多久

组织 OTel 发往部署方自己的后端。邮箱、命令与正文的保留期由那套部署决定。

冻结在 2.1.247 的完整字段表在哪里

Monitoring 页面持续更新，官方没有提供该版本的独立冻结页。本页排除了明确要求 2.1.248 或更高版本的字段。

Sources and reproduction

一手来源与复现入口

安全复现

固定 2.1.247，用临时目录与 loopback collector，先关闭所有内容开关。还需获准登录模型 provider，并接受提交合成 prompt 可能产生的订阅或 API 用量。再按 prompt.id 与 event.sequence 核对。

失败复现

把 endpoint 指到未监听的 loopback 端口，用 --debug-file 写临时日志。分别正常退出与中断，记录诊断标签、主会话状态和最后收到的 sequence。完成后删除临时文件。
