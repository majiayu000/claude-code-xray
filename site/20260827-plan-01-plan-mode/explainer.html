Plan Mode

AskUserQuestion

ExitPlanMode

04

哪些地方会停，哪些不会

Plan Mode 只给源码写入增加一道强约束。探索命令、交互工具和预先启用的危险模式各有自己的例外。

正常路径

源码写入停在批准前

官方把 reads、shell exploration、plan file 与 source edits 分开。O

探索命令仍受判断

只读集合外的 shell 命令可能由 auto classifier 审核，也可能弹出人工批准。O

问题可超时，批准不会

只有配置过的选择题能空闲后继续。计划批准一直等到用户作答。O

非交互运行通常会阻塞

-p 中两个交互工具都需要宿主通过 hook 提供完整更新输入。单独 allow 无效。O

绕行与停止

选择继续规划

不退出，不执行，计划按反馈重做。

按键直接离开

Shift+Tab 可无批准离开。官方没有把这次动作称为批准。O I

预先启用 bypass

Plan Mode 的写入阻断不再强制，Claude 只剩规划指令约束。O

关闭或中断会话

本页没有真实运行证据，不推断未公开的恢复细节。

bypass permissions 是主链的明确例外，页面把它单列在这里。

公开实现边界与版本差异

官方 hook 字段揭示了计划文件流。内部状态枚举、调度函数和计划目录生命周期没有公开，本页不会靠二进制字符串补故事。

hook 能看见什么

  1. AskUserQuestion 输入含 questions 数组。每题有文字、选项与是否多选。
  2. ExitPlanMode 调用前，Claude 已把 Markdown 计划写入磁盘。
  3. Claude Code 向 hook 注入计划正文和计划文件路径。
  4. 批准后的 PostToolUse 结果含计划正文与文件路径。官方建议直接读返回正文。O

07

仍然不知道的地方

这些缺口会改变复现实验的解释，所以保留。它们没有被状态图悄悄写成确定事实。

计划文件在 2.1.247 本机放在哪里，何时清理

官方只公开 hook 收到计划路径。本轮禁止读取本机 Claude 会话目录，也没有 R，具体目录、命名和清理时机保持未知。

反复继续规划会怎样更新计划文件

原地改写、换文件还是保留版本，官方没有说明。本页只画出计划内容回到规划侧。

无批准按键离开后具体回到哪种权限模式

官方确认可以离开，没有说明所有入口、宿主和可用模式组合下的后继模式。

批准后编辑从哪个内部调度点开始

官方给出可观察结果，批准后切换模式并开始编辑。统一的内部事件名与回合边界没有公开。

问题超时后的自主判断怎样处理关键缺口

官方说 Claude 可以自行继续并稍后重问，没有承诺它会对每类产品选择采取哪种默认行为。
