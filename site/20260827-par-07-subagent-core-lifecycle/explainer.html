02 / SEQUENCE

一次委派怎样走完

交接消息决定子任务从哪里起步。普通 subagent 不会带走父对话历史，也不知道父 Claude 已经读过哪些文件、调用过哪些 skill。父 Claude 要把目标、必要背景、交付形式和约束写进同一条任务消息。消息漏掉的事实不会凭空出现在独立上下文里，子任务只能自己重新查找，或者带着缺口继续工作。O

T0 · 请求

用户点名 subagent，或父 Claude 主动判断任务适合交出去。O

T1 · 交接

父 Claude 调用 Agent 工具，并写一条能独立执行的任务消息。O

T2 · 装载

运行时新建上下文，放入 agent prompt、任务、规则和可用工具。O

T3 · 分流

前台让父对话等，后台让父 Claude 继续处理别的工作。O

T4 · 结束

成功、失败、轮数上限或停止，让这次 run 离开运行态。O

T5 · 交回

前台返回结果。后台在后续 turn 送达完成通知。O

04 / LIMITS

权限先卡住动作，停止再结束这次 run

权限门

  • Agent 工具或某个 agent type 被 deny，任务不会启动。
  • tools 与 disallowedTools 会继续收窄子任务能做的事。
  • 后台普通 subagent 的 built-in 工具池比前台更小。
  • 2.1.247 会把后台审批送到父 session。持续授权会影响整个 session。

停止与失败

  • 用户在 /tasks 按 x 会取消该 subagent，后续消息不会自动唤醒。
  • 父 Claude 用 TaskStop 停下的 subagent，后来收到消息时可以自动恢复。
  • maxTurns 到达后返回 partial。API error 会按失败交回父 Claude。
  • 同时已有 20 个 subagent 在跑时，新的 Agent spawn 默认失败。

/tasks 管的是当前父 session

2.1.247 会在这里保留一段很短的管理窗口。成功的 subagent 完成后会立刻离开输入框下方的 panel，footer 提示用户可在 30 秒内去 /tasks 查看。失败或被停止的行会在 panel 留 30 秒，却会从 /tasks 离开。这里管理的是当前 session 的后台工作，整场会话的 detach、attach、logs 与 stop 另有入口。O

用户按 x 以后，这次停止带有明确的取消语义。父 Claude 后来再发消息，也不会自动把它唤醒。TaskStop 留下的任务则可以被后续消息恢复，两种停止动作不能混用。O

沿用当前 session 的登录与计量入口

subagent 留在同一父 session，不会再开一遍登录流程。它的模型请求沿用该 session 已选中的认证来源。这一判断把官方的 session 级认证说明与 subagent 的单 session 边界接在了一起。Claude Code 支持 Pro 或 Max、Team 或 Enterprise、Claude Console，也支持 Amazon Bedrock、Google Cloud 的 Agent Platform 与 Microsoft Foundry。OI

每次 subagent 运行都会增加模型 token 用量。官方按 token 和当前认证方式记账，没有给 subagent 单列固定附加费。Pro、Max、Team 与 Enterprise 的 /usage 会把 subagent 归因到当前计划用量；Team 和 Enterprise 从成员席位额度扣，Pro 和 Max 先使用订阅内额度。Console 与云提供商按 token 计费给当前组织或云账号。前后台只改变父对话怎样等待，计量入口不随之改变。O

06 / IMPLEMENTATION

公开契约能落到六个部件

这里没有反编译，也没有读取会话文件。结构来自官方公开的输入项、工具池与状态行为。

定义

agent prompt、model、tools、permissionMode、maxTurns 与 background 等配置。

委派消息

父 Claude 把当前任务写成独立消息。普通 subagent 不会自行得到父对话历史。

上下文装载

运行时加入适用的 CLAUDE.md、git status 与预载 skills。Explore 和 Plan 有例外。

工具求交

父会话工具池、subagent 固定过滤、后台过滤与 agent allowlist 共同决定最终可用工具。

运行状态

running 最终走向 success、failed、partial 或 cancelled。前后台影响父对话是否等待。

交回

前台返回给当前等待者。后台完成先进入 notification，再在父会话后续 turn 交付。

07 / UNKNOWNS

这些地方还缺一次安全实跑

任务状态怎样落盘

官方说明了面板行为和 resume 能力，没有公开 2.1.247 的 task record、agent ID 与 notification 文件格式。本轮没有打开私人 session 数据。

多个完成通知怎样排队

几乎同时完成的后台 subagent 会按什么顺序通知、是否合并、失败后怎样重试，现有一手材料没有给出稳定契约。

Ctrl+B 的组合状态

嵌套 subagent、权限提示正在显示、终端失去焦点等状态叠加时，TUI 怎样响应，需要在 2.1.247 的隔离会话里观察。

每次交回多少 token

一般计费入口已经明确，前台结果和后台通知各自增加多少 token，长输出扫描和摘要实际花费多少，官方行为页没有给出可直接套用的数字。
