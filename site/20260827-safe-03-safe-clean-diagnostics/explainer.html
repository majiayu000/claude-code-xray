SAFE-03 · documented · Claude Code 2.1.247

先减载，再一件件装回去

交互式 Claude Code 启动异常时，先用 safe mode 关闭本次会话的自定义项，故障仍在，再用空配置目录和无项目配置的启动目录做 clean 比较，随后每次只恢复一件，重复同一个触发动作，故障第一次回来就停。

01 / TERMS

三种启动面，各回答一个问题

我先对照官方 debug 指南、CLI reference 和冻结版 help，safe 与 clean 的隔离层次并不相同。

NORMAL

正常启动

用户、项目、本地与组织配置按作用域参加加载。它能复现故障，却很难直接说明是哪一层造成的。

SAFE

Safe Mode

本次会话关闭个人和项目自定义项。组织 policy 仍在，按 policy 配置的 hooks、status line 与 file-suggestion commands 仍会生效。认证、模型、内置工具和权限机制继续工作。

CLEAN

Clean 比较

把配置根目录指向新的空目录，并从没有项目配置的目录启动。惯用用户与项目配置都不参加，临时目录会保存自己的 onboarding 状态。

BOUNDARY

边界状态

clean 仍受配置目录之外的组织管理设置影响。macOS Keychain 凭据也可能延续，Linux 与 Windows 通常会重新要求登录。

02 / SEQUENCE

一次诊断按比较结果往下走

每轮都用同一个启动目录、同一版本和同一触发动作。否则差异来自哪里，马上又会说不清。

00
先固定

写下最短症状

记录版本、启动目录类别、出现时机和最短触发动作。不要先改真实配置。

01
第一轮

运行 safe mode

故障消失，只能说明原因位于被关闭的自定义面。回到正常会话，用 context、hooks、mcp、status 等观察命令确认实际加载项。

02
条件进入

运行 clean 比较

safe 中仍有故障，或 settings 本身也可疑，再换空配置根目录和无项目配置的启动目录。看到首次设置界面，说明新的临时配置目录已经生效。

03
逐项恢复

每轮只放回一件

使用配置副本，一次恢复一个文件或一类扩展。重启后重复第 00 步的动作。

04
停止位置

第一次复现就停

刚恢复的单元成为当前嫌疑项。先修它或继续拆小，别让后续项目把比较结果搅在一起。

03 / FLOW

被读入的东西怎样变化

这张表只写官方公开的可观察边界。它没有猜测二进制内部先读哪个函数。

NORMAL
惯用配置

用户、项目、本地配置及其自定义项参加加载。

外部边界

组织策略与环境变量也可能影响启动。

SAFE
本次关闭

个人和项目的指令、skills、plugins、hooks、MCP、commands、agents、styles、workflows、themes、keybindings 等。managed plugins、managed skills、managed CLAUDE.md 和 policy MCP 也不加载。

仍然存在

认证、模型选择、内置工具和权限机制。policy 配置的 hooks、status line 与 file-suggestion commands 继续生效。

CLEAN
换根目录

用户配置、hooks、MCP、plugins、memory 与 onboarding 状态进入新的临时配置目录。

换启动目录

避开项目的 .claude、.mcp.json 与 CLAUDE.md。配置目录外的组织策略仍可进入。

clean 中消失

原因仍在真实用户配置或项目配置范围内。开始逐项恢复。

clean 中仍在

停止搬动用户与项目文件。检查组织设置、环境变量，再转向安装或运行故障。

04 / LIMITS

权限门和停止条件

诊断的价值来自少改东西。safe 与 clean 都是比较面，不能替用户决定删除配置，也不能绕过组织策略。

不要删真实配置

官方 clean 路径使用新的配置根目录。恢复阶段优先复制到临时目录，保留原件和回退点。

policy 仍是权限门

safe 中，policy 配置的 hooks、status line 与 file-suggestion commands 仍会生效。clean 也会读取配置目录之外的 managed settings，并可能重新获取 server-managed settings。

doctor 分成两个入口

shell 的 claude doctor 是只读诊断，不启动会话。交互式 /doctor 能提出修复，实际修改前仍要确认。

Bare Mode 留在页外

2.1.247 help 显示 Bare 面向脚本快速启动，另有 keychain、认证和显式上下文规则。它不参加本页的交互恢复链。

用量沿用登录方式

safe 与 clean 只改变加载面。发送模型请求后，订阅登录计入原有套餐用量，API key 或云提供商按相应账户计费。官方资料没有列出这两个诊断入口的额外套餐门槛。

本轮没有验证账单

本轮没有启动交互会话，也没有覆盖每种套餐和企业身份。具体账户选中了哪种凭据，可在正常会话用 /status 核对；safe 不会替用户切换计费账户。

停止规则

故障第一次随某个恢复单元回来，就停在这一轮。继续放回其他配置只会扩大嫌疑面。

06 / CONTRACT

公开契约到这里为止

本机 help 说明 safe mode 会设置环境变量，官方配置文档说明 clean 使用另一条配置根目录，内部加载函数和先后顺序没有公开。

Safe 的公开数据流

CLI flag 令本次启动进入 safe 状态，并公开等价环境变量。产品继续走认证、模型、内置工具和权限路径。

Clean 的公开文件流

用户配置根改到临时目录，项目配置由启动目录避开。临时目录随后接收自己的首次设置状态。

07 / UNKNOWNS

仍然不知道的几件事

这些缺口会改变根因判断，所以保留在页面上。

2.1.247 内部怎样依次跳过自定义项

官方只给可观察范围，没有发布精确调用顺序。本轮也没有动态 trace。

help 中 and more 的封闭清单

在线 CLI reference 列得更长，在线页会滚动更新。冻结二进制没有给出一份机器可读的 2.1.247 完整清单。

崩溃前是否已有扩展副作用

这取决于故障发生在启动链的哪个时刻。需要隔离的坏配置样本和真实运行证据。

企业管理组合的保留行为

MDM、文件 policy 与 server-managed settings 的具体组合需要在相应组织环境验证。

每种套餐下的诊断入口

官方资料没有给 safe 或 clean 单列套餐门槛。本轮没有登录，也没有逐一验证 Pro、Max、Team、Enterprise、Console API 与云提供商账户。

CLI 之外的宿主入口

IDE 与 Desktop 是否呈现完全相同的 safe 和 clean 入口，本页没有验证。
