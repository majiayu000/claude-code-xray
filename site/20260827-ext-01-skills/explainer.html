SKILLS · DISCOVERY TO CONTEXT

先看标签，再取正文

在本地 Claude Code 里，程序先把可由模型调用的文件型 Skill 名称和描述编成一份清单。用户点名，或 Claude 判断当前任务匹配以后，完整 SKILL.md 才渲染成一条消息进入会话。支持文件还要等正文说明需要时再读。

手动专用 Skill 的描述不交给模型，只等用户输入完整名称调用。Cowork、cloud、同步 Skills 和 Agent SDK 沿用这套按需思路，来源与执行门另有差别。O

01 TERMS

四件东西，先分开

DISCOVERY

发现

Claude Code 从企业、个人、项目、插件和加入目录里找到候选 Skill，并处理同名项。

LISTING

描述清单

模型可调用项的名称与描述。它有总预算，名称都保留，较少使用项的描述可能先被缩掉。

BODY

正文

调用后渲染的 SKILL.md。它作为一条消息进入上下文，随后不会每回合重读文件。

RESOURCE

支持文件

参考资料、例子与脚本。正文告诉 Claude 在什么情况下读取或运行，文件不会自动全塞进上下文。

02 SURFACES

先看会话跑在哪里

本页后面的六步主链讲本地 Claude Code。远端会话、从 claude.ai 同步到本机的 Skill 和 Claude Agent SDK 仍会先发现描述，再按需取正文；它们拿文件的地方和能执行的内容并不相同。

表面
从哪里发现
正文与执行边界
本地 Claude Code
企业、个人、项目、插件与加入目录
本页主链完整适用，包括参数替换、支持文件与获准的动态命令
Cowork 与 cloud
要以 claude.ai 账号登录，都取账号已启用项，不读本机个人目录；cloud 还取克隆仓库里的项目 Skill 与仓库声明的插件
cloud 在隔离容器中保留本地正文行为；Cowork 会把正文里的动态命令换成禁用占位文本
同步到本机
先用 claude.ai 登录，在非交互运行里明确开启同步，下载后才供本地会话发现
本机会话不执行其中的动态命令，也不自动附上引用文件，不替换项目目录与会话编号变量
Claude Agent SDK
由 settingSources 选择本地文件来源，也可加载本地插件；skills 选项再过滤可见项
描述先给模型，正文仍按需加载；项目和个人 Skill 的 allowed-tools 会生效，SDK 顶层 allowedTools 也能追加预授权；同步 Skill 另按自身规则处理
本地 Skills 随 CLI 和 Claude Agent SDK 在官方列出的各模型提供商上可用，不要求另买 claude.ai 订阅。发起模型请求时仍要有可用认证，可以来自 Claude 订阅、Anthropic Console、云提供商或企业网关；用量和费用跟随所选方案。O
Claude API、claude.ai 对话与 Managed Agents 的 Agent Skills 另有上传、Skill ID、容器和预置文档 Skill 等接口。本页不拿本地目录优先级和动态注入规则解释那些产品面。O
03 SEQUENCE

一次调用走过六道门

扫描候选位置

启动目录到仓库根目录先加入。更深的嵌套目录等 Claude 首次读写其中的文件才出现。

O

解决名称与范围

企业、个人和项目同名时按公开优先级取一份。插件使用带命名空间的名称。嵌套同名项保留目录限定名。

O

编描述清单

默认把名称与描述交给模型。清单超预算时仍保留名称，从较少调用项开始缩掉描述。

O

用户或模型调用

用户输入斜杠名称可以直接点名。模型依据描述自行判断。两个前言字段分别关掉模型入口或用户入口。

O

先渲染，再装入

参数与路径变量先替换，动态命令也先执行。成功后，渲染正文才作为一条消息进入当前会话或分叉上下文。

O

执行并留下痕迹

Claude 按正文读需要的资源并调用工具。正文留在会话，临时工具授权只活到下一条用户消息。

O
04 FLOW

文件怎样变成一次行动

FILESYSTEM

Skill 目录

前言给出名称、描述与调用门，正文写流程，旁边放参考资料和脚本。

CONTEXT LISTING

轻量清单

模型先看到候选名称和描述。手动专用项在这里保持隐藏。

RENDER

调用渲染

参数、路径变量和动态命令结果进入正文。任何前置失败都在这里停止。

MESSAGE

会话消息

正文以内联消息进入当前对话，或成为分叉子 Agent 的任务。

ACTION

工具与结果

Claude 决定读哪些支持文件、调用哪些工具，结果再回到当前流程。

allowed-tools 容易读错。 它只让列出的工具在本次调用回合免询问，并不把其他工具移走。其他工具仍受普通权限规则管理。O

07 IMPLEMENTATION

作者控制什么，Claude Code 控制什么

Skill 作者留下的东西

  • SKILL.md 前言里的名称、描述与调用字段
  • 正文里的流程、资源导航和停止条件
  • 同目录参考资料、例子与脚本
  • 可选的参数与路径变量

Claude Code 在运行时做的事

  • 按位置发现并解决名称
  • 按预算生成描述清单
  • 处理调用门、参数替换与动态命令
  • 把正文送往当前会话或分叉上下文
版本边界

页面基线固定为 2026-08-27 的 Claude Code 2.1.247。官方文档还标出几个较早变化。2.1.218 起分叉 Skill 默认可后台运行，2.1.233 起校验命令可定位前言问题，2.1.246 起会话用 /cd 移动后会加入新目录的项目 Skills。

本机次日已到 2.1.248。官方 changelog 没有宣称这一版改写 Skills 主链，这也不能证明内部实现完全没变。

压缩以后

调用过的 Skill 会随自动压缩重新附上。每个 Skill 最多保留最近调用的前 5000 token，合并预算为 25000 token，最近调用者先占预算。较旧 Skill 可能整个消失。O

分叉以后

context: fork 把正文变成子 Agent 的任务。它看不到当前对话历史，结果完成后回到主对话。这个子 Agent 的完整生命周期属于 PAR-07，本页只记录正文改道的边界。O

08 UNKNOWNS

公开材料没有说完的部分

U01

清单的精确位置

Claude Code 的 system prompt 没有公开。描述清单在完整请求中的序列化格式、位置和周边文本仍未知。O ＋ I

U02

模型怎样判定匹配

官方说明描述会参与判断，也给出预算规则，没有公布固定分数、阈值或可重复的排序算法。O

U03

支持文件读多少

正文负责指路，模型按任务取用。官方没有承诺每个引用文件都读，也没有给出确定的读取次序。O ＋ I

U04

旧版真实路径

本机 2.1.247 已被替换。重新安装会改动机器，本轮没有这样做，旧版二进制上的真实调用仍待隔离复现。L

U05

远端表面没有实测

本轮没有登录 claude.ai，也没有启动 Cowork、cloud 或 SDK 请求。表面差异只写到官方契约允许的位置，仍缺 R。O

怎样做一次完整复现
  1. 在隔离测试仓库固定安装 2.1.247，核对给定版本和哈希。
  2. 创建默认、手动专用、模型专用和嵌套四个无害 Skill。
  3. 在获准计费的会话里记录用户点名与模型匹配两条路径，只保留匿名化状态。
  4. 加一个只读支持文件和一个只读动态命令，再让另一个命令以状态 2 失败，核对正文是否在失败前进入上下文。
  5. 发送下一条用户消息并触发压缩，观察临时权限清除与正文再附加预算。

详细命令边界、不能证明的事项和哈希摘要见同目录 evidence.md。
