RUNNING SESSION INGRESS

外部消息插进正在跑的会话

获准的 Channel 服务器把外部事件排进已经打开的 Claude Code 会话。入口连着聊天平台或公开端点时，服务器应先核发送者。Claude 处理后，按事件带来的路由字段调用普通 MCP 回复工具；工具若卡在批准框，受信通道还可以带着一次性请求号把允许或拒绝送回来。

它依赖一条仍在运行的本地会话。会话关掉，入口也随之消失。 [O]

01 / TERMS

只需要四个名词

普通 MCP 让 Claude 主动找工具。Channel 在这层协议上加了一个外部事件入口，消息可以在用户没有敲下一次回车时进入已经打开的会话。 [O]

channel capability

服务器声明 claude/channel，Claude Code 才注册通知监听器。声明本身还不够，用户仍要逐会话启用。

notification

content 是事件正文。可选 meta 保存 chat ID 或 severity 等路由信息；键名不合规则会静默丢弃。

reply tool

双向桥公开的普通 MCP 工具。Claude 主动调用它，服务器再把文字送回外部平台。

permission relay

额外 capability。它只转发当前工具批准，并用短请求号把一次 allow 或 deny 对回等待项。

02 / SEQUENCE

一条消息走过的时间顺序

这条链从用户启动会话开始。外部发送者、Channel server、Claude Code 和 Claude 各做一段，任何一段都不能代替另一段。 [O]

本地用户

先用 claude.ai 账号或 Anthropic Console API key 认证，再在新会话中选入一个获准 Channel。个人 Pro、Max 可以逐会话选入；Team、Enterprise 还要由组织管理员开启。

Claude Code

启动同机 MCP 子进程，通过 stdio 完成连接。服务器的 capability 让客户端注册 Channel listener。2.1.247 若实际选到 v2 runtime，并在自动协商中连上不承载 Channel 消息的新协议 revision，注册会停在这里。

外部发送者

向聊天机器人或 webhook 发事件。对外入口应先核 sender ID，未获准的消息静默丢弃。

Channel server

发送 Channel notification。事件带正文与字符串 meta，服务器名会成为 source。

当前会话

事件按序排队。Claude 正忙时，多条通知留到下一 turn 一起交付。

Claude

读取 channel 事件并继续工作。需要回应时，从 meta 取路由值，再调用服务器公开的 reply tool。

三次放行，各管一关 capability 让客户端认出这类服务器；逐会话选择决定这一次是否接入；sender gate 决定某个外部身份能否投递。前两道门由 Claude Code 与组织策略把守，最后一道门必须在 Channel server 发通知之前完成。少掉任何一道，消息都不该进入当前会话。 [O]
03 / FLOW

数据停在哪里

统一契约定义了 transport 与字段，没有规定所有插件共用一份状态文件。allowlist 和平台凭据属于各 Channel server，排队与开放的批准请求属于运行中的 Claude Code 会话。 [O + I]

外部系统

消息、告警或 webhook 事件

sender gate

服务器自己的 allowlist 或等价状态

MCP stdio

content 与 meta notification

当前会话

按序队列与 channel 标签上下文

reply tool

chat ID 与回复文字回到外部系统

通知信封 正文放在必填的 content，chat ID、severity 一类辅助值放在可选的 meta。meta 只接受字符串字典，键名只能使用字母、数字和下划线；服务器名则由客户端补成 source。meta 只把路由上下文交给 Claude 读取；自动回复仍要显式调用工具。 [O]
排队语义 写入 stdio 成功，只能说明 notification 进入 transport，不能证明 Claude 已经看到或处理。客户端按到达顺序排队；Claude 忙碌时，等待中的多条事件到下一 turn 才一起交付。若业务需要彼此独立的并发处理，就要使用不同会话，不能把同一队列误当成多条并行执行线。 [O]
批准支路 Claude Code 把 tool name、说明、输入预览和短 request ID 发给同一受信服务器。远端 verdict 带原 ID 返回，先到的本地或远端答案结束这次等待。 [O]
04 / GATES

入口与停止条件

认证方式先决定功能是否可用，随后还要经过注册、逐会话选择、组织策略与 sender 身份检查。服务器写入 transport 也没有送达回执。 [O]

账号与套餐

只支持 claude.ai 认证或 Anthropic Console API key。没有加入组织的 Pro、Max 用户不经过组织开关；claude.ai Team、Enterprise 必须由管理员启用。

平台止步

Amazon Bedrock、Google Cloud Agent Platform 与 Microsoft Foundry 均不支持 Channels。

注册门

声明 Channel capability，并由用户在这次启动中选入。普通 MCP 配置无法单独打开注入。

组织策略

Team、Enterprise 默认阻止。Console API key 认证默认允许；组织一旦部署 managed settings，就要把 channelsEnabled 设为 true。有效插件允许列表仍决定谁能注册。

协议协商

2.1.247 落在 2.1.232 及以上的 runtime 规则内，但本轮没有实测它这次选了哪一个 runtime。实际使用 v2、设置 MCP_PROTOCOL_NEGOTIATION=auto，且服务器协商到 revision 2026-07-28 时，Claude Code 不会把它注册为 Channel。

发送者门

服务器核对 sender ID。只看 room ID 会让获准群里的其他人也能注入消息。

权限门

relay 只处理 tool-use approval。project trust 与 MCP server consent 留在本地终端。

静默丢弃

会话没加载服务器或策略阻止时，通知可能没有错误地消失。transport resolve 不能当处理成功。

停止条件

会话关闭、sender 未获准、注册失败或当前工具被 deny，都会让这条路径停住。

回复另走普通 MCP 工具 入站事件到达后，Claude 仍要选择并调用服务器公开的 tool。工具 schema 规定回复正文和路由参数，服务器的 instructions 提醒 Claude 从哪一个 meta 字段取值。若路由值缺失、工具没有公开或调用未获准，入站消息已经成立，外部回复却仍会停住。 [O + I]
裁决只认当前等待项 permission relay 另有 capability。Claude Code 发出带短 request ID 的批准请求，服务器把远端 allow 或 deny 连同原 ID 送回；本地答案与远端答案谁先到，谁结束等待。它没有把 project trust、MCP server consent 或未来工具调用一起授权，也不应被理解成持久权限规则。 [O]

06 / BUILD

实现与版本边界

2.1.247 已越过 relay 修订点，也落在 2.1.232 及以上的 runtime 规则内。runtime 会在每次启动时重新选择，本轮没有运行握手实验；Channels 仍是 research preview，启动语法和协议还可能变化。 [O + L]

边界公开行为2.1.247 的位置
2.1.211permission description 与 input preview 会清理方向覆盖字符、折叠空白，并按字段保留首尾后限长。已包含
2.1.234可识别格式的凭据会遮蔽，不可安全序列化的值用占位，permission capability 的 false 才真正表示未声明。遮蔽有识别边界，不能当作完整的 secret filter。已包含
2.1.234权限请求只发给本会话已经注册的 Channel，仍需逐会话 opt in 与组织策略通过。已包含
2.1.232+这些版本进入 v2 MCP runtime 规则，但认证平台、apps gateway、feature flag 或显式设置仍可能让启动选择 v1。实际使用 v2 时，stdio server 若在 MCP_PROTOCOL_NEGOTIATION=auto 下协商 revision 2026-07-28，该 revision 不能承载 Channel 消息，服务器不会注册为 Channel。变量不设置或设为 legacy 时，stdio 保持较早握手。2.1.247 在版本范围内；本轮未运行协商实验
preview两个 Channel 启动参数不出现在普通帮助中，官方提醒参数与协议会继续变化。本机帮助吻合

07 / UNKNOWNS

还缺一次真正跑通

官方契约足以画出路径，本机只读证据还不能回答当前账号、组织和终端上的真实呈现。

这台机器能否注册一个 Channel

需要支持的认证方式、套餐或组织策略、有效插件，以及 MCP 握手一起验证。本轮没有启动可能付费的 Claude 会话，也没有运行协议协商实验。

忙碌时多条事件怎样出现在终端

官方保证下一 turn 成组处理，2.1.247 的具体行样式与交互没有 R。

晚到或重复 verdict 显示什么

公开契约只保证匹配开放 request ID 的裁决才应用，具体错误文字和超时长度未知。

本地先批准后服务器怎样收尾

官方说明待处理远端请求会被丢弃，没有定义一条显式关闭回执。本页不补推测。

安全复现摘要

在隔离目录固定 2.1.247，创建最小 stdio Channel server。只记录允许与拒绝 sender 的送达差异、忙碌 turn 的次序，以及本地和远端 verdict 谁先结束等待。关闭会话后再发匿名事件，确认 transport write 不能充当处理回执。完整步骤见 evidence.md。
