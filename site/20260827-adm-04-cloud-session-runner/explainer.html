环境一选定，任务才会进入执行端

云任务先绑定一个已有环境。托管轨道会分配隔离 VM，自托管轨道会把任务送进环境队列，由空闲 Runner 领取。随后才发生代码获取、凭据接入和 Claude Code 子进程执行。官方公开的托管 VM 回收条件是会话空闲一段时间，任务或单轮完成不等于 VM 立即消失。自托管正常释放会进入 hook 与工作区拆除；Runner 失联后，控制面会把同一会话重新排队，异常终止时 hook 不保证执行。 O

01 / terms

先认清参与执行的角色

TASK

云任务

用户从网页、Desktop、移动端、CLI 或 routine 发起的一次 Claude Code 会话。它选择环境，不选择某一台 Runner。 O

ENVIRONMENT

环境

一份已保存的执行目的地。它决定网络边界和环境变量，也决定任务走 Anthropic VM 还是组织自己的 Runner。 O

CONTROL PLANE

Anthropic 控制面

负责会话编排、队列与界面。即便任务跑在自托管设施，控制面仍留在 Anthropic。 O

RUNNER

自托管 Runner

组织部署的长驻进程。它轮询队列、领取租约、准备 checkout，再启动每条会话的 Claude Code 子进程。 O

SESSION CHILD

会话子进程

读代码、调用工具并向 Anthropic 请求模型推理的 Claude Code 进程。Runner 负责启动和停止它。 O

CREDENTIAL PATH

凭据通道

托管环境用沙箱外代理代签请求。自托管环境可同时使用部署方的 Git 接入，以及按会话身份换取的内部服务凭据。 O

02 / sequence

一次任务按这个顺序执行

选择环境

界面用选择器。CLI 采用保存的默认值，自托管环境也可用 ID 单次覆盖。 O

取得算力

托管侧分配隔离 VM。自托管侧先入队，再由有空位的 Runner 领取 lease。 O

准备代码

托管端从 GitHub 克隆；CLI 没有可用的 GitHub 连接时，也能上传本地仓库 bundle。自托管 Runner 准备 checkout。 O

接入凭据

凭据按用途接入。Git 可走代理，内部服务可由 wrapper 校验 session JWT 后换取短期凭据；这些机制可以并存。 O

运行子进程

Claude Code 执行工具并通过 HTTPS 传回事件，同时请求模型推理。 O

分清结束路径

托管 VM 在空闲过期后回收。自托管正常释放会运行 hook 并拆除工作区；停止轮询约 60 秒会触发重排，异常终止可能跳过 hook。 O

这六步有严格的先后关系。环境先决定执行端与网络边界，执行端随后取得仓库内容。凭据只在需要访问 Git、内部服务或模型时接入。代码已经开始运行以后，网页上的环境编辑不会回头改变这次会话。 O

03 / flow

同一任务，两类执行端

Anthropic 托管
环境选择已有 env
新 VM隔离 Ubuntu
代码输入GitHub clone / bundle
Claude Code工具与推理
空闲过期回收 VM
组织自托管
环境队列控制面入队
Runner 领取lease 与心跳
clone 与 wrapper部署方供凭据
会话子进程出站 HTTPS
结果分流正常清理 / 失联重排

自托管 Runner 的约 60 秒 lease 失联规则有官方契约。Anthropic 托管 VM 的内部队列与 lease 没有公开，图中没有把这条规则外推过去。 I

代码先落到执行端

托管会话通常从已连接的 GitHub 仓库克隆代码。CLI 从未连接 GitHub 的本地仓库 dispatch 时，会自动打包并上传仓库；bundle 不含未跟踪文件，超过 100 MB 会逐级缩减，仍过大才失败，没有 GitHub 认证也不能回推。自托管 Runner 则先准备 checkout，再进入 session wrapper。 O

凭据可以按用途组合

托管 VM 里的 GitHub 与 API 密钥由沙箱外代理保管。自托管 Runner 可让宿主机或 checkout hook 提供 Git 凭据，也可选用 Anthropic Git proxy；wrapper 还能校验 session JWT，再按创建者换取内部服务的短期凭据。Git 接入与内部凭据交换不是二选一。 O

自托管仍会连接 Anthropic

checkout、构建产物和工作文件留在组织机器上。会话正文、工具结果和模型请求仍通过 HTTPS 进入 Anthropic 服务，队列与控制面也由 Anthropic 托管。自托管改变的是执行位置，并没有把整条会话链搬进组织网络。 O

04 / limits

任务会卡在哪一步

DISPATCH

谁能把代码送进 Runner

自托管 environment 没有逐环境派发访问控制。组织内任意成员都能向任意 environment 派发；--lock-to-account 只限定 Runner 接受哪个账户的会话，不能收窄派发者。Runner 主机只能放所有这些派发者都有权读取的数据与凭据。 O

ELIGIBILITY

账户、套餐与组织策略

托管云会话面向 Pro、Max、Team，以及具有 premium seat 或 Chat + Claude Code seat 的 Enterprise 用户。CLI 还要用 claude auth login 登录 Anthropic 账户；配置为 Bedrock、Google Cloud Agent Platform 或其他第三方模型提供商时不可用。组织策略必须允许 remote sessions。自托管环境另处于 Team 与 Enterprise public beta，并由 Owner 开启。 O

SOURCE

代码从哪里进入

有 GitHub 认证时，托管会话从远端 clone。CLI 没有可用连接时可自动上传本地仓库 bundle，但不带未跟踪文件，且没有 GitHub 认证就不能 push 回远端。自托管 Runner 必须取得 checkout 所需凭据。 O

CREDENTIAL

凭据给到哪一层

托管 API credential 只在匹配请求离开 VM 后附加。自托管 JWT 能识别会话创建者，但进程内代码也能读取它，派生权限必须缩到单次编码任务。固定 fleet 还把 environment secret 放在运行会话代码的主机上，会话代码可读取 secret 文件。官方建议改用隔离主机和 on-demand Runner，让 secret 留在不运行会话代码的 orchestrator。 O

NETWORK

出站路径是否放行

托管环境受所选网络级别与代理约束。自托管部署需要自己做默认拒绝，并允许控制面、Git 主机和确有需要的内部服务。 O

STOP

哪一条路径改变会话状态

自托管 Runner 的空闲释放与最长寿命默认都是 0，也就是关闭；启动超时默认 15 分钟。运维方还可设置绝对退役时间。正常释放会给 post-session hook 留出窗口。停止轮询约 60 秒触发的是重排，突然断电或强杀还可能跳过 hook。 O

05 / experiment

本轮没有创建云会话

documented

创建云任务会消耗账户用量并留下远端状态。启动自托管 Runner 还需要组织权限与 environment secret。本轮停在官方契约和本机只读帮助，因此没有 R。

安全检查所得

  • 当前 PATH 找不到 claude，显式安装位置可只读运行。 L
  • 可执行版本已是 2.1.250，和固定基线 2.1.247 不同。 L
  • 当前 help 有 cloud dispatch、environment 覆盖和 self-hosted-runner 参数。 L
  • 未登录、未读取 token、未发任务，也未碰私人会话文件。
06 / implementation

回收发生在两个层次

会话层

Anthropic 托管会话空闲后，VM 会被回收。再次打开会配新 VM 并恢复对话历史。原先仍在运行的后台任务与 shell 命令不会跟回来。 O

  • 环境变量在会话启动时复制一次
  • 运行中的会话不会重读环境编辑
  • 准确空闲阈值没有公开

Runner 层

Runner 的首条会话把它锁给一个 owner。默认 drain grace 为零，活动会话做完就退出。这个 owner 锁不限制谁能向 environment 派发。编排器可以随后启动干净实例，避免不同 owner 共用磁盘。 O

  • 启动超时默认 15 分钟
  • 空闲释放默认 0，处于关闭状态
  • 最长寿命默认 0，处于关闭状态
  • 绝对退役时间默认未设置

自托管会话有几条互相独立的停止路径。正常结束时，子进程先退出，Runner 再运行 post-session hook 并拆除 workspace。子进程启动后 15 分钟仍未报告初始化，默认会释放 slot。运维方可另行开启空闲释放、最长寿命，或给 Runner 设置绝对退役时间；前两项默认关闭，退役时间默认未设置。Runner 停止轮询约 60 秒后，控制面会把仍被持有的会话重新排队。这条路径是重排，不能据此断定旧 Runner 已正常释放、运行 hook 或清理工作区。Runner 收到终止信号时先停止接新任务，再按 drain 预算结束子进程。基础设施若先强杀进程，hook 可能没有机会执行，未推送的修改也不能指望随重排到达下一台 Runner。 O

托管会话走另一套回收条件。它在空闲一段时间后停止，原 VM 随后释放。用户再次打开会话时，对话历史可以恢复，执行环境会换成新 VM，旧 VM 里的后台任务不会继续运行。 O

Self-hosted environments 在官方 Week 32 changelog 中标为 v2.1.224 引入。--environment 同样要求 v2.1.224。当前官网还记录了 v2.1.229、2.1.236、2.1.238 与 2.1.246 的局部修正，固定基线 2.1.247 已包含这些版本条件。 O

07 / unknowns

这几处还不能写死

托管 VM 多久算空闲

官方只说一段空闲后停止并回收，没有给出固定时长。套餐、容量和会话状态会不会改变它，本轮没有证据。

托管侧怎样排队与续租

公开的约 60 秒 lease 规则属于自托管 Runner。Anthropic 托管 VM 的调度实现没有公开。

2.1.247 本机帮助全文

当前安装已经更新到 2.1.250，二进制摘要也变化了。本页保留 2.1.247 固定基线，没有拿新版本 help 代替旧实现证据。

故障点上的 dirty working tree

官方警告 Runner 释放以后，未 push 工作可能丢失。不同中断瞬间究竟还能保存多少，需要一次可销毁部署里的 R。
