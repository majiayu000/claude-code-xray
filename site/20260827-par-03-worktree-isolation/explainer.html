Worktree isolation

每个并行会话，领一份独立目录和分支

用户申请 worktree 隔离以后，Claude Code 默认优先从远端默认分支开出一条干净支线，把会话工作目录移到这条支线的检出目录。它会拦住写回主检出的工具调用。退出时，干净目录可以清掉，带工作成果的目录先保留或等用户选择。

这份隔离保护工作区文件。Git 历史、远端、项目插件和部分持久权限仍会共享。CLI 沿用 Claude Code 的账户或提供商凭证，Desktop Code 要用支持的订阅账号登录。官方没有给 worktree 单列价格，多个会话的模型用量仍计入各自套餐或账单。本页没有启动 Claude 会话。

01 / TERMS

先分清四件东西

申请隔离不会复制一套完整仓库。Claude Code 让 Git 增加一个 checkout，再把新会话放进去。目录和分支各自独立，仓库历史仍共用。理解这一点以后，基线从哪里取、哪些文件会出现、退出时能否删除，便能沿着同一条链看清。

01

主检出

用户原来打开的项目目录。隔离会话把它当作受保护的 checkout，文件工具和命令不能绕回去改。

02

worktree

同一个 Git 仓库的另一份工作目录。它有自己的文件状态和分支，仍连接同一份 Git 历史。

03

基线

新分支从哪里开始。默认 fresh 取远端默认分支，head 才会带上当前本地 HEAD 的未推送提交。

04

可丢工作

退出清理会检查改动、未跟踪文件和新提交。任何一项存在，删除都可能丢工作，流程便进入保留或确认分支。

02 / SEQUENCE

一次申请怎样走完

入口不同，核心转换相同。系统先确认目标可用，再选提交作为起点，随后创建目录和分支并切换会话工作目录。隔离检查从这时开始约束文件工具与命令。退出检查负责判断这份工作树能否安全收走。

用户提出隔离

CLI 用 -w 或 --worktree。会话内可让 Claude 调用 EnterWorktree，subagent 定义可写 isolation: worktree。

O · L

先过入口条件

Git 仓库走内置流程。首次交互运行还要有工作区信任。默认目录外的目标会再要批准。

O

确定起点

fresh 尝试更新远端默认分支的缓存。远端不可用时回退当前本地 HEAD；head 配置直接使用当前 HEAD。

O

建目录和分支

新名称的默认路径是项目根下 .claude/worktrees/<name>，默认分支名是 worktree-<name>。名称可以由用户给出或自动生成。

O · L

会话在支线工作

跟踪文件进入新检出，忽略文件只按 .worktreeinclude 复制。文件写入、命令目录和 Git 重定向受到隔离检查。

O

退出时检查成果

干净、命名、脏工作树和非交互运行走不同清理路径。运行中的 agent 还会用 worktree lock 防止并发清理。

04 / STOP & FAIL

删除前，先看会不会丢工作

有改动、未跟踪文件或新提交吗
干净且会话未命名

交互会话退出时，目录和分支自动删除。

干净但会话已命名

Claude Code 先询问，用户可以留下 worktree 继续使用。

含有工作

用户选择保留或删除。删除会丢掉目录、分支及其中尚未带走的工作。

非交互运行

-p 没有退出提示，不自动清理。需要手工 remove，锁未释放时先 unlock。

subagent

无改动时结束即清。带改动时先留在磁盘，周期清理只在能确认不会丢工作时处理。

入口会拒绝

默认 Git 流程要求仓库。符号链接路径、无法核验的 Git 身份和部分仓库本地 filter driver 配置也会阻止创建或采用 worktree。

恢复可能失去隔离

交互恢复遇到已删除或无法核验的 worktree 时，官方契约允许在启动目录继续并给出提示。非交互恢复通常中止，已删除目录是例外。

命令也受边界检查

Claude Code 会拒绝绕回主检出的 cwd、Git 重定向和无法静态追踪的 Shell 结构。这类拒绝作为工具错误返回。

自定义 hook 接管创建

WorktreeCreate 会替换默认 Git 逻辑。它必须返回目录路径，失败或没有路径会让创建失败；WorktreeRemove 不能阻止删除。

CLI 怎样登录

--worktree、EnterWorktree、subagent 与 hook 都在本地 Claude Code 流程里。官方列出的入口包括 Pro、Max、Team、Enterprise 订阅账号，也包括 Anthropic Console、Bedrock、Google Cloud Agent Platform、Microsoft Foundry 与企业网关凭证。Worktree 不另要一套凭证。

06 / VERSION

2.1.247 这条线上的实现边界

基线可以选 fresh 或 head

fresh 默认从远端默认分支开出干净支线，取不到远端引用时回退当前本地 HEAD。head 会把当前 HEAD 的未推送提交与分支状态带入新 worktree。

2.1.247 收紧仓库 filter driver

官方文档写明，这一版创建 worktree 时不再运行仓库本地配置里的 filter driver。只做过 local 安装的 Git LFS 可能留下指针文件。

2.1.246 给自动清理加标记

周期清理会看 Git 元数据中的 Claude Code 标记，没有标记的手工 worktree 会留下。早于 2.1.246 的清理曾可能被旧后台记录误导。

2.1.212 阻止符号链接越界

默认 .claude、worktrees 目录或目标目录是符号链接时会拒绝创建。官方把这一变化放在曾经可能写到项目外的风险之后。

项目插件与批准仍会共享

2.1.200 起，同仓库的项目级插件会在 worktree 中加载。2.1.211 起，普通平台上的持久 Bash 批准保存回主检出的本地设置，其他 worktree 也会继承。

同名 worktree 可能重用

目标目录已经存在时会打开旧 worktree。默认 fresh 只有在干净、仍处于 Claude 创建的分支且提交条件满足时才重置到默认分支，其余情况保留旧 tip。

07 / UNKNOWNS

现在还不能写死的地方

U1

本机真实命令链

2.1.247 在这台 macOS 机器上的 Git 子命令、锁写入时点与逐字提示没有 R 证据。

U2

复杂 Shell 的完整集合

官方说明了四类检查与若干例子，没有公开全部可接受和会拒绝的命令形状。

U3

周期清理的调度细节

官方给了年龄阈值、保留条件和锁规则，没有给扫描由哪个进程在何时唤起的完整时序。

U4

第三方版本控制的隔离强度

自定义 hook 可以返回非 Git 工作目录。同等文件保护是否成立，取决于 hook 的实现。
