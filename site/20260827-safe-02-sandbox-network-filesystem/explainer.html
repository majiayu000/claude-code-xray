BASH SANDBOX / FILE / NETWORK / PROCESS

命令能走多远

用户启用沙箱且沙箱成功启动后，Bash 命令先过权限检查，随后在操作系统边界中运行。默认可以读机器上的大部分文件，只能写当前工作目录与会话临时目录。新网络主机第一次出现时，代理先把请求交给 Manual 审批或 Auto 分类，获准后在本会话内继续。文件越界或严格域名策略拒绝会让 Bash 失败；失败结果回来以后，Claude 才能调整允许范围，或申请一次无沙箱重试。OI

这页把权限已经允许的命令作为起点。沙箱是各模型提供方都可用的本地能力，没有单独的付费档位；实际让 Claude 发起 Bash 命令仍要先建立已认证会话。页面固定在 2026-08-27 的 2.1.247 契约。OI

01 / TERMS

先分清三道边界

读懂本页只需要三个对象。它们出现的时间不同，失败也落在不同位置。

权限层

命令运行前，规则与模式决定 Bash 工具能否开始。它管调用资格。O

操作系统沙箱

命令开始后，macOS Seatbelt 或 Linux bubblewrap 约束文件和网络。子进程继承同一边界。O

沙箱外代理

进程的网络流量经过代理。代理按主机名核对允许表，默认不检查加密连接里的内容。O

02 / SEQUENCE

一条命令怎样走完

用户已经启用沙箱并允许 Bash 工具。文件越界会先形成失败，新网络主机则先走会话准入。两条路在这里分开。

权限先放行

权限规则与当前模式先处理工具调用。沙箱不会替一个已被 deny 的命令取得执行资格。O

运行时组装边界

Claude Code 合并沙箱文件设置、Read 与 Edit 规则、域名规则，再用当前平台的操作系统原语启动命令。O

进程开始访问

文件访问由系统边界裁决。网络流量送往外部代理。命令随后启动的子进程仍受相同限制。O

新主机先请求准入

默认没有预先允许的域名。第一次访问新主机时，Manual 模式询问用户，Auto 模式交给分类器；获准的主机加入本会话允许项。严格允许表会跳过询问，直接拒绝表外主机。O

允许范围内继续

默认写入当前工作目录和会话临时目录。已有规则或刚获准的主机可以继续连接，命令把普通退出结果交回 Bash 工具。O

违规拒绝形成失败

文件边界或严格网络策略拒绝访问后，违规详情附进 Bash 失败结果。普通新域名获准时不会经过这个节点。O

重试回到权限流

无沙箱重试使用 dangerouslyDisableSandbox。Manual 模式询问用户，Auto 模式交给分类器；严格设置可直接忽略该参数。O

04 / LIMITS

允许范围与停止位置

默认可读范围很宽。只打开沙箱并不等于凭据已经隐藏，文件读拒绝和凭据设置需要另行配置。O

动作默认或明确规则越界后的结果
读普通文件大部分机器可读。denyRead 与凭据规则可以收窄，更具体的读路径决定重叠区域。系统拒绝读取，违规详情进入 Bash 失败结果。
写工作目录当前工作目录、子目录与会话临时目录可写。Claude 自己加载的受保护路径仍拒绝写入。写入失败。allowWrite 也不能豁免受保护路径。
写目录外路径需要 allowWrite 或合并后的 Edit allow。多个设置来源的路径数组会合并。先失败，随后才可能申请沙箱外重试。
访问新主机默认没有预先允许的域名。Manual 询问，Auto 分类；严格允许表跳过询问并直接拒绝。获准后加入当前会话，命令继续。普通准入拒绝会停下这次访问，严格策略拒绝会形成违规失败。
启动子进程子进程继承同一文件与网络边界。Unix socket 与本地监听另受平台设置约束。子进程不能靠换程序名脱离边界。
沙箱无法启动默认警告后用无沙箱方式运行。failIfUnavailable: true 才要求启动失败。默认会降低隔离强度。严格部署会直接停止启动。
05 / OBSERVATION

本机只能证明版本漂移

研究过程只读了 CLI 帮助、安装入口和公开索引，没有读取设置、会话或私人内容。

本机已经是 2.1.248

claude --version 返回 2.1.248，原生 arm64 二进制的哈希也不同于任务给定的 2.1.247 快照。当前安装不能充当 2.1.247 的静态实现证据。L

官方索引仍有 202 项

2026-08-28 在线索引仍计得 202 个入口，SHA-256 已不同于 2026-08-27 固定值。官方页面是活文档，版本标注不能省。OL

本页没有 R

真实验证要启动 Claude 会话，让 Bash 访问专门准备的边界目标。任务禁止启动任何会消耗模型额度或产生用量的新会话，也禁止读取或改动现有设置，因此没有执行。页面保持 documented。

没有拿 Seatbelt 冒充 Claude

系统带有 sandbox-exec，独立的 srt 没有安装。自写 Seatbelt profile 只能证明自写规则，不能证明 Claude Code 2.1.247 生成过什么。L

登录与费用跟着模型提供方走

沙箱本身没有额外付费档位。认证入口包括 Claude.ai 的 Pro、Max、Team 或 Enterprise 账户、Claude Console、Amazon Bedrock、Google Cloud 与 Microsoft Foundry。订阅账户按套餐额度与已开启的额外用量结算，Console 和云提供方按各自的模型用量与账单结算。OI

06 / IMPLEMENTATION

操作系统负责执行边界

Claude Code 负责合并策略并启动命令。实际文件拒绝与进程继承交给平台原语，网络则通过沙箱外代理收口。O

macOSSeatbelt。无需另装 sandbox 依赖。
Linuxbubblewrap 负责文件隔离，socat 接力代理流量。
WSL2沿用 Linux 路径。WSL1 缺少所需内核能力。
Windows2.1.247 不支持原生运行这套 Bash 沙箱。

默认读取为什么仍需单独收紧

官方文档明确写着，默认读范围包含整台机器的大部分位置，常见凭据目录也不会自动全部挡住。需要用 denyRead 或 sandbox.credentials 指定文件与环境变量。网络隔离无法替这一步补上文件读限制。

代理能看见什么

内置代理通常按客户端给出的主机名放行，不解密 TLS 内容。广泛允许一个域名会扩大外传机会。要求内容检查时，官方建议接入会终止 TLS 的自定义代理，并处理对应证书。

沙箱覆盖不到哪里

Read、Edit 与 Write 直接走权限系统。Computer use 操作真实桌面。环境变量默认由父进程传给 Bash，除非用凭据设置或全局子进程清理开关收窄。O
