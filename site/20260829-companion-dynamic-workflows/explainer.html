COMP-PAR-WORKFLOW · CLAUDE CODE XRY 伴页

脚本根据上一阶段结果创建下一批 subagent

上一阶段的 subagent 返回结果，脚本先把它留在变量里。等结果到齐以后，后面的调用才按这些结果创建新 subagent。失败和停止会改变下次重放的起点。

阶段标题只负责进度展示。等待关系来自脚本顺序与 await。同一会话重放可以复用未变化的结果，未来新会话运行保存脚本会从头开始。 O + I

01 / TERMS

先认四样东西

JS

workflow 脚本

Claude 为任务写出的 JavaScript。runtime 执行它，循环、分支和等待关系都在脚本里。

PH

phase

它把随后创建的 agents 归到同一个进度标题下。重放规则按 agent 结果判断。

OUT

结果变量

一个 agent 返回的文本或结构化值。后续脚本可据此拼 prompt、生成列表或决定是否继续。

RUN

run 记录

同一会话里跟踪 agent 的结果与顺序，为暂停恢复和停止后的重放提供依据。

本页边界 这里没有共享工单与 teammate 信箱。Lead、Task list、Mailbox 和 shutdown 属于 PAR-08 Agent Teams 主页面。

02 / SEQUENCE

一趟运行的时序

0
用户提出任务
O · 交互入口

用户直接要求使用 workflow，或在交互输入里用 ultracode。Claude 随后为这件事写脚本。字面触发词在 2.1.160 已从 workflow 改为 ultracode，自然语言请求仍有效。

1
先过启动门
O · 权限与入口

CLI 的批准页可显示阶段并打开 raw script，Desktop 改用带用量提醒的批准卡。claude -p 与 Agent SDK 不显示这两种界面，Workflow 调用仍接受各自的权限评估。workflow 内 agent 的工具也继续接受会话权限与沙箱检查。

2
runtime 启动
O · 隔离执行

runtime 在对话之外执行脚本，并把本次脚本写进会话目录。主会话保持可响应。中间结果不会逐条灌进主对话上下文。

3
第一批返回
O · agent()

agent() 生成一个 subagent。脚本可以要求结构化输出，等待它返回以后，把结果放进普通 JavaScript 变量。

4
派生下一批
O + I · 调度门

脚本从上一批结果生成列表或新的 prompt，再调用 pipeline() 或 parallel()。phase() 给随后出现的 agents 标题，await 与函数调用顺序才建立阶段门。

5
汇总或收住
O · return

末段 agent 可以合并前面的发现，脚本也可以过滤空结果或按条件停下。最终返回值进入主会话。中途停止和不可恢复 API 错误可能给脚本一个 null。

03 / FLOW

结果怎样往后走

DISCOVER

先找出工作清单

第一个 subagent 可以返回带 schema 的对象。脚本拿到其中的文件列表或问题列表。

const found = await agent(…)
FAN OUT

按结果创建 workers

脚本遍历上一项结果。每个列表项成为一名新 subagent 的 prompt 输入。

await pipeline(found.files, …)
SYNTHESIZE

再把发现合起来

后续 agent 接收前面返回的文本或对象，去重、排序或验证，最后只把总结果交回会话。

return results.filter(Boolean)
文件走另一条路

workflow 脚本没有直接文件系统或 shell 访问。早期 subagent 若写了文件，文件留在它获准访问的工作目录。后续 subagent 要靠已知路径再读，仍会经过自己的工具权限。脚本变量只传返回值，文件不会随变量形成快照。 O + I

04 / LIMITS

失败、停止与重放

先要有可用凭据与付费入口

当前官方指南把 Dynamic Workflows 开放给所有付费计划，也支持 Anthropic API、Amazon Bedrock、Google Cloud Agent Platform 与 Microsoft Foundry。Claude Code 仍要先用对应的 Claude.ai、Console、API 或云端凭据完成认证。Pro 用户还要在 /config 的 Dynamic workflows 一行开启功能。

这项能力覆盖 CLI、Desktop、IDE 扩展、claude -p 与 Agent SDK。本轮没有登录，也没有在任何入口真实启动 workflow。这里的可用性与界面差异只有当前官方文档这一层 O，尚无 2.1.247 的 L 或 R。

O · 当前官方契约，L / R 未验证
入口启动时实际看到什么
CLI交互批准页列出计划阶段，可查看 raw script。Auto、手动和绕过权限三种模式的提示时机不同。
Desktop批准卡显示 workflow 名称、阶段与 token 用量提醒，操作是 Once、Always 和 Deny。进度放在 Background tasks 侧栏。
IDE 扩展官方确认可以使用 workflow，用户亲手输入的 ultracode 关键字也能触发。指南没有单列 IDE 的批准界面，本轮同样没有实测。
claude -p没有交互批准页。Workflow 工具调用直接进入会话的 allow、deny、ask、dontAsk 或宿主批准流程。
Agent SDK也没有交互批准页。调用可由权限规则、hook、canUseTool 或宿主回调决定。SDK 只有把键盘输入标成 human origin 时，ultracode 关键字才会触发。

启动权限

手写或现生成脚本在开始前可能需要批准。已保存 workflow 可按名称写 allow 规则。提示形式与权限判定要按上表的入口分别看。

运行权限

脚本本身只编排。subagent 调用 Read、Write、Bash 或网络工具时，各自接受会话规则与沙箱约束。权限提示可以暂停 run。

脚本硬限

脚本不能动态加载模块。单次 parallel() 或 pipeline() 最多接收 4096 项，一次 run 最多创建 1000 agents，并发最多 16，CPU 较少时还会降低。

用户停止

/workflows 里用 p 暂停或恢复，用 x 停一个 agent 或整次 run，用 r 重启选中的运行中 agent。停止整次 run 不把所有仍在跑的 agent 记成 failed。

运行中没有普通用户输入。

主会话保持可响应，不等于脚本会在阶段之间收取新指令。一次 workflow 开始以后，只有 agent 的权限提示可以暂停这次 run。

流程若要求人在发现阶段结束后签字，再决定是否进入修改阶段，就要拆成两个 workflow。前一段先返回并结束，用户确认以后再启动后一段。

O · Behavior and limits
空结果要由脚本处理。agent() 被单独停止或遇到不可恢复 API 错误时返回 null。pipeline() 会保留它。脚本可以过滤、记录为未验证、换一条分支，也可以让后续步骤停止。官方没有替所有 workflow 规定一种统一失败策略。

同一会话里的重放

O

完成且 prompt 未变化的 agent 直接返回保存结果。首个 prompt 变化、首个不同上游结果、failed agent 或停止时仍在运行的 agent 会再跑。该点以后已经完成的 agents 也会再跑。

保存脚本后的重跑

O + I

用户可把脚本保存成 /name。未来新会话执行的是同一段编排，旧 run 的结果缓存不属于这个新会话，所以全程重新开始。

06 / IMPLEMENTATION

脚本与版本断点

export const meta = { name, description }

phase('发现')
const found = await agent('列出目标', { schema })

phase('逐项处理')
const work = await pipeline(found.files, file =>
  agent('处理 ' + file)
)

phase('汇总')
return work.filter(Boolean)

读这段代码看三件事

phase() 改进度分组。

await 让下一段等结果。

变量 found 和 work 承接产物。文件操作仍由 agent 工具完成。

07 / UNKNOWNS

还没有证据的地方

2.1.247 怎样落盘每个 agent 的结果

官方说明结果保存在 session 目录并支持重放，没有公开内部文件名、字段、刷新时机与事务边界。本轮也没有读取私人会话目录。

部分输出遇上不可恢复 API 错误后留下什么

官方写明 agent() 会返回 null，没有说明已经流出的部分文本是否另行保存。缺少 R，页面不补这个细节。

同一阶段的开始顺序怎样稳定下来

重放规则按 agents 原先开始顺序判断。多个 agent 几乎同时启动时，内部如何排序与持久化，公开文档没有给格式。

长期无人处理的权限请求有没有超时

官方只说 permission prompt 可以暂停 run。固定超时、超时身份与自动重试策略没有公开契约。

崩溃或磁盘写满时还能复用多少结果

没有 R，也没有公开的原子写入保证。页面只把正常暂停、停止和恢复画进主链。

怎样安全复现

  1. 固定 2.1.247，在临时配置目录和空仓库启动。
  2. 让三阶段脚本先返回结构化列表，再 fan-out，最后汇总。
  3. 停止中段一个 agent，用同一脚本重新启动，记录复用与重跑边界。
  4. 恢复同一会话再试一次，随后用新会话运行保存脚本作对照。
  5. 只留匿名计数，实验结束后删除整个临时环境。
