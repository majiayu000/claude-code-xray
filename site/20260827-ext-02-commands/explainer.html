输入斜杠命令以后，Claude Code 怎样分派自定义斜杠命令与内置 Commands

Claude Code 只在消息开头认斜杠命令。菜单会随输入过滤候选，CLI 随后按提交的名字选择当前可用命令。内置命令进入固定处理逻辑。旧式文件命令会读取 Markdown，替换参数及获准的动态片段。默认分支把渲染结果放进当前会话；写了 context: fork 的文件命令会把它交给一个子 Agent。名字未命中时，CLI 报告未知命令；动态注入失败时，正文不会交给 Claude。OL

01 / TERMS

四个角色就够读懂这页

命令菜单把多种来源放在一起，运行时仍要分清谁认名字、谁展开文件，以及谁真的改变会话。

01

用户输入

消息必须以斜杠命令开头。名字后的文字是参数。斜杠出现在消息中部时，公开契约不把它当命令入口。O

02

命令匹配器

菜单随输入过滤候选。顶部候选只有在名称或别名按官方规则匹配时才高亮；拼错时相近候选仍可留在列表，直接提交会报未知命令。OL

03

两类处理器

大多数内置命令执行 CLI 固定逻辑。文件命令沿用 Skill 的提示渲染机制。O

04

当前会话

内置处理器按各自契约改状态。默认文件命令把渲染内容留在当前会话；context: fork 改为启动子 Agent，并把结果送回当前会话。O

02 / SEQUENCE

一次提交里的先后顺序

下面只写官方能够约束的顺序。CLI 内部函数名和注册表结构没有公开，留在未知项。

01

识别消息开头

提交内容以 /name 开头才进入命令路径。后面的原始文字先作为参数保留。

O
02

过滤候选，再决定是否高亮

菜单会随输入过滤。顶部候选只有在名称或别名从开头或词段命中时才高亮，分隔符可以忽略。拼错时相近候选仍可留在列表；平台、套餐或环境不允许的命令通常不出现，隐藏命令要输入完整名字。

O
03

选择处理分支

内置名字进入 CLI 处理器。文件名产生的命令进入兼容的 Skill 渲染路径。Skill 和旧 command 文件同名时，Skill 优先。

O
04

文件分支先完成预处理

Claude Code 替换整段参数、位置参数和命名参数。动态命令获准后先运行，输出只注入一次。任何失败都会在模型看到正文之前中止。

O + L
05

按前置字段选择文件落点

内置命令按自己的契约改模型、权限、上下文或界面。默认文件分支把渲染内容作为一条消息放进当前会话。若前置字段写了 context: fork，同一内容会成为子 Agent 的提示；它默认在后台运行，完成后把结果送回当前会话。

O

03 / FLOW

名字相同，数据流不同

命令菜单是共同入口。内置分支处理状态，文件分支先渲染文本，再由前置字段决定进入当前会话，还是交给子 Agent。

输入缓冲区

/name args

  • 位置在消息开头
  • 保留命令后的文字
→

内置分支

调用 CLI 固定处理器，结果可能是切模型、开菜单、压缩上下文或开始新任务。

文件分支

读取 command Markdown，套用参数及环境替换，按政策处理动态注入，再读取 context 与 background 等前置字段。

→

状态落点

  • CLI 状态按内置契约变化
  • 默认文件内容进入当前会话
  • context: fork 启动子 Agent
  • 注入失败则正文不交给 Claude

04 / LIMITS

权限门、登录和费用

文件展开并不保证会走到模型。名字、可见性、政策、认证和注入命令都可能让这次调用提前结束。触发模型请求以后，用量才按当前认证路径归账。

名字命中

匹配当前可用命令以后才选择处理器。少量隐藏命令只有完整名字能够触发。O

名字拼错

2.1.236 起，拼错时不会高亮顶部候选，相近项仍可留在列表。按 Enter 提交原文后，CLI 报告未知命令。官方没有公开这条错误路径是否发起模型请求。OLI

临时工具授权

allowed-tools 可以给调用当轮的工具免去逐次确认。该授权到下一条用户消息就清除。O

动态注入被拒

注入命令不会现场询问。权限结果只要不是 allow，整次展开中止，正文不会交给 Claude。OL

注入命令失败

默认 Bash 下，普通非零退出码会中止整次调用。部分搜索与比较命令的退出码 1 有明确例外。O

启动模式关闭来源

safe mode 关掉自定义项。bare mode 仍认 Skills，却跳过旧 command 文件。OL

先有可用认证

文件式命令要交给 Claude 处理，当前会话必须有可用凭据。个人账号可通过 Claude.ai 的 Pro 或 Max 登录。团队还能使用 Team、Enterprise 或 Console；组织可把请求交给 Amazon Bedrock、Google Cloud’s Agent Platform 或 Microsoft Foundry。认证失效时，模型请求停下。O

费用跟着认证路径走

文件内容渲染后，触发模型请求才计入用量。Pro、Max、Team 与 Enterprise 使用相应计划额度，Console 和云提供商按 token 计费。本地匹配和没有触发模型请求的内置命令不新增模型 token 用量。O

关键停止点

动态注入的权限拒绝和执行失败都发生在内容进入会话以前。页面因此没有把文件命令画成必然送达模型的直线。O

文件命令还有一个落点

command 文件支持除 name 与 paths 外的 Skill 前置字段。写入 context: fork 后，渲染正文会成为子 Agent 的提示；默认后台运行，完成后把结果送回当前会话。O

05 / EXPERIMENT

这次只做到静态核对

本轮没有启动新的 Claude 会话，也没有读取私人命令或会话记录。页面状态保持 documented。

R 0NO LIVE SESSION

本机能够确认什么

固定版本文件仍在，版本输出为 2.1.247，二进制摘要与基线一致。帮助里能看到 safe mode、bare mode 和关闭 Skills 的开关。静态字符串还能找到未知命令、参数替换及两类动态注入失败提示。L

这些材料只能证明版本带着相应入口与错误文案。它们不能证明菜单实际怎样排序，也不能证明渲染消息的内部字段。要升为 verified，仍需在获准的隔离会话里提交无副作用命令，并对照前后状态。该实验一旦让文件内容进入模型，就会按当时的认证路径占用计划额度或产生按 token 计费。IO

安全复现的最小范围

另行获准后，在无私人配置的临时项目创建一个只回显参数的 command 文件。依次测正常名字、拼错名字、无占位符、位置参数、同名 Skill 和失败的动态注入。只保留匿名化事件类型、退出码和消息计数，不保存 prompt、回复、cwd、会话 ID 或 transcript。

07 / UNKNOWNS

仍然没有证据的地方

这些缺口不会影响公开用法，却会影响对内部实现的精确描述，所以继续保留问号。

未知命令的模型请求边界

官方只承诺提交原文并报告未知命令，没有说明这条错误路径是否发起模型请求。本页没有 R，故不把“模型一定看不见”写成运行事实。I

内部注册表

官方没有公开 CLI 如何合并内置命令、文件命令、Skills、插件与 MCP prompts 的数据结构。I

硬编码内置项的同名冲突

文档说明了 Skill 与旧 command 文件、bundled skill 的优先关系，没有给出一条覆盖普通内置命令的完整规则。

旧 command 文件的热更新

官方明确保证 SKILL.md 的 live change detection，没有同样明确地承诺旧 command 文件的监听时机。

内部消息字段

公开契约说渲染内容作为一条消息进入会话，没有公开它在 CLI 内部使用的 role、subtype 与序列化字段。

终端实际画面

本轮没有 R，故没有把 2.1.247 的菜单排序、候选动画和错误提示布局写成已验证事实。
