Claude Code 2.1.247基线 2026-08-27

一个按键要过两道门

终端先把按键组合编码成 Claude Code 能收到的信号。Claude Code 再按当前组件与输入模式解释它。终端没有区分开的组合键，后面的 keybindings 无法补回。 INSERT 时字符写进输入框。NORMAL 改变光标位置，VISUAL 会选中文字。

01 / TERMS

四个角色各管一段

把终端、组件动作与 Vim 混成一层，许多键位冲突就会解释错。

O

终端模拟器

它把物理按键变成字符或控制字节。支持扩展协议时，终端还能报告修饰键。Option、Shift、Command 能否被区分，先由这一层决定。

O

keybindings

它在 Global、Chat、Transcript 等组件上下文里，把收到的键或 chord 匹配为动作。一个按键也可以显式解绑。

O

Vim 输入状态

它在输入框这一层处理模式与光标，也解释 motion、operator 和选择。多数 Ctrl 组合继续交给组件级 keybindings。

O

持久化文件

个人 keybindings 单独保存在用户配置目录。Editor mode 与 INSERT 双键退出映射属于 settings，作用域规则不同。

02 / SEQUENCE

一次按键怎样落地

这条顺序在提交前结束。消息何时进入队列或发给模型，属于 UI-01。

用户按下一个键或组合键

终端先接到物理输入。macOS 的 Option 通常要配置为 Meta，Command 则依赖 Kitty keyboard protocol 或 modifyOtherKeys 一类扩展报告。O

终端发送它能表达的信号

有些组合在这一层已经合并。Ctrl+M 与 Enter 到 Claude Code 时相同，Ctrl+I 与 Tab 相同，Caps Lock 根本不会交给终端应用。O

信号进入本地解释阶段

官方把 Vim 文字层与组件级 keybindings 写成两套独立机制，没有公开它们的内部先后。本页从这里分成两条用户可见路径。I

输入框路径看 Vim 状态

INSERT 接收文字。Esc 进入 NORMAL，v 或 V 进入 VISUAL；NORMAL 中的 h、j、k、l 负责移动。Esc 在这里不会触发 chat cancel。O

组件路径看活动 context

Chat、Autocomplete、Confirmation、Transcript 等 context 把信号匹配为组件动作。仍有 chord 前缀时，Claude Code 会继续等待下一键。O

动作改文字、光标或组件状态

结果可以是插入换行、提交、移动、打开面板或退出。Enter 在 Vim INSERT 中仍会提交；要换行可用 Ctrl+J，NORMAL 中也可用 o 或 O。O

未匹配、被截获或保留键让线路停止

tmux 可能先拿走 Ctrl+B，shell 会用 Ctrl+Z 挂起进程。Ctrl+C 与 Ctrl+D 属于硬编码中断和退出，配置文件不能改绑。O

04 / LIMITS

门、失败与退路

这条机制主要停在本地输入与配置。登录和费用取决于用户能否进入所用界面，以及按键有没有提交消息。

O

终端能力门

多数终端不报告 Super 或 Command。非拉丁布局若没有位置报告，只能按终端实际送来的字符匹配。想跨终端使用，官方建议优先选 Ctrl 或 Meta。

O

多路复用冲突

tmux 默认占用 Ctrl+B，GNU screen 默认占用 Ctrl+A，Unix 用 Ctrl+Z 发送 SIGTSTP。事件在 Claude Code 之前被拿走，keybindings 就看不到。

O

配置校验门

JSON、context、action、保留键和重复绑定都会校验。2.1.247 遇到未知 action 会跳过该项并保留默认绑定，2.1.246 以前会把这个键静默禁用。

O

Vim 边界

Vim motion 不能在 keybindings 文件中改绑。INSERT 双键映射只能接收恰好两个可打印字符，目标只能是 Esc，第二键须在一秒内到达。

O

写文件门

/terminal-setup 可能直接改宿主配置，官方展示的是完成后的结果消息，没有承诺写入前再询问。VS Code、Cursor 与 Devin Desktop 路径还会关闭 GPU acceleration，并调整终端鼠标滚动灵敏度。运行前应自行核对目标文件并备份。

O

保留与备份边界

已有 Shift+Enter 绑定会留在原处。Zed 在合并新绑定前只对文档列明的路径创建同目录备份；读取、解析、备份或校验失败时不改文件，改由用户手工添加。该保证不能外推到所有终端。

O

停止条件

配置匹配到动作后，这次键位解释完成。保留键走硬编码行为，未送达的键没有后续动作，未完成的 chord 前缀则继续等下一键。

O

登录与可用范围

官方总览只承诺多数 Claude Code 界面需要 Claude 订阅或 Anthropic Console 账户，并说明终端 CLI 还支持第三方提供商。它没有为 keybindings 与 Vim 单列套餐或后端矩阵。

OI

模型请求与费用

官方把插入换行和提交消息列成不同动作，也说明用量按订阅额度或 API token 计算。本页据此把未提交的输入、移动和本地配置编辑视为不产生模型 token 的路径。提交以后进入模型用量，计费口径随认证来源而变。

Shift+Enter 不可用→Ctrl+J→反斜线后按 Enter　两种退路都不需要设置

06 / VERSION

2.1.247 前后的变化

同一份配置在旧版本上可能有不同的失败后果。

2.1.18

官方 changelog 加入可定制 keybindings、上下文绑定与 chord。

2.1.92

/vim 被移除。编辑模式改从 /config 的 Editor mode 切换。

2.1.208

vimInsertModeRemaps 加入，可把两个可打印字符映射为 Esc。

2.1.242

Kitty keyboard protocol 终端中的 Ctrl+[ 从这一版起可稳定按 Escape 处理。

2.1.246

未知 action 的失败语义改变。新版本跳过坏绑定并保留默认值，旧版本会静默禁用该键。

2.1.247

本页基线。非拉丁布局在 Kitty 协议终端中的 Ctrl 快捷键匹配得到修复，Ctrl+X Enter chord 也从这一版进入默认集合。

07 / UNKNOWNS

仍然不能写死的地方

官方公开了用户可观察的规则，没有公开完整的本机事件对象与解析调用链。

本机终端报告

当前终端是否启用 Kitty keyboard protocol、modifyOtherKeys 或 Meta 映射，本轮没有读取终端私人设置，也没有按键实测。

内部优先级细节

同一信号在多个活动 context、Vim 文字层与 chord 等候状态间的完整内部判定顺序，没有公开实现证据。

热重载原子性

官方承诺 keybindings 改动无须重启。保存到一半的文件、编辑器原子替换与连续快速写入怎样合并，没有公开保证。

IME 组合状态

中文输入法候选窗打开时，Esc、Ctrl 组合与 Vim 模式怎样分配给 IME、终端和 Claude Code，需要逐终端真实测试。

终端安装回滚

官方只给出 GPU acceleration 的手动恢复办法与 Zed 的条件式备份，没有承诺其他改动都能一键撤销，也没有跨终端的统一卸载流程。

本机配置结果

个人是否已有 keybindings、editorMode 或冲突警告属于私有配置。本轮依约不读取，因此无法给出当前机器的最终匹配表。

认证与账单实测

未登录能否到达 2.1.247 的交互键位界面，本轮没有测试。keybindings 与 Vim 在各订阅、Console、云端提供商下是否完全同功能，官方也没有单列对照表。
