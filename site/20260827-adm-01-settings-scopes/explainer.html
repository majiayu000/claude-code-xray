01 · TERMS

先看设置能到谁那里

作用域回答覆盖人群，优先级回答冲突结果。两个问题分开以后，project 和 local 就不会再混。

用户

放在用户配置目录，影响这台机器上此人的所有项目。适合主题、默认模型和个人规则。 O

共享项目

放在仓库的 .claude/settings.json，提交后随仓库到达协作者。它高于用户设置。 O

项目 local

放在 .claude/settings.local.json，只给当前用户在这个项目使用。它高于共享项目，又不会随提交交给队友。 O

managed 与命令行

managed 由组织或设备管理渠道交付。命令行只改一次启动。两者相遇时 managed 在上。 O

02 · SEQUENCE

一次启动里的裁决顺序

文件存在时，键仍要通过校验，随后才会进入候选集。

确定运行表面

本机 CLI、IDE、Desktop 与云端会话可读的来源不同。云端不会带走本机 user 和 local 文件。 O

收集到达当前会话的来源

本机设置文件、启动参数与 managed 交付源进入候选集。命令行省略的键仍由下面的文件补上。 O

解析并剔除坏条目

普通文件的坏 JSON 会触发错误处理。managed payload 会尽量保留仍然有效的键，失效键可能回到更严格的默认。 O

先解决 managed 内部来源

默认由最高的非空 managed 来源获胜。2.1.242 起，管理员可以明确选择合并受控来源。 O

逐键裁决

普通单值走五层顺序，列表常取并集，环境变量查看自己的规则，安全键保留更严格值。 O

再过功能可用性门

provider、订阅与管理员开关会继续收窄结果。最终界面可能显示、隐藏、灰掉，也可能在执行前阻断。 O I

04 · LIMITS

六道门，六个停止位置

设置优先级只负责其中一段。功能缺失时，先判断它停在哪道门，别只盯着 JSON。

入口门

登录方式决定远端策略能否拉取

server-managed 要求 Team 或 Enterprise 组织，并直连 api.anthropic.com。Team 或 Enterprise OAuth 登录、CLAUDE_CODE_OAUTH_TOKEN 与直接配置的 API key 可以触发拉取。apiKeyHelper 返回的 key 不会触发。第三方 provider 或非默认 ANTHROPIC_BASE_URL 也会跳过拉取。 O

来源门

文件有没有被读

云端不读本机 user 和 local。共享文件未被信任时，一些允许类键也会等待。 O

校验门

坏键会被丢下

交互启动会报告 settings error 或 warning。非交互运行可能跳过坏文件，随后要用 doctor 查明。 O

策略门

组织可以锁住或隐藏

模型 allowlist 会限制选择，空 marketplace allowlist 会封锁来源，managed 禁用的插件会从 marketplace 隐藏。 O

网络门

远端策略可能暂时没到

首次启动无缓存且拉取失败时，默认继续运行。开启 fail-closed 后，拉取失败会让 CLI 退出。 O

边界门

客户端策略管不到别的工具

managed settings 约束 Claude Code 客户端。未受管设备上的修改版客户端或其他 API 工具不受这层保证。 O

06 · IMPLEMENTATION

五类键要分开算

拿到一个冲突键时，先判它是哪种类型。照搬五层阶梯会把列表和安全门讲错。

键的形态裁决办法结果示例证据
普通单值最高作用域取值local 可改项目值，managed 仍能压住 localO
普通列表跨层合并并去重permission allow 等列表可同时保留多层条目O
限制性整表按专门规则取完整列表managed availableModels 不接纳个人追加项O
安全性例外较低层的更严格值仍可生效某些关闭、隔离、拒绝设置无法被上层放宽O
环境变量逐键查自己的覆盖契约不能把 shell env 画成统一第六层O
更新什么时候进入运行中会话

用户、项目、local 和文件型 managed 的多数改动会重载。远端按启动与小时轮询到达，MDM 约每 30 分钟检查。模型、部分遥测和少数启动键要等下次启动。 O

怎样确认来源

在会话里看 status 的 Setting sources。它能告诉你读了哪些层、managed 从哪条渠道到达，无法告诉你每一个键由谁提供。用 doctor 查被拒条目。 O

为什么管理员已经保存，客户端仍然没有策略

先核对当前会话的认证路径。Team 或 Enterprise OAuth、CLAUDE_CODE_OAUTH_TOKEN 和直接配置的 API key 才会触发 Anthropic 的远端拉取。apiKeyHelper、第三方 provider、非默认 ANTHROPIC_BASE_URL 会让这条拉取路径停下。此时应改用符合条件的认证与路由，或由管理员通过 MDM、系统 managed 文件等 endpoint-managed 渠道下发。 O

怎样锁住功能

设置默认值只决定起点。要限制用户切换，管理员还要部署对应 allowlist 或 only-managed 锁。官方用模型选择、permission rules、hooks、MCP 与 marketplace 分别给出了这类键。 O

07 · UNKNOWNS

目前还不能写死的地方

这些缺口会改变管理员的判断，留在页面上比假装完整更有用。

逐键 resolved 来源

status 只列加载层，不导出每个键的来源。复杂冲突仍需按键推导，再用行为核对。

真实下发延迟

文档给出轮询节奏，本轮没有真实组织、网络与多平台样本。

组合失败分支

部分 payload 无效、缓存陈旧、用户拒绝安全确认同时发生时，2.1.247 的全部界面分支未实测。

账户 rollout 的先后

feature flag、套餐门与 settings 同时作用时，没有一份公开的统一客户端状态机。
